# 报告目录

`reports/` 保存需求接入、分析、计划和验证的过程证据。报告是本地任务产物，按项目和任务隔离；本框架提交集只保留本 README，不提交具体项目报告或历史迁移记录。

## 目录规则

```text
reports/
├── README.md
├── {项目标识}/
│   └── {任务号或需求包名}/
│       ├── intake.md          # 可选：需求包分诊与人工确认
│       ├── analysis.md        # 可选：缺陷、重构或架构前置分析
│       ├── plan.md            # 可选：已确认的实施计划
│       └── verification.md    # 可选：验证命令、结果、风险和收尾结论
└── _unassigned/               # 项目归属尚未确认的报告
```

## 命名与写入

- 项目标识使用本机项目关联配置中的项目键；不明确时使用 `_unassigned/`，不得猜测项目。
- 项目目录下优先使用稳定任务号作为目录名；未创建任务时，使用需求包名或简短、稳定的主题名。
- 同一工作项的所有报告放在同一目录中，按产物类型使用固定文件名；不以日期创建平铺文件。
- 重构、架构优化和复杂缺陷的 `analysis.md` 必须在修改前创建，并使用 `templates/bugfix-refactor-report.md` 的字段。
- 报告使用 Markdown；引用项目路径时使用绝对路径。

## 迁移规则

1. 对历史报告先确认项目，再按项目和任务号、需求包名或稳定主题创建报告目录。
2. 将分析、计划和验证产物按固定文件名放入同一任务目录。
3. 不改写历史结论、证据或确认记录；仅修正路径字段和文件格式以符合当前规则。
4. 迁移记录保存在本地任务产物中，不写入通用框架 README。
5. 迁移前更新内部引用；无法更新的外部链接应保留兼容副本，并在本地记录处理结果。

## 生命周期

报告在任务确认、实施、验证和收尾阶段持续更新。任务完成后，验证证据保留在对应任务目录；日报、周报和月报只从项目 Git 历史读取已提交任务标题，不从报告推断完成状态。
