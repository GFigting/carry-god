# 测试驱动实施

## 循环

1. 选择一个最小行为切片。
2. 写能表达需求的失败测试或反馈检查。
3. 运行并确认失败原因是缺少行为，而不是测试错误。
4. 编写最小实现使测试通过。
5. 重构实现和测试，保持行为不变。
6. 运行局部测试，再按风险扩大验证范围。

## 约束

- 测试通过不等于需求完成，仍需检查验收标准。
- 不为追求覆盖率制造无价值测试。
- 修改测试预期时必须记录行为变化的理由。

## 深度执行流程

对可自动化验证的功能、缺陷修复、行为变更或高风险重构，加载 [测试驱动开发](../skills/test-driven-development/SKILL.md)。它规定失败证据、最小实现和保持绿色的重构循环；项目测试约定、任务确认范围和验收标准优先。
