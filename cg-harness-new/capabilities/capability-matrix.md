# 智能体技能能力矩阵

本矩阵记录各来源目录的优点、吸收方式和边界。`GGFrame` 是治理主线，其他目录只提供可复用的方法，不直接覆盖主流程。

| 来源 | 主要优点 | 吸收进入新版的内容 | 不直接吸收的内容 |
|---|---|---|---|
| `GGFrame` | 目标驱动、角色职责、任务状态、流程门禁、产物追踪、知识归档 | 作为核心骨架；补充前后端关联和领域术语注册 | 具体项目资料、业务历史、Obsidian 展示和过重的目录层级 |
| `skills` | 深模块设计、领域建模、TDD、系统化调试、双轴代码审查、研究证据、计划拆票 | 形成设计、术语、测试、调试、审查、调研和依赖拆分能力 | 依赖特定 issue tracker、编辑器或语言工具的安装技能 |
| `superpowers` | 头脑风暴、计划先行、按任务派发、执行回路、验证前置、审查修复循环 | 形成需求澄清、计划、派发包、验证门禁和审查闭环 | 特定宿主的插件 manifest、工作树脚本和贡献流程 |
| `compound-engineering-plugin` | 把头脑风暴、计划、实施、简化、审查、复合学习串成完整循环 | 形成软件交付主循环和任务结束沉淀机制 | 安装器、插件转换器、发行管理和宿主命令 |
| `gstack` | 产品视角质询、范围控制、先搜索复用、架构报告、真实路径 QA、安全审查、发布和复盘 | 形成范围与复用、HTML 报告、真实路径检查、安全和复盘能力 | 浏览器守护进程、遥测、外部服务、特定宿主脚本 |

## 吸收原则

1. 治理规则只保留一套，遇到重复能力以 `core/` 和 `workflow/` 为准。
2. 方法类技能按阶段挂载，不在启动时全部加载。
3. 项目领域术语优先于通用术语，统一登记在项目词汇表。
4. HTML 报告用于复杂分析和重构前置，不替代任务记录和自动化测试。
5. 所有技能必须说明触发条件、输入、输出、证据和不适用边界。
