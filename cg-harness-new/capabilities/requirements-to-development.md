# 需求到开发追踪

## 目标

把已确认需求转换为开发可执行的垂直切片，并在交付前证明每条验收标准都有实现和验证。它连接需求收件箱、任务计划、代码变更和测试，不替代需求澄清或技术设计。

## 建立基线

1. 从已确认的 intake 或需求记录复制目标、范围、非目标和约束。
2. 为每条验收标准分配稳定编号 `AC-*`，每条至少写一个 Given/When/Then 场景，并保留来源文件或原型证据。
3. 将验收标准映射为垂直切片 `S-*`；每个切片必须说明输入、输出、代码边界、依赖和验证方式。
4. 计划进入 `ready` 前检查反向覆盖：每个 `AC-*` 都有切片和验证方式，每个切片都至少服务一个 `AC-*`；需要计划的任务还必须已获得人工确认。

## 实施与回填

- 测试名称、实际代码路径和命令必须回填到追踪表，不能只写“已实现”。
- 发现需求变化时暂停当前切片，更新需求基线和影响的 `AC-*`，再重新确认计划；不得悄悄扩大范围。
- 跨前后端或数据层的验收标准必须标出真实调用路径和数据变化，不能用单元测试替代端到端关键路径。

## 审查与收尾

按 `AC-* -> 场景 -> S-* -> 代码 -> 测试 -> 实际结果` 逐项检查。缺少任一环节时结论只能是需要修复或明确延后，不能标记 `done`。延后项必须写明原因、影响和后续任务。

## 输出

需求基线、垂直切片计划、需求追踪表，以及包含命令和实际结果的验证记录。
