# 代码审查

从两个维度审查：

1. **需求符合性**：实现是否覆盖验收标准，是否改变了未授权行为。
2. **工程质量**：边界、错误处理、安全、性能、可维护性、测试和兼容性是否可靠。

审查前先锁定任务、验收标准、比较范围和项目约定，并明确未审查范围。发现按严重性排序，优先指出会导致错误、回归、数据风险或无法验证的事项。每条发现必须包含位置、影响、复现或推理证据和建议修复方向；无法核实的观察应标为风险或问题，不得作为确定缺陷。

审查结论只能是：通过、需要修复、或明确记录的延后项。

## 深度执行流程

重要功能、复杂修复、重构或合并前审查时，加载 [独立代码审查](../skills/independent-code-review/SKILL.md)，并使用 `templates/code-review-report.md` 记录审查基线、覆盖范围、发现处理和剩余风险。该技能不绕过 `workflow/software-delivery.md` 的确认门禁，也不自动授权修改代码。
