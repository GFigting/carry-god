# 工程能力

能力是按需挂载的执行方法，不是新的角色，也不覆盖 `core/` 和 `workflow/` 的治理规则。

| 能力 | 适用时机 |
|---|---|
| 澄清与头脑风暴 | 目标、范围或验收标准不清 |
| 深模块设计 | 需要拆分边界或稳定接口 |
| 测试驱动实施 | 新功能、行为修复和高风险重构 |
| 通用代码实现规范 | 编写、修改或审查代码时 |
| 提交规范 | 创建、审查或收尾代码提交时 |
| 系统化调试 | 缺陷、回归、性能或间歇性故障 |
| 代码审查 | 提交审查或合并前 |
| 完成前验证 | 任何完成声明前 |
| 复合学习 | 任务结束且产生可复用经验 |
| 范围与复用 | 开始新建模块或扩大变更范围前 |
| 领域建模 | 术语、对象或业务规则不清 |
| 架构机会报告 | 重构、架构优化或复杂缺陷分析 |
| 计划与依赖拆分 | 工作跨多个步骤或多个角色 |
| 调研与证据 | 需要外部资料或技术取舍 |
| 问题分诊与路线规划 | 问题模糊或工作规模过大 |
| 原型与真实路径验证 | 状态模型、交互或端到端链路不确定 |
| 安全审查与操作护栏 | 涉及敏感数据或危险操作 |
| 发布与复盘 | 发布前后或任务结束 |
| 需求到开发追踪 | 需求已确认，需要拆解、实现或验收追踪时 |

注册信息见 `../registry/capabilities.yaml`。
