# 角色体系

角色描述“负责什么”和“交付什么”，不代替能力模块。角色是框架内部的职责约束，不是用户需要输入的命令。主会话自动选择合适角色，并始终保留一名主责角色。

## 自动路由

用户只需描述目标，例如“处理这批需求”“实现这个功能”“检查一下有没有问题”。框架根据意图和当前阶段自动加载角色；只有范围、方案或风险存在分歧时才向用户确认角色相关决策。

| 用户意图或阶段 | 主责角色 | 默认协作角色 |
|---|---|---|
| 目标、需求、收件箱分诊 | 技术负责人 | 质量工程师（检查证据） |
| 原型、架构、接口、数据流 | 技术负责人 | 架构师 |
| 编码、修复、重构、测试 | 技术负责人 | 开发工程师 |
| 审查、验收、回归、风险检查 | 技术负责人 | 质量工程师 |
| 发布、监控、回滚 | 技术负责人 | 运维工程师 |

技术负责人默认由主会话承担，负责跨阶段上下文、关键取舍、集成和最终交付。一个任务可以组合多个协作角色，但不要求用户显式指定。

| 角色 | 主责 |
|---|---|
| 技术负责人 | 目标、架构、取舍、集成和最终交付 |
| 架构师 | 领域边界、接口、数据流和长期结构 |
| 开发工程师 | 实现、测试、重构和局部技术决策 |
| 质量工程师 | 需求符合性、风险、回归和审查证据 |
| 运维工程师 | 发布、观测、回滚和运行风险 |

详细协作规则见 `delegation.md`。
