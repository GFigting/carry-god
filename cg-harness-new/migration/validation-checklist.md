# 整理验证清单

- [ ] 根入口能说明启动顺序和边界。
- [ ] `core/` 与 `workflow/` 对同一行为没有互相矛盾的规则。
- [ ] 任务状态机包含开始、阻塞、审查、返工、完成和取消路径。
- [ ] 需求、设计、实施、审查和收尾均有对应门禁。
- [ ] 每个注册能力的路径都存在。
- [ ] 缺陷修复和重构先生成 Markdown 分析报告，再进入代码修改。
- [ ] 项目注册表能够关联前端、后端、数据和运行对象。
- [ ] 项目源码、前端、后端、数据、文档和部署路径全部使用绝对路径。
- [ ] 首次使用项目时检查 CodeGraph MCP，并在缺失时提醒安装。
- [ ] CodeGraph 索引缺失或过期时，先提醒使用绝对路径重建索引。
- [ ] 领域词汇表能够记录标准术语、别名和代码映射。
- [ ] 每个能力都有触发条件、输入、输出和适用边界。
- [ ] Codex 入口不改变宿主无关的核心规则。
- [ ] 新框架不依赖具体项目路径、业务文件或 Obsidian 配置。
- [ ] 没有引用被排除的框架目录或文件。
- [ ] 至少按功能、缺陷、调研三种场景走通一次加载路径。
- [ ] 每个状态变化都能记录具体下一步、负责人、前置条件、产出和完成标准。
- [ ] 阶段完成和任务收尾的回复都包含下一步行动。
