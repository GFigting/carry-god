# 下一步行动协议

## 目的

让任务始终知道“接下来做什么”，避免只记录历史而没有推进方向。

## 判断顺序

1. 检查当前验收标准是否已经满足。
2. 检查是否存在未解决的阻塞、审查意见或待确认决策。
3. 检查前后端、数据、部署和验证链路是否还有未完成环节。
4. 从计划中选择最早且可执行的未完成动作。
5. 若没有可执行动作，明确等待对象、解除条件和重新检查时机。

## 标准格式

```text
下一步：{具体动作}
负责人：{角色或人员}
前置条件：{需要先满足的条件；没有则写无}
产出：{文件、代码、测试结果或确认结论}
完成标准：{如何判断这一步完成}
顺序：{现在执行 / 等待确认 / 等待依赖 / 任务结束}
```

## 回复要求

任务阶段完成后，回复不能只写“已完成”。必须同时说明当前状态、下一步行动和仍需人工关注的事项。任务结束时，下一步通常是发布、同步项目文档、归档知识或明确无后续动作。

## 禁止事项

- 不把“继续优化”“后续处理”作为没有具体对象的下一步。
- 不把未满足前置条件的动作标记为可立即执行。
- 不捏造不存在的依赖、负责人或时间。
