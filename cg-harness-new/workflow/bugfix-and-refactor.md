# 缺陷修复与重构流程

## 强制顺序

### 1. 收集现状

记录问题现象、复现步骤、相关页面或调用方、前端入口、后端接口、数据表、日志、配置和已有测试。重构任务则记录当前模块边界、调用关系、重复逻辑和行为约束。

### 2. 先生成 HTML 报告

使用 `templates/bugfix-refactor-report.html` 生成报告，保存到当前任务的产物目录。报告必须能独立回答：现在发生了什么、证据在哪里、哪些前端/后端/数据库/接口和部署对象受到影响、使用了哪些领域术语、候选方案有哪些，以及如何验证没有引入回归。

### 3. 确认方案

报告中的范围、方案和风险确认后，才能进入代码修改。报告未经确认时，只允许继续调查和补充证据，不允许开始实现。

### 4. 修改与验证

优先建立回归测试或可重复的反馈，再进行最小修改。完成后更新报告的变更、验证结果、未解决风险和人工复查项。

## 前后端关联要求

前端页面、组件、状态和请求必须能关联到后端接口；后端接口必须能关联到权限、领域服务、数据访问和数据结构。无法建立关联时，报告中必须标记为“关联缺口”，不能假设链路完整。
