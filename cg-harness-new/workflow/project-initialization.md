# 项目初始化协议

## 触发条件

新增项目到 `registry/project-context.yaml`，或已注册项目尚未具备项目级需求箱、报告根目录和项目文档入口时执行。

## 输入

- 项目标识：`registry/project-context.yaml` 中唯一的项目键。
- 项目根目录，以及前端、后端、数据库和运行对象的绝对路径。
- 已知项目文档、领域词汇表、启动入口和 Git 仓库边界。

## 初始化步骤

1. 在 `registry/project-context.yaml` 登记项目路径、文档、前后端入口、数据目录、运行入口和集成规则；所有项目路径必须是绝对路径。
2. 创建框架管理的需求箱根目录：

   ```text
   requirements-inbox/{项目标识}/
   └── _processed/
   ```

3. 创建框架管理的报告根目录：

   ```text
   reports/{项目标识}/
   ```

   任务或需求包进入后才创建其子目录和 `intake.md`、`analysis.md`、`plan.md`、`verification.md`。
4. 创建框架管理的原型设计根目录：

   ```text
   designs/{项目标识}/
   ```

   具体原型进入后才创建 `designs/{项目标识}/{原型名称}/`。外部需求包携带的原型仍保留在需求箱，不复制或移动到此目录。
5. 在后端项目建立或确认 `docs/README.md`、`docs/capability-map.md` 和 `docs/module-map.md`；前端项目建立或确认 `docs/README.md` 和 `docs/capability-map.md`。没有前端或后端时跳过对应一侧。
6. 对每个前端入口登记固定 `url` 和 `health_path`；对每个后端运行对象，在 `backend.health_checks` 登记至少一个就绪检查。能够区分时另行登记存活检查和关键依赖检查。每项包含检查类型、请求地址和方法、认证方式、预期状态、预期响应及前置依赖。地址由项目决定，不能假定为 `/health` 或 Spring Boot Actuator。
7. 按“先探测，后启动，按需重启”执行运行时验证：先请求前端健康地址和后端就绪检查；已健康的运行对象默认复用。仅当本轮变更影响运行时且不支持热更新时才重启对应对象：后端源码、资源、配置或依赖变更重启后端；前端业务代码优先由开发服务器热更新；前端环境变量、构建配置、依赖或启动参数变更重启前端。健康检查失败但端口被占用时，先诊断现有进程，不得直接启动第二个实例。
8. 启动或重启后执行已登记的健康检查并记录命令、环境、结果和未满足的前置条件。就绪检查失败时，项目不得标记为“可接入”或“可交付”；依赖不可用时应明确记录为环境限制，不能将其误判为代码通过。
9. 将上述项目文档绝对路径及健康检查定义登记回项目关联表。能力地图记录细粒度可复用能力；模块索引只记录业务域入口，二者不得混用。
10. 检查 Git 仓库可用性和默认分支；完成任务的汇总记录只使用该项目 Git 提交标题，规则见 `workflow/completed-task-records.md`。
11. 涉及代码结构时，检查 CodeGraph MCP 与 `.codegraph/` 索引状态；缺失或过期时先记录限制，并在实际实现前处理索引。

## 既有材料处理

- `requirements-inbox/_unassigned/` 或根目录中的既有材料不得在初始化时自动移动。
- 只有人工确认项目归属后，才能将原始需求包移动到 `requirements-inbox/{项目标识}/`。
- 历史报告按 `reports/README.md` 的迁移规则处理；初始化不重写报告结论或删除文件。

## 验收清单

- [ ] 项目标识在关联表中唯一，所有登记路径均存在且为绝对路径。
- [ ] `requirements-inbox/{项目标识}/_processed/` 存在。
- [ ] `reports/{项目标识}/` 存在，且未预建虚假的任务报告。
- [ ] `designs/{项目标识}/` 存在，且未预建虚假的原型设计。
- [ ] 前后端项目文档入口与能力地图已存在并登记。
- [ ] 后端模块索引与能力地图职责清晰；前端能力地图不含后端实现细节。
- [ ] 每个可运行后端已登记就绪检查；检查地址、认证和预期结果与实际部署方式一致。
- [ ] 每个前端入口已登记固定访问地址和健康路径。
- [ ] 已验证运行对象的复用或重启决策；启动或重启后已执行健康检测并保留结果。未能执行时已记录环境依赖和补测条件。
- [ ] 项目 Git 仓库可用于读取提交标题。
- [ ] CodeGraph 状态已检查，缺口已记录。

## 下一步行动

项目初始化完成后，等待需求包进入对应 `requirements-inbox/{项目标识}/`；接入时按项目文档、能力地图和模块索引进行分诊。
