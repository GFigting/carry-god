# 项目初始化协议

## 触发条件

新增项目到 `registry/project-context.yaml`，或已注册项目尚未具备项目级需求箱、报告根目录和项目文档入口时执行。

## 输入

- 项目标识：`registry/project-context.yaml` 中唯一的项目键。
- 项目根目录，以及任务实际涉及的仓库、运行对象、外部集成或运维入口。
- 已知项目文档、领域词汇表、Git 仓库边界，以及需要时的启动入口和健康检测。

## 初始化步骤

1. 在框架 `registry/project-context.yaml` 登记项目标识、显示名称、领域、项目背景、项目根路径、业务文档路径和 `required_context`；所有已登记路径必须是绝对路径。仅在实际需要时登记 `repositories`、`runtime`、`integrations` 或 `operations`。业务规则、词汇表、接口说明和项目专属规范只在项目自身 `docs/` 中维护，框架只保留其关联入口。
2. 创建框架管理的需求箱根目录：

   ```text
   requirements-inbox/{项目标识}/
   └── _processed/
   ```

3. 创建框架管理的报告根目录：

   ```text
   reports/{项目标识}/
   ```

   任务或需求包进入后才创建其子目录和 `intake.md`、`analysis.md`、`plan.md`、`verification.md`。
4. 创建框架管理的原型设计根目录：

   ```text
   designs/{项目标识}/
   ```

   具体原型进入后才创建 `designs/{项目标识}/{原型名称}/`。外部需求包携带的原型仍保留在需求箱，不复制或移动到此目录。
5. 对实际存在的应用仓库建立或确认 `docs/README.md`；需要按能力或模块定位时，再建立对应能力地图或模块索引。没有独立前端、后端或服务仓库时跳过。
6. 仅对需要启动或健康检测的运行对象登记 `runtime`。每个入口至少包含名称、命令和工作目录；每项健康检查包含请求地址、方法、认证方式、预期结果及前置依赖。地址由项目决定，不能假定为 `/health` 或 Spring Boot Actuator。
7. 仅在本轮需要运行时验证时，按“先探测，后启动，按需重启”执行：已健康的运行对象默认复用；健康检查失败但端口被占用时，先诊断现有进程，不得直接启动第二个实例。
8. 启动或重启后执行已登记的健康检查并记录命令、环境、结果和未满足的前置条件。依赖不可用时应明确记录为环境限制，不能将其误判为代码通过。
9. 将项目背景、业务文档路径、`required_context` 和实际使用的扩展入口登记到框架关联表；业务文档内容仍在项目自身 `docs/` 维护。
10. 检查实际涉及的 Git 仓库可用性和默认分支；完成任务按 `workflow/completed-task-records.md` 从 Git 提交标题生成、改写和合并后登记到 `reports/completed-tasks.md`。
11. 涉及代码结构时，检查 CodeGraph MCP 与 `.codegraph/` 索引状态；缺失或过期时先记录限制，并在实际实现前处理索引。

## 既有材料处理

- `requirements-inbox/_unassigned/` 或根目录中的既有材料不得在初始化时自动移动。
- 只有人工确认项目归属后，才能将原始需求包移动到 `requirements-inbox/{项目标识}/`。
- 历史报告按 `reports/README.md` 的迁移规则处理；初始化不重写报告结论或删除文件。

## 验收清单

- [ ] 项目标识在关联表中唯一，项目根路径和所有已登记的关联路径均存在且为绝对路径。
- [ ] `requirements-inbox/{项目标识}/_processed/` 存在。
- [ ] `reports/{项目标识}/` 存在，且未预建虚假的任务报告。
- [ ] `designs/{项目标识}/` 存在，且未预建虚假的原型设计。
- [ ] 实际涉及的项目文档入口已存在并登记；能力地图或模块索引仅在需要时建立，职责清晰。
- [ ] 每个需要运行时验证的对象已登记对应入口和健康检测，检查地址、认证和预期结果与实际部署方式一致。
- [ ] 已执行的运行对象复用或重启决策有记录；未执行时已记录原因和补测条件。
- [ ] 实际涉及的 Git 仓库可用于读取提交标题，且统一完成记录可按项目登记。
- [ ] CodeGraph 状态已检查，缺口已记录。

## 下一步行动

项目初始化完成后，等待需求包进入对应 `requirements-inbox/{项目标识}/`；接入时按项目文档、能力地图和模块索引进行分诊。
