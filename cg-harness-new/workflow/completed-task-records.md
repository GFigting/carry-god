# 已完成任务记录

## 记录原则

项目 Git 历史是已完成任务的事实来源；统一完成记录文件是日报、周报和月报的检索入口。记录按日期和项目集中维护，避免各仓库分别建立台账。

每个可汇总的完成任务必须有一个对应的 Git 提交。完成记录只保留经过适当优化的任务文本，不复制提交正文、任务摘要、验证日志或报告内容。

## 完成规则

1. 一个完成任务对应一个语义完整、可读的 Git 提交标题。
2. 提交前按项目约定完成审查与验证；验证证据仍保存于任务报告或项目测试输出，不写入汇总记录。
3. 提交后使用 `git log -1 --format=%s` 核对标题，并将其转换为简洁、自然的任务文本后登记。
4. 未产生 Git 提交的工作不进入日报、周报或月报；若任务没有文件变更，应在任务报告中说明原因，而不是伪造提交。
5. 跨前后端任务可以分别在各自项目提交，但同一业务任务在完成记录中只登记一次。

## 统一记录格式

统一文件为 `reports/completed-tasks.md`，使用日期一级标题、项目二级标题、项目内连续序号的结构：

```markdown
# 2026-09-07

## FMS

1. 供应商列表展示并支持查询中台供应商编码
```

记录规则：

- 同一日期下按项目分组，项目内序号从 `1` 开始。
- 只保留任务文本，不保留 `feat(scope):` 等 Git 提交前缀。
- 前后端提交标题不同但指向同一业务目标时，按语义合并为一条。
- 文本合并时使用简洁、准确、面向结果的表述。
- 同一日期、同一项目下按任务语义去重，而不是只按字符串完全匹配。

## 按项目汇总

项目路径由 `registry/project-context.yaml` 的项目记录确定。对每个项目根目录，在相应时间范围读取提交标题：

```powershell
git -C 'D:/绝对路径/项目目录' log --since='2026-09-07 00:00:00' --until='2026-09-07 23:59:59' --format='%s'
```

日报、周报和月报均从统一完成记录文件按日期范围读取；输出按项目分组，并沿用记录中的序号和优化后文本。

## 边界

- 不创建 `work-log/` 或按仓库拆分的重复台账；统一完成记录文件是唯一汇总入口。
- 不从聊天记录、需求包、报告标题或未提交工作推测完成任务。
- 不用合并提交或包含多个无关任务的提交标题作为任务汇总；需要清晰汇总时，应在提交前拆分任务。
