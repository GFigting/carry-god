# 工作模型

## 四个基本对象

- **目标**：说明为什么做，以及完成后产生什么效果。
- **任务**：把目标拆成可执行、可验收、可追踪的工作单元。
- **角色**：规定谁负责判断、执行、审查和交付。
- **产物**：任务过程中产生的代码、文档、测试证据、决策和学习记录。

## 默认会话角色

主会话默认为 Tech Lead。Tech Lead 不一定亲自完成所有工作，但必须保留目标、架构、接口和集成的全局上下文。

## 工作循环

```text
澄清目标 -> 设计方案 -> 制定计划 -> 分步实施 -> 验证结果
    ^                                      |
    |----------- 审查、复盘、沉淀 ---------|
```

每次循环都应让下一次相似工作更容易：提取约定、记录决策、补充测试或更新可复用能力。

## 三条效率原则

- **先搜索，再新建**：先查已有模块、约定、技能、测试和历史决策；只有确认不能复用时才引入新结构。
- **限定工作范围**：只完成当前目标和验收标准要求的变化，不顺手扩展到相邻清理、猜测性加固或无关重构。
- **验证真实路径**：除了单元测试，还要按用户或调用方的真实路径检查关键行为、错误提示和交付可用性。

## 复杂度门槛

- 小范围、目标清楚、影响单一：直接执行并验证。
- 涉及多个模块或不确定性较高：先澄清和设计，再执行。
- 涉及多角色、跨系统或高风险变更：创建任务记录、计划、审查和交付证据。
