# 实施计划编写

把已确认需求拆分成可独立验证的垂直切片。计划必须让执行者无需猜测范围、依赖、接口、验证方式或完成条件。

## 计划前置条件

先读取已确认需求、`AC-*`、项目上下文、相关设计与现有实现。需求不清或关键业务决策未确认时，返回需求澄清，不生成可实施计划。

## 编写步骤

1. 列出将创建、修改或验证的文件与职责，遵循项目既有结构；不因计划而引入无关重构。
2. 按可交付行为划分 `S-*` 垂直切片，每个切片至少关联一个 `AC-*`。
3. 为每个切片明确输入、输出、接口或数据变化、文件边界、依赖、风险、失败路径和验证方式。
4. 以最小可验证步骤描述实施顺序：先建立失败测试或反馈检查，再实现、验证、必要时重构。
5. 标注串行、可并行和外部阻塞关系；只能对独立、边界清楚且可验收的工作安排并行。
6. 区分默认判断与待人工确认决策，并按 `workflow/software-delivery.md` 输出唯一的待确认最终计划。

## 自检

- 每条 `AC-*` 都有至少一个切片和验证方式。
- 每个切片都服务于至少一个 `AC-*`，没有隐藏范围。
- 接口、字段、命令、文件路径和完成条件无占位描述。
- 高风险、跨系统或不可逆操作已有风险控制、回滚或人工确认点。

## 输出

由已加载的计划 capability 指定任务模板；记录切片、依赖、决策和验证计划。计划状态进入 `awaiting_confirmation`；确认前不得实施。
