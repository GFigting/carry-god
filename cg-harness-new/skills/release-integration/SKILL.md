# 发布与集成收尾

发布、合并、推送和工作区清理是独立的外部动作。完成本地实现不等于已发布；所有动作须以当前工作树的验证证据和用户授权为依据。

## 发布前检查

1. 读取本轮验证、审查结论、变更范围、项目发布约定和运行约束。
2. 核对构建、测试、配置、权限、迁移兼容性、监控信号、回滚路径和人工操作。
3. 区分已通过、未执行、环境受限和不适用项；未满足的必要门禁不得标记可交付。
4. 使用当前已加载的提交规范核对提交范围与标题，并确保提交可关联任务和验证记录。

## 集成决策

- 合并到其他分支、推送、创建合并请求、发布环境和删除工作区均需用户明确授权或项目既有自动化流程授权。
- 执行前确认目标分支、目标环境、当前工作区和回滚路径；信息不足时停止并报告缺口。
- 不自动删除分支、工作树、未跟踪文件或本地报告；清理属于单独的明确操作。

## 发布后验证与复盘

1. 按真实用户或调用方路径执行已登记的发布后检查。
2. 记录部署或集成引用、实际结果、监控观察、回滚状态和遗留风险。
3. 复盘只记录可行动的系统改进：缺失信息、失效门禁、返工来源、负责人和验证方式。

## 输出

由已加载的发布 capability 指定记录模板；输出发布检查、授权、执行结果、回滚信息和复盘行动。没有新证据时，不得宣称已发布或交付成功。
