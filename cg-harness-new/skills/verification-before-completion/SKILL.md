# 完成前验证

在声称测试通过、构建成功、问题修复、需求完成或可以交付前，必须取得本轮新的验证证据。信心、旧结果、局部检查和其他智能体的自报都不是证据。

## 验证门禁

对每项完成声明执行：

1. 明确要证明的声明，以及对应的验收标准或行为。
2. 选择能直接证明它的项目命令、真实路径检查或人工验证。
3. 在本轮运行完整检查，读取退出状态、失败数、关键输出和实际覆盖范围。
4. 判断输出是否支持该声明；不支持时，如实记录当前状态和缺口。
5. 将命令、结果、未执行项、环境限制和残余风险回填到任务记录或交付摘要。

## 证据对应关系

| 声明 | 最低证据 |
|---|---|
| 测试通过 | 本轮测试命令成功，且失败数为零 |
| 构建成功 | 本轮构建命令退出状态为零 |
| 缺陷已修复 | 原始复现或回归测试在修复后通过 |
| 验收标准满足 | 逐条核对 `AC-*`、场景、切片、代码和验证结果 |
| 变更已提交 | 已核对提交范围、标题和关联验证记录 |
| 已交付 | 必要验收通过，未验证项和高风险已明确披露 |

## 禁止行为

- 不用“应该”“看起来”“大概”替代验证结论。
- 不用格式化、静态检查或单元测试替代它们不能证明的构建、集成或真实路径结论。
- 不把他人或其他智能体的成功报告直接当作完成证据。
- 未运行必要验证时，不得以任何同义表达暗示任务已完成。

## 输出

按验收标准组织的验证记录：命令或操作、时间、结果、覆盖范围、未执行项、环境限制、残余风险和交付结论。
