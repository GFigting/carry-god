# 知识库总览

## 概述

知识沉淀是框架的"长期记忆"。所有技术决策、踩坑经验、最佳实践、调研报告都在这里留存，确保知识不因人员流动而丢失。

当某项目在开发中反复出现结构相近的页面、相同的处理方式、项目特有的权限/配置规则等模式时，应按「项目级开发约定归档流程」（详见 [[AGENT.md]]）归档到对应目录。

---

## 目录指南

| 目录 | 用途 | 典型内容 |
|------|------|----------|
| [[最佳实践]] | 跨项目或项目级的规范与约定 | 编码规范、Git工作流、API设计规范、项目级开发约定 |
| [[技术文档]] | 按技术领域/项目组织 | 方案设计、API文档、架构说明、项目技术速查、项目踩坑记录 |
| [[经验教训]] | 踩坑记录与改进建议 | 故障复盘、问题根因分析、改进措施 |
| [[技术调研]] | 技术评估与选型 | 技术对比、POC报告、竞品分析 |
| [[外部资源]] | 有用的外部链接与参考 | 文档、博客、论文 |
| [[业务领域]] | 特定行业/业务线知识 | 财务规则、供应链流程、CRM策略、合规要求 |

## 知识成熟度

每个知识文档都有 `maturity` 字段标记其成熟度：
- **draft** — 初稿，可能不完整或有待验证
- **verified** — 已验证，经实践确认
- **adopted** — 团队已采纳，成为标准做法
- **deprecated** — 已过时，不再适用

## 按领域浏览

```dataview
TABLE WITHOUT ID
  file.link AS "文档",
  topic AS "主题",
  maturity AS "成熟度",
  date(updated) AS "最近更新"
FROM "5.知识沉淀"
WHERE type = "knowledge"
SORT domain ASC, updated DESC
GROUP BY domain
```

## 最近更新

```dataview
TABLE WITHOUT ID
  file.link AS "文档",
  domain AS "领域",
  date(updated) AS "更新时间"
FROM "5.知识沉淀"
WHERE type = "knowledge"
SORT updated DESC
LIMIT 15
```
