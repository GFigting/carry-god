# UTIL-需求导出协议 — 需求文档导出给外部人员

## 目的

将框架内某个 Goal 分点的需求文档（实施计划、原型、审核报告、grill 明细等非代码产物）整理为**独立的需求文档包**，供外部人员（非本框架使用者）阅读和传递。导出包放入 `A.目标体系/_需求收件箱/`，人类自行取走分发。

> **与 `/withInbox` 的关系**：`/withInbox` 是"入站"（外部需求→框架），本协议是"出站"（框架需求→外部）。两者方向相反，共用收件箱目录。

---

## 触发方式

TL 模式下，人类口头指令即可触发，无需专用 with 指令。典型说法：

- "把 GOAL-XXX P{N} 的需求整理导出到收件箱"
- "把这个分点的文档打包给外部人看"
- "导出需求文档包"

---

## 执行模型

```
人类: 导出 GOAL-XXX P{N} 需求文档包
      ↓
Agent 读取 Goal 目录，定位 P{N} 相关的全部产物文件
      ↓
筛选：排除代码文件（.sql / .java / .vue / .ts 等），保留非代码产物
      ↓
去标识化处理（见下方规则）
      ↓
在 _需求收件箱/ 下创建 {业务主题名}/ 目录
      ↓
复制去标识化后的文件 + 生成 README.md 索引
      ↓
口头报告导出结果
```

---

## 去标识化规则 ⚠️ 强制

> **核心原则**：导出的文档包应对外部人员（及其 AI Agent）完全透明。外部人员的 Goal/分点体系与本地不同，本地标识（GOAL-XXX、P{N}、任务序号等）只会造成困惑。

### 规则 1：目录名去标识化

- 目录名使用**纯业务主题**，不含 GOAL 编号和分点号
- 格式：`{业务主题}` 或 `{项目}-{业务主题}`
- 例：~~`GOAL-002-P5-收支流水需求文档包`~~ → `收支流水统一表需求`

### 规则 2：文件名去标识化

- 去除产物工件前缀 `[GOALNNN]-[NN-NN-NN]-ART-角色-`
- 仅保留**业务描述部分**
- 例：
  - ~~`[GOAL002]-[05-00-01]-ART-TL-资金流向看板原型.html`~~ → `资金流向看板原型.html`
  - ~~`[GOAL002]-[05-00-02]-ART-TL-实施计划.md`~~ → `实施计划.md`
  - ~~`[GOAL002]-[05-00-03]-ART-CR-计划审核报告.md`~~ → `计划审核报告.md`
  - `05-grill明细.md` → `需求澄清明细.md`（也去掉分点号前缀）

### 规则 3：文件内容去标识化

- **Frontmatter**：去除 YAML frontmatter 块（`---...---`），外部人员的工具不解析这些字段
- **正文中的 GOAL 引用**：将 `GOAL-XXX P{N}` 替换为纯业务描述
- **内部路径引用**：将框架内部路径（如 `A.目标体系/GOAL-002-.../`）替换为相对路径（`./`）或直接去除
- **保留内容**：业务需求描述、技术方案、字段定义、审核意见、决策记录等纯业务内容

### 规则 4：README.md 去标识化

生成的 README.md 索引文件：
- 标题使用**纯业务名称**
- 不出现 GOAL 编号、分点号、任务序号
- "来源"字段可保留项目名（如 lasen），但不引用框架结构
- 状态描述用业务语言（"已审核"而非"CR 审核通过"）

## 文件筛选规则

### 包含（非代码产物）

| 类型 | 示例 | 说明 |
|------|------|------|
| 实施计划 | `ART-TL-实施计划.md` | 核心需求文档 |
| 审核报告 | `ART-CR-计划审核报告.md` | 独立审核视角 |
| 原型/线框图 | `.html` 原型文件 | 可视化需求表达 |
| Grill 明细 | `grill明细.md` | 需求澄清 Q&A |
| 需求文档 | `.md` / `.txt` | 任何文字需求描述 |
| 截图/图片 | `.png` / `.jpg` | 辅助理解的视觉材料 |

### 排除（代码/框架内部文件）

| 类型 | 示例 | 排除理由 |
|------|------|---------|
| DDL SQL | `DDL-fc_flow_detail.sql` | 代码文件，应由开发流程产出 |
| Menu SQL | `menu_*.sql` | 代码文件 |
| 任务文件 | `TASK-*.md` | 框架内部追踪用 |
| 工作记录 | `工作记录.md` | 框架内部追踪用 |
| 历史分点 | `历史分点.md` | 框架内部归档用 |

## README.md 模板

导出包根目录下生成 README.md，使用以下模板：

```markdown
# {业务主题名}

> 整理日期：{日期}
> 来源项目：{项目名}

## 背景

{一段话描述业务背景和目标效果，不引用框架编号}

## 文档清单

| 文件 | 说明 |
|------|------|
| {文件名} | {一句话说明} |

## 关键技术决策摘要

- {决策1}
- {决策2}

## 状态

- {用业务语言描述当前阶段}
```

## 执行约束

### 必须做

- 导出前**读取 Goal 目录下所有产物文件**，理解 P{N} 的完整上下文
- **严格去标识化**：文件名 + 目录名 + 文件内容 frontmatter + 正文引用
- **README.md 使用纯业务语言**，不出现框架内部编码
- 导出后口头报告：导出位置、包含文件数、排除了哪些文件及原因
- 原始文件**原样保留不动**，导出的是去标识化后的**副本**

### 禁止做

- 不修改原始 Goal 目录下的任何文件
- 不在导出包中保留框架 frontmatter
- 不在 README.md 中引用 GOAL 编号或分点号
- 不导出代码文件（SQL/Java/Vue/TS 等）
- 不导出框架内部管理文件（工作记录/历史分点/任务文件）
