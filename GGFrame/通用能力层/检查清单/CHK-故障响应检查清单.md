# 故障响应检查清单

本检查清单用于 [[PROC-故障响应流程]] 全流程节点，指导 SRE 工程师、技术负责人和 DevOps 工程师在故障发生时按标准化步骤响应，覆盖告警确认、影响评估、止损、根因定位到复盘的全生命周期。

## 检查项

| # | 检查项 | 通过标准 | 不通过处理 |
|---|--------|---------|-----------|
| 1 | 告警/报障确认 | 收到告警或报障后 5 分钟内完成：查看监控大盘和日志确认故障是否真实存在、排除误告警、确认故障开始时间 | 确认误告警则关闭工单，标记为误报，记录原因；确认真实故障则立即进入检查项 2 |
| 2 | 影响范围评估 | 明确受影响的服务/模块、受影响的用户比例（全量/部分/少量）、受影响的功能范围（核心/非核心）、是否有规避方案 | 影响范围不明确时继续排查，但不可阻塞止损操作——影响评估和止损可并行进行 |
| 3 | 故障严重级别定级 | 按 P0/P1/P2/P3 标准准确判定：P0=核心业务完全不可用全量用户、P1=核心功能降级或部分用户（>10%）、P2=非核心功能异常少量用户（<10%）、P3=轻微问题 | 定级不准确时由技术负责人修正；P0/P1 故障向上级和业务方及时通报 |
| 4 | 应急指挥启动（P0/P1） | P0 故障 15 分钟内组建应急小组，P1 故障 30 分钟内组建；故障指挥官已指定、专用沟通渠道已建立、各角色（运维执行/技术排查/对外发言人）已就位 | 无法及时组建时由可用最高级别技术负责人临时直接指挥，边组建边止血 |
| 5 | 止损措施执行 | 执行至少一项有效的应急止损操作（服务降级/限流/切换备用节点/重启异常服务/回滚最近变更），操作前确认回滚方案，不可逆操作双人确认 | 止损无效时立即切换策略（如从重启升级为回滚）；操作导致二次故障时停止操作并记录 |
| 6 | 最近变更排查 | 检查故障时间窗口内的最近发布记录、配置变更、数据库变更、基础设施变更，识别可能触发故障的变更 | 发现可疑变更后评估回滚可能性，回滚优于继续排查；无相关变更则扩展排查范围 |
| 7 | 服务恢复确认 | 服务恢复后核验：错误率回到基线、延迟 P90/P99 回到正常范围、QPS 恢复故障前水平、用户侧确认功能可用 | 仅部分恢复或指标仍有波动时，继续调整止损策略，不可提前关闭故障 |
| 8 | 根因定位 | 根因定位到具体模块/代码行/配置项/基础设施组件级别，完成 5 Whys 分析，明确触发条件和根本原因 | 2 小时内无法定位根因时，以当前有效止损方案维持服务，根因分析转为事后排查任务 |
| 9 | 修复方案验证 | 修复方案针对根因而非表面现象，修复代码/配置变更通过回归验证，修复后核心指标持续稳定 >= 30 分钟 | 修复引入新问题则回滚修复、重新制定方案；指标不稳定则继续观测并准备备用方案 |
| 10 | 故障时间线记录 | 完整记录故障关键时间节点：发现时间、定级时间、应急小组就位时间、止损执行时间、服务恢复时间、修复部署时间、故障关闭时间；每步操作记录执行人和结果 | 时间线不完整则在故障关闭前补充，关键操作遗漏须由操作人回忆并补充记录 |
| 11 | 故障复盘触发 | P0 故障：3 个工作日内组织复盘；P1 故障：5 个工作日内组织复盘；复盘聚焦流程和系统改进（Blameless），输出含 Action Items（责任人+截止日期）的复盘报告 | 超期未复盘由技术负责人跟踪催办；复盘质量不达标（无 Action Items 或无责任人）则重新组织 |
| 12 | 监控告警优化评估 | 评估现有监控告警是否能覆盖本次故障模式：本次故障是否有相应告警规则、告警阈值是否合理、告警到响应的时间是否符合 SLA | 缺失告警规则须在复盘 Action Items 中添加；阈值不合理则调整并记录变更 |

## Agent 使用说明

当 Agent 以 [[ROLE-OPS-002]] 或 [[ROLE-ARCH-001]] 角色执行本检查清单时：

1. **故障发现阶段（检查项 1-2）**：
   - 读取告警通知原文（Prometheus Alert / PagerDuty 消息），提取告警指标名称、当前值、阈值
   - 调用监控大盘（Grafana / Prometheus）API 查看对应时间段的指标图表，确认是否存在异常波动
   - 查询最近 30 分钟的应用日志和系统日志，检索 ERROR/FATAL 级别日志
   - 根据告警服务查询该服务的上下游依赖，评估影响链路
   - 输出：故障确认单（含故障现象、初步影响范围、开始时间、置信度）

2. **故障定级阶段（检查项 3）**：
   - 对照故障严重级别定义表（P0/P1/P2/P3），结合影响范围评估结果给出定级建议
   - 输出：故障定级单（严重级别 + 判定依据）
   - 注意：定级由人类 SRE 工程师最终确认，Agent 提供分析数据和初步建议

3. **应急止损阶段（检查项 4-6）**：
   - 检索对应服务的故障 Runbook（`通用能力层/运维手册/`），提取推荐的应急操作流程
   - 查询最近发布记录（发布平台 / Git 日志），筛选故障时间窗口内的变更
   - 对于每项变更，评估其与故障现象的关联度，排序可疑程度
   - 输出：可疑变更列表（排序）、建议止损操作序列（从低风险到高风险）

4. **恢复确认阶段（检查项 7）**：
   - 持续轮询监控 API（建议 30 秒间隔），获取错误率、延迟 P90/P99、QPS 的实时值
   - 与故障前的基线值对比，确认各指标已回到安全区间
   - 输出：恢复确认单（含恢复时间、当前指标值 vs 基线值对比表）

5. **根因分析阶段（检查项 8-9）**：
   - 聚合故障时间窗口的 ERROR 日志，按频率和堆栈聚类，识别高频错误模式
   - 检索分布式追踪系统（Jaeger / Zipkin）的 Trace 数据，定位异常调用链
   - 对可疑代码变更做diff分析，评估变更与错误模式之间的因果关系
   - 执行 5 Whys 分析：从错误现象出发，逐层追问"为什么"，直到找到根本原因
   - 输出：根因分析记录（含 5 Whys 链、定位到的具体模块/代码/配置、触发条件）

6. **事后阶段（检查项 10-12）**：
   - 从故障处理过程中自动提取各节点时间戳，生成故障时间线
   - 对于复盘（检查项 11），Agent 辅助制作复盘报告草稿：时间线整理、根因总结、若需追踪的 Action Items 模板
   - 对于监控优化（检查项 12），对比故障模式和现有告警规则列表，识别告警盲区
   - 输出：时间线记录、复盘报告草稿（含建议 Action Items）

7. **人类介入点**：
   - 检查项 3（故障定级）：须人类 SRE 最终确认
   - 检查项 4（应急指挥启动）：领导者角色须人类担任
   - 检查项 5（止损执行）：生产环境操作须人类执行，Agent 提供操作建议和风险评估
   - 检查项 11（复盘）：复盘会议须人类主持，Agent 提供数据整理和报告起草
