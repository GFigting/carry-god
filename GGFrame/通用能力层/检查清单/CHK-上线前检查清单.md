# 上线前检查清单

本检查清单用于 [[PROC-需求到上线]] 的 `node_release` 节点和 [[PROC-发布流程]] 的 `node_prep` 节点，确保发布上线前所有必要条件均已满足。

## 检查项

| # | 检查项 | 通过标准 | 不通过处理 |
|---|--------|---------|-----------|
| 1 | 代码冻结确认 | 发布窗口内无未经审批的新代码合入，所有改动已通过 CI 完整流水线 | 冻结发布，移除未审批的提交后重新走 CI，更新审批记录 |
| 2 | 单元测试覆盖率 | 新增/变更代码单元测试覆盖率 >= 80%，所有测试用例通过 | 补充单元测试至达标，重新执行全量测试套件 |
| 3 | 集成测试 / E2E 测试 | 核心业务流程的集成测试全部通过，无阻塞级失败用例 | 排查失败用例根因，修复后重新运行，测试报告更新为 passed |
| 4 | 安全扫描结果 | 安全扫描无高危（Critical/High）漏洞，中危漏洞已有豁免审批 | 修复高危漏洞后重新扫描；中危漏洞补充风险评估和豁免审批记录 |
| 5 | 配置变更核对 | 环境变量、配置文件、Feature Flag、密钥等变更与配置变更清单一致，且已在目标环境预检 | 核对清单逐项确认，不一致项修正后在预发布环境重新验证 |
| 6 | 数据库 Migration 验证 | Migration 脚本已在预发布环境成功执行（正向+回滚均通过），无数据丢失 | 修复 Migration 脚本逻辑，预发布环境重新执行直至正反向均通过 |
| 7 | 预发布冒烟测试 | 预发布环境核心业务流程可用，关键 API 响应正常，无新增异常 | 记录失败项，排查并修复后重新部署预发布环境并完成冒烟测试 |
| 8 | 回滚方案就绪 | 回滚方案已文档化，包含回滚步骤、回滚验证方法、预估回滚耗时；回滚所需的上版本部署包/镜像仍可用 | 编写或完善回滚方案文档，确认上版本制品可获取，技术负责人签字确认 |
| 9 | 监控告警配置 | 新增功能相关监控指标和大盘已配置，告警规则已设定（含阈值和通知渠道），告警通知已测试可达 | 补充缺失的监控指标和告警规则，发送测试告警确认通知渠道正常 |
| 10 | 发布审批状态 | 发布申请单已获技术负责人和产品经理审批，发布窗口已确认且在允许时段内 | 补充审批签字，确认发布窗口与团队日历无冲突 |
| 11 | 依赖服务健康检查 | 上游依赖服务和下游依赖服务的生产环境健康状态正常，无阻塞级故障 | 等待依赖服务恢复，或评估在依赖降级模式下是否可发布 |
| 12 | 灰度策略配置 | 灰度发布参数（初始比例、放量步长、观察间隔、回滚阈值）已设定并评审通过 | 完善灰度策略参数，技术负责人和DevOps工程师确认后重新配置 |

## Agent 使用说明

当 Agent 以 [[ROLE-OPS-001]] 或 [[ROLE-QA-001]] 角色执行本检查清单时：

1. **逐项对照检查**：按检查项编号顺序，逐项从原始数据源（CI 系统、安全扫描报告、配置管理系统、监控平台）获取检查证据
2. **证据记录**：每项通过时记录证据来源（如 CI Job URL、扫描报告链接、配置截图）；不通过时记录具体不达标内容和对应的"不通过处理"建议
3. **结论汇总**：在检查清单末尾生成汇总表格，包含「检查项编号 | 检查项名称 | 通过/不通过 | 证据/说明」
4. **阻断判断**：存在任一不通过项时，结论为「不建议发布」，明确列出所有阻塞项并给出修复预计工作量；全部通过时结论为「建议发布」
5. **输出格式**：将检查结果以 Markdown 格式输出，作为 [[PROC-发布流程]] `node_prep` 节点的输入——发布准备确认单
6. **人类介入点**：检查项 10（审批状态）和检查项 12（灰度策略）需人类确认，Agent 仅能校验文档存在性，最终审批状态须人类在审批系统中核实
