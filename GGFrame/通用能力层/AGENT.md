## 检查清单的使用方式

检查清单是 Agent 执行关键操作时的强制性参考，确保不遗漏步骤。使用方式：

1. **加载检查清单**：根据任务类型，确定需要加载哪个检查清单（代码审查、上线、安全、故障响应）
2. **逐项对照**：按检查清单中的项目逐项执行，每完成一项在心中标记
3. **记录偏差**：如果某项不适用或无法执行，在任务文件中记录原因
4. **引用检查清单**：在输出报告或 PR Review 中引用检查清单项作为审查依据

**检查清单与角色/流程的绑定关系**：
- 代码审查：`ROLE-代码审核员` + `PROC-代码审查流程` + `CHK-代码审查检查清单`
- 上线发布：`ROLE-DevOps工程师` + `PROC-发布流程` + `CHK-上线前检查清单`
- 故障响应：`ROLE-SRE工程师` + `PROC-故障响应流程` + `CHK-故障响应检查清单`

## 工具手册的使用方式

工具手册提供标准化操作指南，确保团队使用工具时行为一致。

### Agent 权限边界

Agent 在使用工具手册时需注意以下权限约束：

1. **只读优先**：Agent 以查询和参考为主。执行写操作前必须确认权限。
2. **危险操作必须确认**：涉及删除、强制推送、生产环境变更等操作，必须经人类确认后执行。
3. **遵循工具手册中的安全约束**：如果手册中标注了 `[危险]` 或 `[需审批]`，Agent 不得跳过审批流程。
4. **回滚先于执行**：如果手册中提供了回滚方案，Agent 在执行变更操作前应确保回滚方案可用。
5. **不在工具手册范围外的操作**：如果需要的操作没有对应的工具手册，Agent 应告知人类并建议补充文档。

### 按需加载

- Agent 不需要加载所有工具手册，只加载当前任务涉及的工具
- `🛠️_能力总览.md` 中的能力矩阵可以帮助确定哪些角色需要哪些工具手册

## 脚本库索引

`脚本库/脚本索引.md` 包含：
- 脚本目录结构（deploy / data-migration / monitor-check / ops-automation）
- 脚本编写规范（独立执行、入参校验、幂等性、错误处理、日志输出、退出码）
- Shell 脚本模板和 Python 脚本模板
- Agent 使用说明

**Agent 编写脚本时**：
1. 参考模板保持风格统一
2. 根据功能放入对应分类目录
3. 更新脚本索引中的目录结构条目
4. 在 staging 环境执行 dry-run 验证

## 与其他板块的联动

- **角色体系**：角色定义中的 `checklists` 字段引用了检查清单，`tools` 字段引用了工具手册。Agent 绑定角色后应按需加载。
- **流程引擎**：流程 node 的 `checklist` 字段引用检查清单。执行到对应 node 时必须加载。
- **工作体系**：工作类型定义中的 context_pack 可能引用检查清单作为 required 上下文。
- **知识沉淀**：工具使用中的经验教训和坑点应归档到 `经验教训/`。
- **导航系统**：`导航系统/📑_工具索引.md` 提供了所有工具和检查清单的快速浏览。

## Agent 操作清单

1. **确定需要的能力**：根据任务类型和角色绑定，确定需要哪些检查清单和工具手册
2. **加载检查清单**：执行关键操作前，先加载对应检查清单，逐项对照执行
3. **查阅工具手册**：需要使用具体工具时，查阅对应的 UTIL 文件获取标准化操作方式
4. **遵守权限边界**：危险操作必须确认，回滚先于执行，不在手册范围外的操作要告知人类
5. **查脚本库**：需要自动化操作时，先查 `脚本库/脚本索引.md` 看是否已有可用脚本
6. **编写新脚本**：按模板规范编写，放入正确目录，更新脚本索引
