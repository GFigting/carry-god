# 日志与追踪 — Agent 使用指引

## 何时读取本板块

- Agent 需要记录每日工作总结（日报）时
- Agent 需要编写或查看周报时
- Agent 需要记录或查阅会议纪要时
- Agent 需要更新框架自身的变更日志时
- 人类要求 Agent 汇总某段时间的工作内容时
- Agent 完成重要操作后需要留下追踪记录时

## 板块结构

```
7.日志与追踪/
├── AGENT.md               ← 本文件
├── 变更日志.md            ← 框架自身的结构变更记录
├── 日报/                  ← 每日工作记录
│   └── YYYY/
│       └── YYYY-MM-DD.md
├── 周报/                  ← 每周工作总结
│   └── YYYY/
│       └── WK-YYYY-NN.md
└── 会议纪要/              ← 会议记录
    └── MTG-YYYY-MM-DD-{主题}.md
```

## 关键文件索引

| 文件 | 用途 | 读取优先级 |
|------|------|:--:|
| `变更日志.md` | 框架结构变更记录，记录新增/修改/废弃 | P0（框架变更时） |
| `日报/YYYY/YYYY-MM-DD.md` | 每日工作内容记录 | P1 |
| `周报/YYYY/WK-YYYY-NN.md` | 每周工作总结汇总 | P1 |
| `会议纪要/MTG-*.md` | 会议讨论内容和决策记录 | P2 |

## 日报的格式

日报存放在 `7.日志与追踪/日报/YYYY/` 下，文件名为 `YYYY-MM-DD.md`。

使用 `.obsidian/templates/tpl-daily-log.md` 模板创建。标准 frontmatter：

```yaml
---
type: daily-log
title: "{日期} 工作日志"
date: "YYYY-MM-DD"
tags:
  - type/daily-log
created: "YYYY-MM-DD"
---
```

正文通常包含：
- **今日完成**：当天完成的任务编号和摘要
- **进行中**：正在进行的任务和进度
- **阻塞项**：遇到的问题和阻塞原因
- **明日计划**：次日的计划安排

**Agent 操作原则**：
- Agent 完成一个任务后，可在对应日期的日报中追加一条完成记录（任务编号 + 完成摘要）
- 如果当天日报不存在，询问人类是否需要创建
- Agent 不主动创建日报文件，除非人类明确要求

## 周报的格式

周报存放在 `7.日志与追踪/周报/YYYY/` 下，文件名为 `WK-YYYY-NN.md`（NN 为 ISO 周数）。

**Agent 操作原则**：
- Agent 可协助汇总一周内完成的日报内容生成周报
- 周报内容应包含：本周完成、下周计划、风险和阻塞、需要关注的议题
- Agent 不主动创建周报文件，除非人类明确要求

## 会议纪要的格式

会议纪要存放在 `7.日志与追踪/会议纪要/` 下，文件名为 `MTG-YYYY-MM-DD-{主题}.md`。

使用 `.obsidian/templates/tpl-meeting.md` 模板创建。标准 frontmatter：

```yaml
---
type: meeting
title: "{会议主题}"
date: "YYYY-MM-DD"
participants: []
tags:
  - type/meeting
created: "YYYY-MM-DD"
---
```

正文通常包含：会议议题、参与人员、讨论要点、决策事项、待办行动项。

**Agent 操作原则**：
- Agent 被要求记录会议时创建
- 重点关注"决策事项"和"待办行动项"，这些可能衍生为新任务

## 变更日志的更新规范

`变更日志.md` 用于记录本框架（Vault）自身的结构变更，而非业务代码变更。

**格式规范**：
```markdown
## YYYY-MM-DD

### 新增
- 新增了哪些目录/文件/模板

### 修改
- 修改了哪些内容，为什么

### 废弃
- 哪些内容被废弃/删除
```

**Agent 更新时机**：
- Agent 创建了新的板块文件、模板、流程时
- Agent 修改了框架的目录结构时
- Agent 废弃了某个不再使用的文档或模板时

**Agent 不需要更新变更日志的情况**：
- 在现有任务文件中更新状态（这是任务系统的工作）
- 修改知识文档的内容（知识文档自身的 updated 字段已记录）
- 创建日报/周报/会议纪要（这些是常规日志，不是框架变更）

## 与其他板块的联动

- **任务系统**：日报/周报中引用任务编号来关联完成的工作项。任务完成后的关键信息可汇总到日报中。
- **知识沉淀**：重要的经验教训和技术发现通过日报/周报反映后，应归档到知识沉淀中。
- **配置与元数据**：日报使用 `type/daily-log` 标签，周报使用 `type/weekly-report` 标签，会议纪要用 `type/meeting` 标签。
- **流程引擎**：周报中的"下周计划"可能引用了待执行的流程。

## Agent 操作清单

1. **更新变更日志**：对框架结构做出变更后（新增/修改/废弃文件或目录），在 `变更日志.md` 中按日期记录
2. **记录日报**：被要求记录日报时，使用 `tpl-daily-log` 模板创建，关联完成的任务编号
3. **生成周报**：被要求生成周报时，汇总当周日报内容，输出 WK 格式文档
4. **记录会议**：被要求记录会议时，使用 `tpl-meeting` 模板创建，重点关注决策和待办行动项
5. **查阅历史**：需要了解历史决策或工作进度时，按日期检索日报/周报/会议纪要
6. **清理归档**：定期（如每季度）将旧日志移至归档或按年份整理目录结构
