# 工作类型总览

## 概述

工作体系将 IT 研发部门的所有工作拆解为明确的工作类型。每种工作类型定义了：
- **生命周期**：该工作经历的状态序列
- **角色参与**：RACI 矩阵——谁负责、谁执行、谁咨询、谁知会
- **输入输出**：开始前需要什么、完成后产出什么
- **质量门禁**：完成前必须通过的检查点

---

## 工作分类

| 分类 | 核心工作类型 | 典型场景 |
|------|-------------|----------|
| **开发类** | 新功能开发、Bug修复、重构、技术债清偿、依赖升级 | 日常研发迭代 |
| **运维类** | 部署发布、监控告警、容量规划、灾备演练、证书轮换 | 系统稳定运行 |
| **架构类** | 系统设计、技术选型、架构评审、性能优化 | 技术规划与演进 |
| **测试类** | 测试用例设计、自动化测试、性能测试、安全测试 | 质量保障 |
| **管理类** | 迭代计划、需求分析、风险管理、干系人沟通 | 项目管理 |
| **调研类** | 技术调研、竞品分析、POC验证 | 技术探索与决策 |
| **事件类** | 故障响应、问题管理、变更管理、故障复盘 | 应急与改进 |

## 所有工作类型

```dataview
TABLE WITHOUT ID
  file.link AS "工作类型",
  category AS "分类",
  primary_owner AS "主负责角色",
  typical_duration AS "典型耗时"
FROM "2.工作体系"
WHERE type = "work-type"
SORT category ASC, file.name ASC
```
