# 系统设计

## 概述

系统设计是将业务需求转化为技术架构方案的核心工作。它包括从高层次架构决策到模块划分、接口定义、数据模型设计的完整过程。良好的系统设计是高质量软件交付的基础，直接影响系统的可扩展性、可维护性和性能。

## 典型子任务结构

**按设计层次拆解：**
1. 系统架构设计：整体架构风格（微服务/单体/事件驱动）、技术栈选型、部署拓扑
2. 模块划分设计：领域划分、模块边界、依赖关系、接口契约
3. 数据架构设计：数据模型、存储选型、读写分离、缓存策略
4. 接口设计：API定义、协议选择、鉴权方案、限流策略
5. 非功能设计：性能指标、安全架构、可观测性、灾备方案

**按4+1视图拆解：**
1. 逻辑视图：功能分解、模块职责
2. 开发视图：包结构、分层架构
3. 进程视图：运行时交互、并发模型
4. 物理视图：部署节点、网络拓扑
5. 场景视图：关键用例的端到端流程

| 数据模型设计（ER图/表结构） | 后端开发/DBA | 满足业务查询需求且性能可行 |

## 质量门禁 (Quality Gates)

1. **设计评审通过**：至少1名架构师和1名TechLead参加评审并批准
2. **非功能需求满足**：设计方案能支撑性能、安全、可用性等关键指标
3. **关键技术决策可追溯**：所有重要技术选择的理由记录在设计文档的决策记录（ADR）中
4. **接口契约清晰**：上下游接口已明确定义，无二义性

### Agent 执行提示

1. 先理解业务场景和核心用例，再动手画架构图
2. 使用C4模型分层描述架构：Context -> Container -> Component -> Code
3. 每个关键决策都写ADR（架构决策记录），记录上下文、选项、理由和后果
4. 关注非功能性需求，性能和安全的考量不能事后弥补
5. 设计评审会前1天发送文档，让评审者有充足时间消化内容
