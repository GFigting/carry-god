# 测试用例设计

## 概述

测试用例设计是根据需求文档和技术设计，系统化地编写测试用例的过程。高质量的测试用例是测试工作的基石，决定了测试的覆盖度、有效性和效率。好的用例设计应该覆盖正常流程、边界条件、异常场景和用户故事验收标准。

## 典型子任务结构

**按用例类型拆解：**
1. 功能测试用例：验证功能是否符合需求（正向流程）
2. 边界值测试用例：输入的有效范围上下界、临界条件
3. 异常测试用例：非法输入、网络中断、超时等异常场景
4. 集成测试用例：模块间交互、端到端业务流程
5. 兼容性测试用例：不同浏览器/设备/系统版本

**按测试方法拆解：**
1. 等价类划分法：将输入数据划分为有效等价类和无效等价类
2. 边界值分析法：在等价类边界上设计测试用例
3. 场景法：模拟用户实际操作流程
4. 判定表法：处理多条件组合的复杂业务逻辑

## 质量门禁 (Quality Gates)

1. **需求覆盖完整**：每条PRD功能点和验收标准至少对应1条正向用例
2. **场景类型齐全**：包含正常流程、边界值、异常场景三类
3. **用例评审通过**：至少1名开发 + 1名QA参与评审并确认覆盖充分
4. **用例可执行**：前置条件明确、步骤可操作、预期结果可衡量

### Agent 执行提示

1. 先读懂PRD，不理解的地方标注出来在用例评审时澄清
2. 用「前置条件-操作步骤-预期结果」三段式编写，每步清晰可执行
3. 不要只写「快乐路径」，至少要包含一个边界和两个异常场景
4. 给用例打优先级标签（P0/P1/P2），帮助测试计划合理安排执行顺序
5. 需求的每个AC必须有对应的用例验证，形成可追溯矩阵
