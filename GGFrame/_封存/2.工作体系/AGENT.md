# 工作体系 — Agent 使用指引

## 何时读取本板块

- Agent 接到新任务，需要确定任务的**工作类型**时
- Agent 需要从工作类型定义中提取 `context_pack`（上下文包）时
- Agent 需要了解某类工作的生命周期、参与角色和质量门禁时
- Agent 需要判断自己的角色在某项工作中是 R/A/C/I 中的哪一种时
- 创建任务文件时，需要填写 `work_type` 字段和关联标签时

## 如何从工作类型定义中提取 context_pack

每个工作类型文件（`WT-*.md`）的 frontmatter 或正文中包含 `context_pack` 字段，定义了该工作类型的最小上下文集合：

```yaml
context_pack:
  required:         # Agent 必须加载
    - "1.角色体系/[对应角色].md"
    - "4.流程引擎/[对应流程].md"
    - "通用能力层/检查清单/[对应检查清单].md"
  optional:         # Agent 按需加载
    - "5.知识沉淀/最佳实践/[相关规范].md"
    - "5.知识沉淀/技术文档/[相关技术站].md"
    - "通用能力层/工具集/[相关工具].md"
```

**Agent 使用方式**：
1. 确定任务的工作类型（如 `WT-新功能开发`）
2. 读取该工作类型文件，定位 `context_pack` 字段
3. 按 `required` 列表加载必读文件，构建纯净上下文
4. 根据任务具体情况，从 `optional` 列表中选读参考文件

如果工作类型文件暂未定义 `context_pack`，可根据以下规则推断：
- 必读：该工作关联的流程文件 + 对应检查清单 + 主负责角色定义
- 参考：RACI 矩阵中标记为 C（Consulted）的角色定义 + 相关工具手册

## RACI 矩阵的使用方式

`工作-能力矩阵.md` 提供了完整的 RACI 矩阵表。Agent 应这样使用：

- **确定角色参与方式**：查表找到工作类型所在行，看自己（当前角色）的标记
  - **R (Responsible)** = 你是执行者，干活的人
  - **A (Accountable)** = 你是最终负责人，需要拍板决策
  - **C (Consulted)** = 你需要被征求意见，但不需要亲自动手
  - **I (Informed)** = 你只需要被通知结果
- **确定协作角色**：同行中其他标记为 R 或 A 的角色是需要协调的协作者
- **确定通知范围**：同行中标记为 I 的角色是任务完成后需要通知的人

## 与其他板块的联动

- **角色体系**：工作类型定义中的 `primary_owner` 和 RACI 矩阵直接关联角色。Agent 确定工作类型后，应立即加载对应角色定义。
- **流程引擎**：工作类型通常关联一个或多个流程（如 `WT-新功能开发` → `PROC-需求到上线`）。Agent 在执行时应加载关联流程。
- **任务系统**：创建任务文件时填写 `work_type` 字段，按工作类型选择任务模板（feature/bugfix/incident/research）。
- **通用能力层**：工作类型定义中的质量门禁引用了检查清单，应按需加载。
- **导航系统**：`0.导航系统/📑_工作类型索引.md` 提供了工作类型的快速跳转列表。

## Agent 操作清单

1. **确定工作类型**：分析用户请求，确定属于哪类工作（开发/运维/架构/测试/管理/调研/事件）
2. **读取工作类型定义**：打开对应的 `WT-*.md` 文件，关注生命周期、输入输出、质量门禁
3. **查 RACI 矩阵**：在 `工作-能力矩阵.md` 中确认自己（当前角色绑定）的参与方式
4. **加载上下文包**：按 context_pack 加载必读文件，构建纯净上下文
5. **确认质量门禁**：明确完成前必须通过的检查点，将这些检查清单加入执行计划
6. **创建任务文件**：在任务系统的 frontmatter 中填写正确的 `work_type` 值和关联标签
