> 此文件由**人类全权维护**。AI 只可读取理解方向，不可创建/修改/删除目标条目、勾选 checkbox、修改目标描述。
>
> 例外：AI 可在既有 Goal 的当前子目标下整理 `总览`、`分点`、`检查项`、`待确认`，并在分点行末尾追加/更新【状态标签】（如【代码:开发中】【SQL:已执行】【部署:已发布】等），详见下方「多维度状态标签」章节。

> 过渡期内，旧称“当前分点”等同“当前子目标”；分点可能会简称为 P（如 P1、P13）。

# 模板使用说明（给 AI Agent 读的，不要复制到实际目标总览中）

## 文件定位

`目标总览.md` 是整个框架的**北极星**。所有工作由此衍生，所有产物最终回链到此。
它是唯一一个"人类写、AI 读"的核心文件。AI 通过它理解：
- 当前有哪些活跃目标
- 每个目标做到哪了（当前子目标/分点 + 状态标签）
- 下一步该做什么

## 结构规范

### Goal 条目必填字段

| 字段 | 维护者 | 说明 |
|------|--------|------|
| `## GOAL-XXX: {名称}` | 人类 | 二级标题，GOAL 编号唯一，名称简洁 |
| `目标效果` | 人类 | 业务效果，不是技术实现。让 AI 一眼看懂"为什么要做这个" |
| `最近完成` | 人类 | 日期 + 简述，给 AI 快速判断进度 |
| `下一子目标序号` | AI（刷新维护） | 下次新增顶层数字子目标应使用的序号；即使当前子目标为空也保留，避免与历史编号冲突 |
| `当前子目标` | 人类/AI | checkbox 列表，每个子目标一句话效果 + 状态标签；旧字段 `当前分点` 过渡期等同该字段 |

### Goal 条目可选字段

| 字段 | 维护者 | 说明 |
|------|--------|------|
| `挂起子目标` | 人类 | 暂不推进的子目标，编号用字母（A/B/C）区分；旧字段 `挂起分点` 过渡期兼容 |
| `关键设计` | 人类/AI | 重要的架构决策、数据源、约束条件。AI 可在 TL 模式下追加 |

### 子目标与分点编号规则

- 数字序号（1, 2, 3...）= 活跃子目标，按优先级排列
- 字母序号（A, B, C...）= 挂起子目标
- 子目标下可嵌套分点（如 `分点`、`检查项`、`待确认`）
- 过渡期不强制重排旧编号，不批量迁移旧 Goal，使用时逐步升级
- `下一子目标序号` 是单调递增游标；新增顶层数字子目标时使用该值，后续由 `/frameworkRefresh` 综合当前与历史最大序号自动推进
- 当前子目标全部迁移后，长期 Goal 继续保留空的 `当前子目标` 和该序号游标，不因暂时无事项而从 1 重新编号

### 多维度状态标签

AI 读取目标总览时，通过状态标签快速判断分点的交付进度。标签由 AI（TL 模式）在分点行末尾追加/更新。

**维度标签**（按需出现，不涉及的维度不加）：
```
【代码:*】    — 代码层面：开发中 / 已生成 / 已提交
【SQL:*】     — 数据库层面：开发中 / 已生成 / 已执行
【部署:*】    — 部署层面：未部署 / 已发布
【配置:*】    — 配置层面：开发中 / 已完成（如 Nginx、环境变量、菜单权限）
【验证:*】    — 验证层面：未验证 / 已验证（如测试通过、人工确认）
【数据:*】    — 数据层面：开发中 / 已迁移（如 DDL 执行、数据清洗）
```

**全局标签**（可独立使用或与维度标签混合）：
```
【开发中】    — 正在进行，尚未完成任何维度
【待确认】    — 需要人类确认某些事项后才能继续
【阻塞】      — 被外部依赖阻塞
```

**标签示例**：
- `【代码:开发中】` — 刚开始写代码
- `【代码:已提交】【SQL:已执行】【部署:未部署】` — 代码和 SQL 都好了，等发布
- `【代码:已提交】【SQL:已执行】【部署:已发布】【验证:已验证】` — 全部完成
- `【阻塞】被 XX 系统接口未 ready 阻塞` — 被外部阻塞

## AI 读取协议

1. **只读默认**：AI 默认读取目标总览理解方向，不可创建/删除 Goal、勾选 checkbox、修改目标描述
2. **可整理子目标**：TL 模式叠加 `/withGo` 或用户明确要求时，AI 可在既有 Goal 的当前子目标下整理 `总览`、`分点`、`检查项`、`待确认`
3. **可追加状态标签**：TL 模式下，AI 可在分点行末尾追加/更新【状态标签】
4. **可追加关键设计**：TL 模式下，AI 可在「关键设计」节追加架构决策
4. **口头建议**：AI 可以口头向人类建议"某分点看起来已完成，是否迁移到历史分点"

## FW-FrameworkInit 初始化行为

当 `/frameworkInit` 执行 Phase 0（首次初始化检测）时：
1. 检查 `A.目标体系/目标总览.md` 是否存在
2. 若不存在 → 复制本模板文件为 `目标总览.md`，并提示用户：
   > 📄 已从模板创建 `目标总览.md`。请按你的实际情况填写 Goal 条目，
   >    删除 GOAL-00N 示例条目。AI 将通过此文件理解你的工作方向。
3. 若已存在 → 跳过，不做任何修改
