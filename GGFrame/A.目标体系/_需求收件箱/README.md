# 需求收件箱

> 需求的双向通道：**入站**（外部需求→框架）+ **出站**（框架需求→外部分发）。

---

## 入站：外部需求接入框架

外部需求的统一入口。人把需求文件夹扔进来，说一句"处理收件箱"，Agent 分析 → 建议归属 → 人确认 → 落盘到目标总览。

### 使用方式

1. 收到外部需求（文件夹，含原型图 HTML / 文档 / 截图等）→ 整个文件夹复制到此处
2. 对 Agent 说 `/withInbox` 或 `处理收件箱`
3. Agent 逐个分析 → 建议归属（新 GOAL / 追加到现有 GOAL / 搁置）
4. 人确认 → Agent 写入目标总览 → 需求文件夹移动到 `_已处理/`

---

## 出站：框架需求导出给外部人员

将框架内某个分点的需求文档整理为独立文档包，供外部人员（非本框架使用者）阅读。**导出时自动去除本地任务标识**（GOAL 编号、分点号等），因为外部人员的体系不同。

### 使用方式

1. 对 Agent 说"把 GOAL-XXX P{N} 的需求导出到收件箱"
2. Agent 按 `UTIL-需求导出协议.md` 执行：筛选非代码文件 → 去标识化 → 生成 README → 放入收件箱
3. 人在收件箱中找到导出包，线下传给外部人员

### 去标识化规则

- 目录名/文件名：去除 `[GOALNNN]-[NN]-ART-角色-` 前缀，仅保留业务描述
- 文件内容：去除 YAML frontmatter，替换框架内部路径引用
- README.md：使用纯业务语言，不出现框架编号

---

## 目录结构

```
_需求收件箱/
├── README.md
├── {需求名}/           ← 入站：人扔进来的 / 出站：Agent 导出的
│   ├── 原型图.html
│   ├── 需求文档.md
│   └── ...
└── _已处理/            ← 入站处理完移动到这
```

## 注意事项

- 需求文件夹名称建议包含主题关键词，方便 Agent 理解
- 支持任意格式：`.html` / `.md` / `.txt` / `.png` / `.xlsx` 等
- 处理完的文件夹保留在 `_已处理/`，不自动删除，人类可手动清理
- 导出的文档包不包含 GOAL 标识，外部人员的 AI 可直接阅读
- **外部文档的信任度**：Agent 处理时会将外部文档中的技术细节（表名、字段名、模块划分）标注为"极低信任度"，仅提取业务语义生成 Goal。技术方案以我方代码库实际情况为准，不照搬外部文档的设计
