# 商品管理新增品名字段开发计划

## 1. 需求背景

商品管理中需要为成品、面料、辅料统一增加“品名”字段，用于后续开票、对账或导出场景识别开票口径下的商品品名。

当前系统已有 `materialName`，表示中台同步过来的商品名称/物料名称。该字段会被物料同步覆盖，因此本需求不能复用 `materialName`，应新增独立字段保存“品名”。

## 2. 目标与范围

### 2.1 建设目标

- 商品管理列表展示“品名”字段。
- 支持按“品名”查询商品。
- 面料、辅料的“品名”由财务人员维护。
- 使用现有表格完成面料、辅料“品名”初始化导入。
- 成品“品名”从物流系统报关申报要素数据同步获取。
- 成品同步规则为：根据 SPU 名称精准匹配报关申报要素数据，并获取中文品名。

### 2.2 本期范围

- 后端 `fc_material` 表新增“品名”字段。
- 商品管理分页、详情、导出、维护接口增加“品名”。
- 前端商品管理列表、查询区、维护弹窗增加“品名”。
- 开发一次性初始化导入能力，用于处理：
  - `D:\FMScode\doc\开票中心\面辅料信息汇总-开票品名(1).xlsx`
- 成品物料同步时补充“品名”自动同步逻辑。

### 2.3 不在本期范围

- 不改造已有库存、采购、销售、ARAP 单据中的 `materialName` 冗余逻辑。
- 不将“品名”反写回中台或物流系统。
- 不允许财务人员手工修改成品“品名”，成品以物流报关申报要素同步结果为准。

## 3. 当前系统分析

### 3.1 现有物料主表

后端本地商品/物料主表为 `fc_material`，对应实体为：

- `MaterialDO`
- 表字段包括：
  - `material_id`
  - `material_code`
  - `material_name`
  - `material_type`
  - `color`
  - `size`
  - `specs`
  - `unit`
  - `parent_id`
  - `zt_id`
  - `status`

### 3.2 物料类型

现有物料类型口径：

| 类型 | 含义 |
|---|---|
| `SPU` | 成品父级 SPU |
| `P` | 成品 SKU |
| `M_P` | 面料父级 |
| `M` | 面料子级 |
| `F_P` | 辅料父级 |
| `F` | 辅料子级 |

### 3.3 同步覆盖风险

`MaterialSyncHelper` 会从中台同步并更新 `materialName`、`materialCode`、`unit`、`color`、`size`、`specs` 等字段。

因此“品名”必须新增独立字段，例如：

- 数据库字段：`invoice_name`
- Java/前端字段：`invoiceName`
- 页面展示名：`品名`

## 4. 数据设计

### 4.1 表结构变更

在 `fc_material` 表新增字段：

```sql
ALTER TABLE fc_material
ADD COLUMN invoice_name VARCHAR(256) NULL COMMENT '品名/开票品名';
```

同步更新测试库 H2 schema，避免后端测试失败。

### 4.2 字段定义

| 字段 | 类型 | 说明 |
|---|---|---|
| `invoice_name` | `VARCHAR(256)` | 商品品名/开票品名 |

### 4.3 字段维护规则

| 商品类型 | 维护方式 | 规则 |
|---|---|---|
| 成品 `SPU/P` | 自动同步 | 从物流系统报关申报要素按 SPU 名称精准匹配中文品名 |
| 面料 `M_P/M` | 财务维护 + 初始化导入 | 允许页面手工维护 |
| 辅料 `F_P/F` | 财务维护 + 初始化导入 | 允许页面手工维护 |

## 5. 后端开发计划

### 5.1 实体与 VO 改造

修改以下对象，增加 `invoiceName` 字段：

- `MaterialDO`
- `MaterialBaseVO`
- `MaterialRespVO`
- `MaterialPageReqVO`
- `MaterialExportReqVO`
- `MaterialExcelVO`

导出 Excel 增加列：

```text
品名
```

### 5.2 分页查询改造

`MaterialMapper.selectPage` 增加 `invoiceName` 模糊查询条件：

```java
.likeIfPresent(MaterialDO::getInvoiceName, reqVO.getInvoiceName())
```

`MaterialMapper.selectList` 导出查询同样增加该条件。

### 5.3 品名维护接口

新增轻量接口：

```http
PUT /fc/material/invoice-name
```

请求体：

```json
{
  "materialId": 1001,
  "invoiceName": "针织布"
}
```

接口规则：

- 校验物料存在。
- 仅允许 `M_P`、`M`、`F_P`、`F` 类型维护。
- `SPU`、`P` 类型不允许手工维护，避免覆盖物流系统同步结果。
- `invoiceName` 允许清空。

建议新增 VO：

```java
MaterialInvoiceNameUpdateReqVO
```

字段：

- `materialId`
- `invoiceName`

### 5.4 初始化导入能力

开发一次性导入服务或命令式脚本，用于读取：

```text
D:\FMScode\doc\开票中心\面辅料信息汇总-开票品名(1).xlsx
```

#### 面料页签

页签名称：

```text
6面料信息-开票名称
```

字段口径：

| Excel 列 | 用途 |
|---|---|
| `物料编码` | 匹配 `fc_material.material_code` |
| `开票品名` | 写入 `fc_material.invoice_name` |

匹配规则：

- `物料编码` 精准匹配 `fc_material.material_code`。
- 限定 `material_type IN ('M_P', 'M')`。
- `开票品名` 为空时不更新。
- 匹配多条时不更新，输出重复匹配清单。

#### 辅料页签

页签名称：

```text
辅料信息-开票名称
```

当前页签没有“开票品名”列，默认口径如下：

| Excel 列 | 用途 |
|---|---|
| `物料名称` | 匹配 `fc_material.material_name` |
| `单位` | 匹配 `fc_material.unit` |
| `分类` | 写入 `fc_material.invoice_name` |

匹配规则：

- `物料名称 + 单位` 精准匹配。
- 限定 `material_type IN ('F_P', 'F')`。
- `分类` 为空时不更新。
- 匹配多条时不更新，输出重复匹配清单。

#### 导入结果输出

导入完成后输出统计：

- 总行数
- 成功更新数
- 空品名跳过数
- 未匹配数
- 重复匹配数
- 表格重复 key 数

同时输出失败明细，便于财务或实施复核。

### 5.5 成品品名同步

新增物流/TMS 报关申报要素查询能力。

#### 数据来源

当前系统已有 TMS 数据源和报关单同步链路：

- `tms_customs_declaration`
- `tms_customs_declaration_item`
- `tms_customs_declaration_item_product`

但现有代码未读取“报关申报要素中文品名”字段，需要新增对应 DO/Mapper 或扩展现有 Mapper。

#### 同步规则

同步逻辑：

1. 获取成品 SPU 数据。
2. 获取物流系统报关申报要素数据。
3. 使用 `SPU名称 == 报关申报要素SPU名称` 精准匹配。
4. 匹配唯一时，取报关申报要素的中文品名。
5. 写入 `fc_material.invoice_name`。
6. 同步到 SPU 父级及其 SKU 子级，保证商品管理列表任意层级都有品名。

异常规则：

- 未匹配：不覆盖旧值，记录日志。
- 匹配多条：不覆盖旧值，记录冲突日志。
- 中文品名为空：不覆盖旧值。

## 7. 测试计划

### 7.1 后端测试

#### 分页查询

- 给物料设置 `invoiceName = 针织布`。
- 使用 `invoiceName = 针织` 查询。
- 断言返回该物料。

#### 手工维护接口

测试场景：

- 面料 `M` 可以更新品名。
- 面料父级 `M_P` 可以更新品名。
- 辅料 `F` 可以更新品名。
- 辅料父级 `F_P` 可以更新品名。
- 成品 `P` 更新时返回失败。
- 成品父级 `SPU` 更新时返回失败。
- 品名传空字符串时可以清空。

#### 初始化导入

测试场景：

- 面料按 `物料编码` 匹配成功并写入品名。
- 面料开票品名为空时跳过。
- 辅料按 `物料名称 + 单位` 匹配成功并写入分类。
- 辅料分类为空时跳过。
- 匹配不到时不更新并记录失败。
- 匹配多条时不更新并记录重复。

#### 成品同步

测试场景：

- SPU 名称唯一匹配申报要素，写入中文品名。
- SPU 名称未匹配，不覆盖旧品名。
- SPU 名称匹配多条，不覆盖旧品名。
- 申报要素中文品名为空，不覆盖旧品名。
- SPU 写入后，同步更新其 SKU 子级。

### 7.2 前端测试

测试场景：

- 商品管理列表展示“品名”列。
- 输入品名查询时，请求参数包含 `invoiceName`。
- 点击面料/辅料“维护品名”可打开弹窗。
- 保存成功后刷新列表。
- 成品行不能手工维护品名。

## 9. 风险与待确认事项

### 9.1 辅料表格口径

辅料页签没有“开票品名”列，当前计划默认使用 `分类` 作为品名初始化来源。

需要业务确认：

```text
辅料品名是否等于辅料分类？
```

### 9.2 TMS 申报要素表结构

当前代码中已有 TMS 报关单相关表，但未发现现成“申报要素中文品名”读取逻辑。

开发前需要确认：

- 报关申报要素所在表名。
- SPU 名称字段名。
- 中文品名字段名。
- 是否存在一条 SPU 对应多个中文品名的情况。

### 9.3 历史数据覆盖策略

当前建议：

- 初始化导入只覆盖空值或按导入任务明确覆盖。
- 成品同步匹配成功时可覆盖旧值。
- 匹配异常时不覆盖旧值。

如业务要求保留人工修正结果，需要增加“品名来源”字段或更新保护规则；本期默认不增加。

## 10. 建议实施顺序

1. 增加数据库字段与后端 VO/查询/导出改造。
2. 增加商品管理前端展示、查询和维护弹窗。
3. 增加面辅料初始化导入能力，并先在测试环境跑导入报告。
4. 确认 TMS 报关申报要素表结构。
5. 增加成品品名自动同步逻辑。
6. 执行后端、前端测试。
7. 在测试环境验证数据初始化结果。
8. 业务确认无误后上线。
