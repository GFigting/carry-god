# 开票中心开发设计

## 1. 目标与范围

开票中心用于承接对账管理后的票据维护流程。用户只能从对账单详情整单发起开票，系统自动识别该对账单下已生成正式账单且未全额开票的数据，生成开票记录、发票行、发票行关联明细、到票记录，并将开票金额、到票金额和状态回传到正式账单、对账单、对账明细。

本期目标：

- 只支持从对账单详情整单发起开票。
- 不支持从正式账单列表或正式账单详情发起开票。
- 不支持在对账单详情勾选明细发起开票。
- 系统自动按整张对账单计算剩余可开票金额。
- 发票行品名从商品管理新增字段 `fc_material.invoice_name` 获取。
- 自动按 `品名 + 款号 ztStyleNo + 采购单号 + 税率` 生成发票行。
- 支持默认带出对账单主体，并允许改选任意有效我方主体作为实际开票主体。
- 支持维护发票行展示名称、备注和分摊调整金额。
- 支持查看发票行关联的正式账单明细。
- 支持按实际发票号选择开票行登记到票，同一发票可覆盖多行，同一行可分属多张发票。
- 将开票金额、到票金额和状态回传到正式账单、对账单、对账明细。
- 预留开票导出接口和前端入口，模板类型包括面辅料、全卖、半卖，本期不生成真实文件。

本期不包含：

- 正式账单发起开票。
- 对账单明细勾选开票。
- 真实发票模板导出。
- 发票 OCR。
- 发票验真。
- 审批流。
- 自动结算。
- 费用类来源建模。

## 2. 总体方案

新增独立业务模块 `reconciliationinvoice`，避免与现有 `invoice-limit` 开票额度模块混淆。开票记录、发票行、发票行关联明细、到票记录作为事实表保存；正式账单、对账单、对账明细上的已开票金额、已到票金额和状态作为冗余聚合结果，用于列表展示、筛选和后续流程判断。

后端按现有项目分层：

- Controller 放在 `fms-module-biz`，负责路由、权限、参数校验和返回包装。
- Service、DO、Mapper 放在 `fms-module-service`，负责事务、业务校验、事实写入和状态聚合。
- 发起开票只提供对账单来源接口，后端不接收账单列表或对账明细列表。
- 发票行生成时批量查询 `fc_material.invoice_name`，缺失则阻断创建。
- 导出接口只做模板类型校验和未开放提示，不生成文件。

前端按现有对账模块组织：

- 新增开票记录列表页。
- 新增开票维护抽屉或详情组件。
- 只在对账单详情增加“发起开票”入口。
- 正式账单列表和详情不增加“发起开票”入口。
- 对账单详情明细表不增加开票勾选列。
- API 放在 `src/api/fms/reconciliation/invoice/index.ts`。
- 类型可扩展到 `src/types/reconciliation.d.ts`。

## 4. 后端接口设计

基础路径：`/fms/reconciliation-invoice`

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| GET | `/page` | 开票记录分页查询 | `fms:reconciliation-invoice:query` |
| GET | `/get?id=` | 开票详情，含发票行、关联明细、到票记录 | `fms:reconciliation-invoice:query` |
| POST | `/create-from-reconciliation` | 从对账单整单创建开票记录 | `fms:reconciliation-invoice:create` |
| PUT | `/update-lines` | 保存发票行展示信息和分摊金额 | `fms:reconciliation-invoice:update` |
| POST | `/ticket` | 登记到票 | `fms:reconciliation-invoice:ticket` |
| GET | `/export` | 预留导出接口，支持模板类型参数 | `fms:reconciliation-invoice:export` |

不提供正式账单创建接口。不提供按对账明细列表创建接口。

### 4.1 创建开票请求

从对账单整单创建：

```json
{
  "reconciliationBillNumber": "RECON-001",
  "invoiceOrgId": 1001,
  "remark": "从对账单整单发起"
}
```

后端处理：

1. 根据 `reconciliationBillNumber` 查询对账单主表。
2. 校验对账单状态可开票。
3. 查询该对账单下所有对账明细。
4. 用 `businessKey + billType + deriveSeq` 查询对应正式账单。
5. 排除已全额开票账单。
6. 对部分开票账单按剩余可开票金额参与本次开票。
7. 批量查询参与账单的 `materialId` 对应 `fc_material.invoice_name`。
8. 任一品名为空时阻断，并返回缺失物料清单。
9. 按 `品名 + 款号 + 采购单号 + 税率` 生成发票行。
10. 保存来源对账单主体和实际开票主体；`invoiceOrgId` 为空时默认使用对账单主体，传入时必须是有效我方主体。

### 4.2 保存发票行请求

```json
{
  "invoiceId": 1,
  "lines": [
    {
      "invoiceLineId": 11,
      "displayName": "针织布",
      "allocationAmountWithTax": 10.00,
      "remark": "展示调整"
    }
  ]
}
```

保存时必须校验所有发票行 `finalAmountWithTax` 合计等于开票记录 `invoiceAmountWithTax`。

### 4.3 到票请求

```json
{
  "invoiceId": 1,
  "ticketNo": "33002606290000123456",
  "attachmentUrl": "https://file.example.com/invoice.pdf",
  "attachmentName": "invoice.pdf",
  "attachmentType": "application/pdf",
  "remark": "到票登记",
  "lines": [
    {
      "invoiceLineId": 11,
      "ticketAmountWithTax": 60.00
    },
    {
      "invoiceLineId": 12,
      "ticketAmountWithTax": 40.00
    }
  ]
}
```

红冲场景允许负数到票金额；累计到票判断按同方向金额绝对值闭合。

提交时按 `lines` 写入到票行关联，整张发票到票金额等于所有行级金额合计。后续查询底层明细归属发票时，通过发票行关联明细与到票行关联组合展示。

### 4.4 导出接口

```http
GET /fms/reconciliation-invoice/export?invoiceId=1&templateType=MATERIAL_ACCESSORY
```

模板类型：

| templateType | 说明 |
| --- | --- |
| MATERIAL_ACCESSORY | 面辅料 |
| FULL_SELL | 全卖 |
| HALF_SELL | 半卖 |

本期只预留接口，不生成真实发票文件。调用时返回业务提示：

```text
开票导出模板暂未开放
```

## 5. 业务规则

### 5.1 发起开票

- 必须从对账单详情整单发起。
- 后端请求只接收 `reconciliationBillNumber`，不接收正式账单列表或对账明细列表。
- 开票主体默认等于对账单主体，允许传入任意有效我方主体作为实际开票主体。
- 来源主体和开票主体分别保存；金额回传仍按来源对账单、正式账单和对账明细归集。
- 正式账单列表和详情不提供发起开票入口。
- 对账单详情不提供明细勾选开票。
- 对账单必须处于已审批/已生效状态。
- 已取消、已作废、草稿、审批中、驳回的对账单不可发起。
- 对账单下必须存在已生成正式账单且未全额开票的数据。
- 已全额开票账单不可重复开票。
- 已部分开票账单按剩余金额参与开票。
- 本次开票金额不得超过剩余可开票金额。
- 正式账单身份使用 `businessKey + billType + deriveSeq` 精确定位。
- 红冲账单保留负数金额，不转正展示。
- 参与开票的物料必须存在 `fc_material.invoice_name`。

### 5.2 发票行生成

- 品名从 `fc_material.invoice_name` 获取。
- `invoice_name` 为空时阻断创建，不使用 `materialName` 兜底。
- 默认按 `invoiceName + ztStyleNo + purchaseNo + taxRate` 汇总。
- `purchaseNo` 优先取 `ztSkuPoNo`，为空取 `ztMaterialPoNo`。
- 款号为空时展示“未识别款号”。
- 采购单号为空时展示“未识别采购单”。
- 发票行展示名称默认等于品名。
- 发票行原始金额等于关联明细本次开票金额合计。
- 每条发票行必须保留关联正式账单明细。
- 混合税率不合并成同一行。

### 5.3 发票行分摊

- 分摊只改变导出和展示金额，不改变明细归属。
- 不移动发票行和账单明细的关联关系。
- 分摊金额允许为正或负。
- 分摊后发票行最终展示金额合计必须等于开票记录开票金额。
- 保存失败时不更新任何发票行。

### 5.4 到票

- 到票必须填写发票号、选择开票行、填写行级到票金额并上传附件。
- 普通正向开票到票金额必须大于 0。
- 红冲开票到票金额允许小于 0。
- 一张发票可覆盖多条开票行，同一开票行可由多张发票拆分覆盖。
- 每条开票行的累计到票金额绝对值不得超过该行最终展示金额绝对值。
- 到票记录金额等于本次所有到票行金额合计。
- 多次到票累计计算状态。
- 禁止累计到票金额绝对值超过开票金额绝对值。
- 累计到票金额为 0：`WAIT_TICKET`。
- 累计到票金额绝对值小于开票金额绝对值：`PARTIAL_TICKETED`。
- 累计到票金额绝对值达到开票金额绝对值：`INVOICED`。

### 5.5 导出开票

- 仅对已生成的开票记录开放导出按钮。
- 前端提供面辅料、全卖、半卖三个模板类型选择。
- 后端校验模板类型合法。
- 本期不生成文件，只返回未开放提示。
- 后续实现真实导出时，使用发票行中的 `invoice_name` 和 `display_name` 作为品名/展示名称来源。

### 5.6 状态回传

正式账单开票状态：

| 状态 | 规则 |
| --- | --- |
| NOT_INVOICED | 累计已开票金额为 0 |
| PARTIAL_INVOICED | 累计已开票金额绝对值大于 0 且小于账单对账金额绝对值 |
| INVOICED | 累计已开票金额绝对值达到账单对账金额绝对值 |

正式账单到票状态：

| 状态 | 规则 |
| --- | --- |
| NOT_TICKETED | 累计到票金额为 0 |
| PARTIAL_TICKETED | 累计到票金额绝对值大于 0 且小于账单已开票金额绝对值 |
| TICKETED | 累计到票金额绝对值达到账单已开票金额绝对值 |

对账单和对账明细金额从开票事实聚合回写，不作为唯一事实来源。

- 到票未填写发票号时阻断。
- 到票未选择开票行时阻断。
- 一张发票覆盖多条开票行时按行写入关联关系。
- 同一开票行多次到票时累计计算行级未到票金额。
- 正向到票累计状态计算。
- 红冲负数到票累计状态计算。
- 到票金额超额阻断。
- 到票后同步正式账单开票状态、到票状态和累计金额。
- 到票后同步对账单、对账明细已开票和已到票金额。
- 导出接口对三种模板类型返回未开放提示。
- 导出接口传非法模板类型时返回参数错误。

### 8.2 前端测试

- 正式账单列表不展示发起开票按钮。
- 正式账单详情不展示发起开票按钮。
- 对账单详情展示整单发起开票按钮。
- 对账单不可开票状态下按钮禁用。
- 对账单详情明细表不展示开票勾选列。
- 发起开票时请求包含 `reconciliationBillNumber`、可选 `invoiceOrgId` 和备注。
- 开票维护页支持修改实际开票主体。
- 开票记录列表查询参数组装。
- 发票行分摊金额合计校验。
- 到票弹窗发票号、开票行、行级金额和附件必填校验。
- 到票后发票行、到票记录和关联明细均展示发票号追溯信息。
- 导出按钮支持选择面辅料、全卖、半卖模板。
- 导出按钮调用预留接口并展示未开放提示。

### 8.3 验收场景

- 用户只能从对账单详情发起开票。
- 用户不能从正式账单列表或详情发起开票。
- 用户不能勾选对账单明细发起开票。
- 系统自动纳入整张对账单下所有可开票正式账单。
- 系统自动按商品管理品名生成发票行。
- 商品管理品名缺失时阻断开票。
- 开票记录默认使用对账单主体，并允许改选实际开票主体。
- 每条发票行可查看关联正式账单明细。
- 支持发票行金额分摊。
- 发起开票后记录状态为待到票。
- 到票时必须填写发票号、选择开票行、填写行级金额并上传附件。
- 同一发票可覆盖多条开票行，同一开票行可被多张发票拆分覆盖。
- 底层明细可追溯到对应发票号。
- 部分到票后状态为部分到票。
- 全额到票后状态为已开票。
- 到票后同步更新正式账单、对账单、对账明细金额和状态。
- 红冲账单以负数金额参与开票、到票和展示。
- 导出开票入口预留三种模板，当前提示未开放。

## 9. 默认假设

- 一期只覆盖库存来源 `MAP_INVENTORY`。
- 费用类来源后续单独设计。
- 发起开票按整张对账单处理，不支持用户选择部分明细。
- 开票主体可选全部有效我方主体，默认等于对账单主体。
- 已部分开票的正式账单按剩余可开票金额自动参与。
- 发票行品名必须来自 `fc_material.invoice_name`，为空时阻断。
- 红冲到票金额允许负数，和红冲开票金额同向。
- 到票按发票号和开票行登记，底层明细归属发票通过开票行关系推导。
- 导出功能一期只预留接口和模板枚举，不生成真实发票文件。
- 面辅料、全卖、半卖模板由用户手工选择，暂不做自动判定。
- 附件只归档 URL、名称、类型，不做 OCR 或验真。
- 不引入审批流。
