## 状态转换规则

| 当前状态 | 可转换到 | 触发条件 | 操作者 |
|----------|---------|---------|--------|
| `draft` | `ready` | 任务内容完善 | 创建者 |
| `draft` | `cancelled` | 不再需要 | 创建者/PM |
| `ready` | `assigned` | 分配执行者和排期 | PM |
| `ready` | `cancelled` | 不再需要 | PM |
| `assigned` | `in_progress` | 执行者确认开始 | 执行者 |
| `assigned` | `cancelled` | 不再需要 | PM |
| `in_progress` | `blocked` | 遇到无法继续的阻碍 | 执行者 |
| `in_progress` | `under_review` | 产出物完成，提交审核 | 执行者 |
| `blocked` | `in_progress` | 阻塞条件解除 | 执行者 |
| `blocked` | `cancelled` | 阻塞无法解决 | PM |
| `under_review` | `done` | 审核通过 | 审核者 |
| `under_review` | `revision` | 审核不通过，需修改 | 审核者 |
| `revision` | `under_review` | 修改完成，重新提交 | 执行者 |
| `done` | `archived` | 归档（完成N天后） | 系统/PM |
| `done` | `in_progress` | 重新打开（极少用） | PM |

## 状态使用建议

1. **DRAFT 不要停留太久**：如果任务有意义但信息不完整，标记为 READY 并注明待补充项
2. **BLOCKED 必须写清阻塞原因**：在任务文档中记录"阻塞原因"和"解除条件"
3. **REVISION vs BLOCKED 的区别**：REVISION 是质量不达标（内因），BLOCKED 是外部依赖（外因）
4. **CANCELLED 优于假 DONE**：如果一个任务不再需要，直接取消，不要标记为完成

## 任务性质与进度策略

任务状态只描述「这项任务处在哪个流程状态」，不描述「这次修改是否推进主交付」。复杂任务必须额外声明任务性质与进度策略，避免持续小修被误认为主里程碑完成。

### task_nature

| 值 | 含义 | 典型场景 |
|----|------|----------|
| `delivery` | 主交付任务 | 新功能、主阶段开发、端到端交付 |
| `integration_revision` | 持续集成修订 | 联调小修、字段补齐、测试数据修正、页面细节对齐 |
| `investigation` | 调研分析任务 | 缺口分析、根因分析、方案预研 |
| `review` | 审核任务 | 代码审查、架构审查、方案复核 |
| `test_data` | 测试数据任务 | 构造、修订、验证 SQL/Mock/基准数据 |

### progress_policy

| 值 | 含义 | 使用规则 |
|----|------|----------|
| `milestone_only` | 仅由里程碑推进 | 主任务默认值；只有验收标准或阶段 checklist 完成才更新进度 |
| `change_log_allowed` | 允许持续记录修订 | 小修和验证类任务可持续追加日志，但不自动改变主任务完成度 |

### 判定规则

1. 主任务默认 `task_nature: delivery` + `progress_policy: milestone_only`。
2. TL/asNormal 直接完成的小修默认记入「TL 直接修订记录」，不勾选主阶段 checklist。
3. 修订只有在明确满足某个验收标准、解除阻塞或通过独立验证后，才允许更新阶段状态。
4. 测试数据任务必须说明服务于哪个验证目标；仅生成脚本不等于主功能通过验证。
