# /frameworkClean — 框架重置

## 触发

- `/frameworkClean`、`重置框架`、`frameworkClean`

## 适用范围

**仅 asTeacher 模式可用**。若当前为 TL 模式，提示用户先执行 `/asTeacher`。

## 目的

按用户指定范围删除目标、任务、产物工件等内容，使框架恢复到干净状态，便于在新机器或新场景下重新开始使用。

---

## 执行流程

### Phase 1: 框架状态扫描

扫描并展示当前框架中有哪些可清理内容：

```
📊 框架内容扫描

【A.目标体系/目标总览.md】
  目标总数: 3 个
    - GOAL-001: 任务模块测试
    - GOAL-999: 日常问题排查
    - GOAL-00N: {目标名}（模板）

【A.目标体系/GOAL-XXX/】
  Goal 支撑文件: 2 类
    ├── 工作记录.md       （目标工作记录）
    └── 产物/01/          （任务 01 的 N 个产物文件）

【任务系统/】
  进行中任务: 0 个
  任务归档: 0 个
```

### Phase 2: 选择清理范围

向用户提供清理选项（可多选）：

```
请选择要清理的内容：

1. 🎯 清空目标文件
   操作: 将 A.目标体系/目标总览.md 重置为空白模板
   影响: GOAL-001, GOAL-999（GOAL-00N 模板保留）
   ⚠️ 不可逆

2. 📦 清理产物工件
   子选项:
   2a. 删除所有 GOAL 工作记录 (A.目标体系/GOAL-XXX/工作记录.md)
   2b. 删除所有任务产物 (A.目标体系/GOAL-XXX/产物/{任务序号}/)
   2c. 删除全部 GOAL 工作记录和产物内容
   ⚠️ 不可逆，删除后无法恢复

3. 📋 清理任务系统
   子选项:
   3a. 清空进行中任务 (任务系统/进行中/*.md)
   3b. 清空任务归档 (任务系统/任务归档/*.md)
   3c. 清空全部任务
   ⚠️ 不可逆

4. 🔄 全部重置（以上所有）
```

### Phase 3: 逐项确认（危险操作二次确认）

对用户选择的每个清理项，展示即将删除/清空的**具体文件列表**：

```
⚠️ 即将删除以下内容：

【清空目标总览】
  → 删除 GOAL-001: "任务模块测试" 及其 4 行内容
  → 删除 GOAL-999: "日常问题排查" 及其 6 行内容
  → 保留模板 GOAL-00N

【删除产物工件】
  → 删除 A.目标体系/GOAL-999/工作记录.md
  → 删除 A.目标体系/GOAL-001/产物/01/ 及其中所有文件
  → 保留各 GOAL 目录、历史分点.md 和关联任务/

【清空任务】
  → （无进行中任务）
  → 保留 任务系统/任务模板/ 目录

确认执行以上清理操作？此操作不可逆！[是/否]
```

### Phase 4: 执行清理

确认后，按顺序执行：

1. **清空目标总览**：将 `A.目标体系/目标总览.md` 重置为只含模板框架的内容
2. **删除产物工件**：删除用户指定的 GOAL 工作记录或任务产物目录
3. **清空任务**：删除用户指定目录下的任务文件
4. 保留 Goal 目录、目标历史、关联任务和模板文件等框架结构内容

### Phase 5: 清理报告

```
✅ 框架清理完成

【已清理】
  ✓ 目标: 删除 2 个（保留模板框架）
  ✓ 产物工件: 删除 1 个工作记录和 1 个任务产物目录（GOAL-999/工作记录.md, GOAL-001/产物/01）
  ✓ 任务: 无进行中任务

【保留】
  - A.目标体系/目标总览.md（模板框架）
  - A.目标体系/GOAL-XXX/（Goal 目录结构）
  - A.目标体系/GOAL-XXX/历史分点.md 与关联任务/
  - 任务系统/任务模板/（4 个模板文件）
  - 配置与元数据/项目注册表.yaml（不在此命令清理范围）

框架已重置。你可以：
  → 执行 /frameworkInit 重新配置项目路径
  → 或直接开始新工作
```

## 行为约束

### 必须做
- **危险操作确认**：清理范围选择 + 具体文件预览，两次确认后才执行
- 展示每个目录/文件的具体名称和内容摘要
- 保留框架结构文件（模板、索引、配置）
- 清理后给出完整的清理报告

### 禁止做
- 不清理 `配置与元数据/`（项目注册表等配置不在此命令范围）
- 不清理 `角色体系/`、`知识沉淀/`、`导航系统/`、`_封存/`
- 不清理 `.obsidian/templates/`
- 不删除框架自身的 `CLAUDE.md`、`AGENTS.md`
- 不在 TL 模式下响应此命令
- 不跳过危险操作确认步骤

### 错误处理

| 场景 | 处理 |
|------|------|
| 框架已为干净状态（无目标/无产物/无任务） | 提示"框架已处于干净状态，无需清理" |
| 用户中途取消 | 不执行任何清理操作，报告"已取消" |
| 文件删除失败（权限等） | 逐项报告失败原因，继续处理其余项 |
| 目标文件已是模板框架 | 跳过，标记为"无需清理" |

## 清理范围边界（硬限制）

| ✅ 可清理 | ❌ 不可清理 |
|----------|------------|
| `A.目标体系/目标总览.md` 中的非模板内容 | `A.目标体系/目标总览.md` 的模板框架行 |
| `A.目标体系/GOAL-XXX/工作记录.md` | `A.目标体系/GOAL-XXX/` 目录本身 |
| `A.目标体系/GOAL-XXX/产物/{任务序号}/` | `A.目标体系/GOAL-XXX/历史分点.md` 与 `关联任务/` |
| `任务系统/进行中/*.md` | `任务系统/任务模板/*.md` |
| `任务系统/任务归档/*.md` | `任务系统/AGENT.md` |
| — | `配置与元数据/项目注册表.yaml` |
| — | `角色体系/` 全部文件 |
| — | `知识沉淀/` 全部文件 |

---

## 与 frameworkInit 的关系

- `frameworkInit` 在流程中会询问是否先执行 `/frameworkClean`
- 用户可单独执行 `/frameworkClean` 清理后，再手动执行 `/frameworkInit` 初始化
- `frameworkClean` 负责"删"，`frameworkInit` 负责"建"
