# /frameworkRefresh — 框架刷新（Goal 同步 + 历史迁移 + 序号续接）

## 触发

- `/frameworkRefresh`、`框架刷新`、`刷新框架`、`同步目标`

## 适用范围

**仅 asTeacher 模式可用**。若当前为 TL 模式，提示用户先执行 `/asTeacher`。

## 目的

以 `目标总览.md` 为活跃 Goal 的唯一真相来源，执行四项维护操作：

1. **Goal 目录同步**：确保每个活跃 Goal 都有对应目录，且目录名与目标总览中的 Goal 标题一致
2. **已完成分点迁移**：将 `目标总览.md` 中已完成的分点 `[x]` 归档到各 Goal 的 `历史分点.md`
3. **下一子目标序号维护**：综合当前子目标、历史分点和已有序号游标，保留下次可安全使用的数字序号
4. **维护排序**：通过目录名与标题的一致性，实现 Goal 在文件系统中的自然排序

---

## 执行流程

### Phase 1: 解析目标总览

1. 读取 `A.目标体系/目标总览.md`
2. 解析所有活跃 Goal 条目（`## GOAL-NNN: 系统-模块`）
3. 跳过模板条目 `GOAL-00N`
4. 对每个 Goal 提取：
   - `goal_id`: GOAL-NNN
   - `full_title`: 标题行 `系统-模块` 部分
   - `expected_dir_name`: `GOAL-NNN-{系统}-{模块}`
   - `completed_subpoints`: 所有 `[x]` 标记的分点（递归收集，含子分点）
   - `declared_next_subgoal_seq`: `- **下一子目标序号**：N` 中已声明的正整数；字段缺失或格式非法时为空
   - `current_top_level_seqs`: 当前子目标中所有顶层数字序号（不把嵌套分点序号计入）
   - `content_block`: 该 Goal 的完整文本块（从 `## GOAL-NNN` 到下一个 `## ` 之前）

### Phase 2: 目录同步

对每个活跃 Goal：

1. **目录不存在** → 创建 `A.目标体系/GOAL-NNN-{系统}-{模块}/`，含：
   - `历史分点.md`（写入模板头部）
   - `工作记录.md`（写入模板头部）
   - `关联任务/`（空目录）
   - `产物/`（空目录）

2. **目录名不一致** → 重命名为 `GOAL-NNN-{系统}-{模块}`：
   - 扫描 `A.目标体系/` 下匹配 `GOAL-NNN-*` 的现有目录
   - 若名称不同，重命名为期望名称
   - 保留目录内所有已有文件

3. **目录已存在且名称正确** → 跳过

报告同步结果：

```
📁 目录同步
├── GOAL-101-FMS-账单及对账单: ✅ 已创建
├── GOAL-1000-FMS-日常零散问题排查: ✅ 已创建
└── GOAL-999-日常问题排查 → GOAL-999-lasen-日常零散问题排查: ✅ 已重命名
```

### Phase 3: 历史分点迁移

对每个有已完成分点的 Goal：

1. 收集该 Goal 下所有 `[x]` 分点（含嵌套子分点，保留完整层级）
2. 生成历史条目（带日期分组）：
   ```markdown
   ## YYYY-MM-DD

   - [x] 1. {分点描述}
       - [x] 1.1 {子分点}
   ```
3. **前置插入**到 `GOAL-NNN-{xxx}/历史分点.md`（更新日期分组已有则合并，无则新建）
4. 从 `目标总览.md` 的对应 Goal 块中删除已迁移的分点行
5. 更新该 Goal 的 `- **最近完成**：` 字段为 `YYYY-MM-DD — {最近完成的分点简述}`
6. 读取迁移后的 `历史分点.md`，提取历次顶层数字序号，与当前子目标序号共同计算下一子目标序号

**规则**：
- 仅迁移顶层 `[x]` 分点和它的所有子分点（不管子分点是否完成——因为顶层已完成意味着整组完成）
- 倒序排列（最新完成的在最上面）
- 保留分点关联的任务引用 `→ [[TASK-xxx]]`
- 下一子目标序号按以下公式单调递增，禁止因当前列表清空而回退：
  ```text
  next = max(
      已声明的下一子目标序号（如有）,
      当前与历史中最大顶层数字序号 + 1,
      1
  )
  ```
- 只统计顶层数字子目标；嵌套分点编号、字母挂起项、任务编号和 Goal 编号均不参与计算

### Phase 4: 写入目标总览

将清理后的内容写回 `A.目标体系/目标总览.md`：

1. 保留文件头部注释块
2. 保留所有未完成分点的 Goal 块（含已清理的）
3. 在 `最近完成` 与 `当前子目标` 之间写入或更新 `- **下一子目标序号**：N`
4. 若某 Goal 所有当前子目标均已完成 → 保留 Goal 块、空的 `当前子目标` 字段和下一子目标序号，将其视为长期 Goal 的正常“待续”状态
5. `最近完成` 字段更新为最新迁移日期

长期 Goal 不因当前子目标清空而自动建议归档。只有人类明确说明 Goal 已终止、已达成且不再续接，或目标本身带有明确的关闭状态时，才提示评估迁入 `历史目标/`。

示例：GOAL-002 的历史最高顶层子目标为 7，本轮迁移后当前子目标为空，则保留：

```markdown
- **最近完成**：2026-07-24 — 7. {最近完成内容}
- **下一子目标序号**：8
- **当前子目标**：
```

### Phase 5: 汇总报告

```
🔄 框架刷新完成

📁 目录同步: {N} 个变更
   ├── 新建: {list}
   └── 重命名: {list}

📋 历史迁移: {M} 个 Goal 有已完成分点
   ├── GOAL-999: 迁移 1 组分点 → 历史分点.md
   └── ...

📝 目标总览: 已更新（删除了 {K} 行已完成分点）

🔢 序号续接: {S} 个 Goal 已核对
   ├── GOAL-002: 当前子目标为空，下次从 8 开始
   └── GOAL-XXX: 下一子目标序号保持 N

💡 待续:
   - GOAL-002 当前无未完成子目标，长期 Goal 已保留，可从 P8 继续
```

## 行为约束

### 必须做
- 以 `目标总览.md` 为唯一真相来源
- 目录重命名前确认目标路径不冲突
- 迁移分点时保留原始格式和关联引用
- 倒序排列历史分点
- 为每个活跃 Goal 保留合法且不回退的 `下一子目标序号`
- 当前子目标清空时保留长期 Goal，不默认建议归档
- 操作完成后报告完整变更清单

### 禁止做
- 不修改未完成的分点
- 不删除 Goal 目录中的已有文件
- 不修改 `关联任务/` 中的任务文件内容
- 不清理 `历史分点.md` 中的已有内容（仅追加）
- 不在 TL 模式下响应此命令

### 边界处理

| 场景 | 处理 |
|------|------|
| 目录重命名冲突（目标名已存在） | 报错，提示用户手动处理 |
| 某 Goal 无已完成分点 | 跳过该 Goal 的迁移，仅同步目录 |
| Goal 标题不含系统-模块（如旧格式） | 使用标题原文作为目录后缀 |
| 历史分点.md 不存在 | 先创建模板头部再追加 |
| `下一子目标序号` 缺失 | 从当前子目标与历史分点的最大顶层数字序号推导；均无数字序号时从 1 开始 |
| `下一子目标序号` 小于已使用最大序号 | 自动提升为最大已使用序号 + 1，并在报告中说明修正 |
| 当前子目标为空 | 保留 Goal 和序号游标，报告为“待续”，不自动归档 |
