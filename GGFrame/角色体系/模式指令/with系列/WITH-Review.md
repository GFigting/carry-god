# /withReview — 派发计划审核

## 触发

- `/withReview` — 在 TL 模式下启用计划审核派发约束

## 作用

强制 TL 将实施计划的审核工作**派发给独立 subAgent**（代码审核员），利用独立视角审查计划的完整性、可行性、边界遗漏和风险评估，辅助用户做出更充分的确认决策。

## 行为约束

### TL 必须做

1. 在 `/withPlan` 产出实施计划后，**必须**派发 subAgent 审核该计划
2. 派发角色：代码审核员（ROLE-QA-002）
3. 构建 subAgent prompt（按下方模板）
4. 在任务文件中记录派发决策
5. 回收后将审核报告与计划一并呈现给用户，辅助用户确认决策

### subAgent 必须做

1. 读取实施计划（`ART-TL-...-实施计划.md`）
2. 从以下维度审查计划：
   - **完整性**：是否覆盖了需求的所有功能点，是否有遗漏的功能或场景
   - **可行性**：技术方案是否可行，是否有明显漏洞或不合理假设
   - **边界遗漏**：异常流程、边界条件、并发场景、空值处理是否被考虑
   - **风险评估**：识别的风险是否全面，缓解措施是否充分
   - **架构一致性**：方案是否与现有架构、编码规范、技术栈约束一致
3. 生成审核报告，写入 `A.目标体系/GOAL-XXX/产物/{任务序号}/`
4. 在产物中记录关键决策（每个审核维度的判断理由）
5. 返回精简摘要

### subAgent 禁止做

- **禁止**修改实施计划原文
- **禁止**修改任何项目代码
- **禁止**编写代码或测试脚本
- **禁止**执行任何命令或数据库操作

## subAgent prompt 模板

```markdown
## 任务
审核当前任务的实施计划，从完整性、可行性、边界遗漏、风险评估、架构一致性五个维度进行独立审查。

## 角色
代码审核员（ROLE-QA-002）— 技能映射见 配置与元数据/角色技能映射表.yaml

## 输入
- 实施计划：A.目标体系/GOAL-XXX/产物/{任务序号}/[GOAL{NNN}]-[...]-ART-TL-实施计划.md
- 相关需求/目标：{TL 指定的目标文件或需求文档路径}

## 输出
- 写入路径：A.目标体系/GOAL-XXX/产物/{任务序号}/[GOAL{NNN}]-[{任务序号}-{子序号}-{产物序号}]-ART-CR-计划审核报告.md
- 格式要求：
  - 审核结论（Approve / Request Changes / Comment）
  - 按维度组织的审核意见（完整性 / 可行性 / 边界遗漏 / 风险评估 / 架构一致性）
  - 每个问题描述包含：问题位置（计划中第几节）、问题描述、影响说明、改进建议
  - 总体评价与建议

## 不可修改
- 项目代码（.java/.vue/.ts 等任何源码）
- 实施计划原文
- 任务文件

## 输出交付方式 ⚠️ 强制规则
你必须将所有产出物直接写入目标文件路径。严格禁止将大段代码或文档内容作为回复文本返回。完成后只返回精简摘要。

## 关键决策记录 ⚠️ 强制规则
在产物工件中记录关键决策（每个审核维度的判断理由、拒绝的替代判断）、偏离说明、产出清单。
```

## 与其他指令的交互

- **强依赖 `/withPlan`**：必须有实施计划作为输入。若用户仅启用 `/withReview` 而未启用 `/withPlan`，TL 应提示"`/withReview` 需要实施计划作为输入，建议先启用 `/withPlan`"
- **+ `/withTest`**：计划审核 → 用户确认 → TL 实施 → 测试计划
- **典型流水线**：`/withPlan /withReview /withTest /withMock` → 计划落盘 → 独立审核 → 用户确认 → 实施 → 测试计划 → 测试数据

## 与 `/withReview` 未启用时的区别

| 场景 | 未启用 `/withReview` | 启用 `/withReview` |
|------|---------------------|-------------------|
| `/withPlan` 产出计划后 | 用户直接审核 | 先派发 subAgent 独立审核 → 审核报告 + 计划一并呈现 |
| 用户确认决策 | 仅基于计划和 TL 口头说明 | 多一份独立视角的审核报告参考 |
| 计划质量问题 | 用户自行发现 | subAgent 前置发现，减少用户认知负担 |
