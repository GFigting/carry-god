# /withQuery — 口语化查询条件生成

## 触发

- `/withQuery {口语查询描述}` — 将用户自然语言描述的查询需求转换为页面可用的 JSON 查询条件
- `/withQuery` — 无参数时，先引导用户描述查询需求

## 作用

用户用口语描述"想查什么"，AI 自动：
1. 定位目标页面和查询 Schema
2. 将口语中的时间/实体/分类等概念映射为查询参数
3. 对模糊语义（如"对账多单的供应商"）执行 DB 探查获取具体值
4. 输出可直接粘贴到页面 `QueryParamClipboard` 导入的 JSON

## 行为约束

### TL 必须做

1. **解析用户输入** → 识别：目标页面（如"ARAP列表"）、时间范围（如"一个月内"）、实体条件（如"供应商"）、聚合语义（如"多单"）
2. **定位 Schema** → 读 `通用能力层/查询Schema注册表/{项目}/` 找到匹配的 Schema 文件。匹配方式：page.title 关键词、semantic_index.words 命中
3. **直接映射** → 口语中能直接确定值的部分（如"一个月内" → dateRange 相对日期），立即填入 JSON
4. **字典翻译** → 口语中的业务术语（如"应收"、"采购入库"）通过 `dict_values` 翻译为编码值
5. **DB 探查（按需）** → 口语中的模糊语义无法直接映射时：
   - 连接 MCP MySQL 数据库
   - 优先使用 Schema 中 `db_probe_hints` 的 SQL 模板
   - 无模板时自行编写 SELECT 查询（**仅 SELECT，禁止 DML/DDL**）
   - 将探查结果映射为具体参数值
6. **组装 JSON** → 按页面 `queryParams` 结构输出 JSON，包含 page doc：注明目标页面、参数说明、使用方式
7. **输出到剪贴板** → 结果 JSON 直接写入剪贴板，用户可在页面上粘贴导入
8. **若涉及多个探查询步骤** → 先口头向用户展示探查路径，确认后再执行

### TL 禁止做

- **禁止**修改任何项目代码
- **禁止**执行 INSERT/UPDATE/DELETE/DROP 等非查询 SQL
- **禁止**在无 Schema 文件时猜测参数 key（应先建议创建 Schema）
- **禁止**输出不完整的 JSON（如缺时间范围、缺关键筛选条件）

### 异常处理

| 场景 | 处理 |
|------|------|
| 找不到匹配的 Schema 文件 | 提示用户该页面尚未注册，建议先用 `init-architect` 扫描生成 |
| Schema 中无对应 db_probe_hints | TL 自行分析表结构后编写探查 SQL |
| DB 连接不可用 | 跳过探查步骤，输出可直接映射的部分，标注"需 DB 探查（数据库不可用）" |
| 口语歧义（如"单号"可匹配多个字段） | 列出候选字段让用户选择，或全部填入让用户自行删减 |
| 探查结果为空 | 告知用户该条件下无数据，建议放宽条件 |

```

         │
         ▼

         │
```

## 输出格式

### 成功时

```markdown
## 查询条件 JSON

**目标页面**：ARAP 统一应收付列表 (`/reconciliation/arap`)
**使用方式**：复制 JSON → 页面上点击粘贴按钮 → 自动填充查询条件

\`\`\`json
{
  "customerType": "SUPPLIER",
  "dateRange": ["2026-05-25 00:00:00", "2026-06-24 23:59:59"],
  "arapBizTypeList": ["AP", "AR"]
}
\`\`\`

### 条件说明
- **对手方类型**：供应商
- **日期范围**：最近一个月 (2026-05-25 ~ 2026-06-24)
- **应收付类型**：应收 + 应付
- **DB探查结果**：一个月内有多笔不同操作类型库存单的供应商共 12 个。
  由于 customerId 为单值选择，无法批量填入，建议先按以上条件查询，再在结果中按供应商名称筛选。

### 可选：进一步缩小范围
如需针对特定供应商查询，可修改 customerId 为以下值之一：
| supplier_id | 供应商名称 | 单据类型数 |
|------------|-----------|-----------|
| 101 | XX供应商 | 3 |
| 203 | YY公司 | 2 |
...
```

### 部分成功时（如 DB 不可用）

标注哪些条件是确定的、哪些需要 DB 验证：

```json
{
  "customerType": "SUPPLIER",
  "dateRange": ["2026-05-25 00:00:00", "2026-06-24 23:59:59"],
  "_db_probe_pending": "需查'一个月内多单供应商' → 连接DB后补充 customerId 或 billTypeList"
}
```

## 与 QueryParamClipboard 的协作

- `/withQuery` 输出的 JSON 格式与页面 `queryParams` 结构一致
- 用户复制 JSON 后，在页面上点击 QueryParamClipboard 的粘贴按钮即可导入
- 导入时自动过滤 `modelValue` 中不存在的 key（安全机制）
- `_*` 开头的注释性字段会被 QueryParamClipboard 自动忽略（不在 modelValue 中）

## 与其他指令的交互

- **独立使用**：`/withQuery` 可独立触发，无需其他 with 指令配合
- **+ `/withGrill`**：口语歧义时可叠加 `/withGrill` 生成澄清问题
- **+ `/withMock`**：测试数据 JSON + 查询条件 JSON 成对输出，测试人员可直接操作页面验证
- **+ `/withTest`**：测试计划的场景矩阵中引用 `/withQuery` 生成的 JSON 作为"页面操作步骤"
