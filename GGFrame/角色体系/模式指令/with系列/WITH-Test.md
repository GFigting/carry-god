# /withTest — 派发测试计划生成

## 触发

- `/withTest` — 在 TL 模式下启用测试计划派发约束

## 作用

强制 TL 将测试计划工作**派发给独立 subAgent**（而非 TL 自己写），利用独立视角发现 TL 可能遗漏的测试场景。

## 行为约束

### TL 必须做

1. 在开发计划确认后（或代码改动完成后），**必须**派发 subAgent 生成测试计划
2. 派发角色：测试工程师（ROLE-QA-001）
3. 构建 subAgent prompt（按下方模板）
4. 在任务文件中记录派发决策
5. 回收后审查测试计划的覆盖度和合理性

### subAgent 必须做

1. 读取开发计划（`ART-TL-...-实施计划.md`）或实际代码改动
2. 分析测试范围、识别测试场景（正常/异常/边界/并发）
3. **若任务涉及列表页功能**：读 `通用能力层/查询Schema注册表/` 中对应页面的 Schema 文件，为每个需要在页面上验证的测试场景生成配套的 JSON 查询条件（格式与该页面 `queryParams` 一致）
4. 生成测试计划文档，写入 `A.目标体系/GOAL-XXX/产物/{任务序号}/`
5. 在产物中记录关键决策（为什么选择这些测试策略）
6. 返回精简摘要

### subAgent 禁止做

- **禁止**修改任何项目代码
- **禁止**编写测试代码/测试脚本
- **禁止**执行任何测试
- **禁止**修改 DDL 或数据库

## subAgent prompt 模板

```markdown
## 任务
为当前任务的代码改动生成测试计划文档。

## 角色
测试工程师（ROLE-QA-001）— 技能映射见 配置与元数据/角色技能映射表.yaml

## 输入
- 开发计划：A.目标体系/GOAL-XXX/产物/{任务序号}/[GOAL{NNN}]-[...]-ART-TL-实施计划.md（如有）
- 代码改动：{TL 指定改动的文件路径列表}
- 相关业务文档：{如有}

## 输出
- 写入路径：A.目标体系/GOAL-XXX/产物/{任务序号}/[GOAL{NNN}]-[{任务序号}-{子序号}-{产物序号}]-ART-QA-测试计划.md
- 格式要求：
  - 测试范围（哪些模块/接口/页面）
  - 测试场景矩阵（正常流程 / 异常流程 / 边界条件 / 并发场景）
  - 每个场景的输入、预期输出、优先级（P0/P1/P2）
  - 若涉及列表页验证：每个场景附带 `query_params_json` 字段，值为可粘贴到页面 QueryParamClipboard 导入的 JSON 查询条件
  - 不阻塞的已知限制

## 不可修改
- 项目代码（.java/.vue/.ts 等任何源码）
- 测试代码
- DDL 脚本
- 数据库

## 输出交付方式 ⚠️ 强制规则
你必须将所有产出物直接写入目标文件路径。严格禁止将大段代码或文档内容作为回复文本返回。完成后只返回精简摘要。

## 关键决策记录 ⚠️ 强制规则
在产物工件中记录关键决策（选择方案、理由、拒绝的替代方案）、偏离说明、产出清单。
```

## 产物

| 文件 | 路径 | 状态 |
|------|------|------|
| 测试计划 | `A.目标体系/GOAL-XXX/产物/{任务序号}/[GOAL{NNN}]-[{任务序号}-{子序号}-{产物序号}]-ART-QA-测试计划.md` | `in_review` |

## 与其他指令的交互

- **依赖 `/withPlan`**：若有 `/withPlan`，subAgent 以开发计划为主要输入；若无，以实际代码改动为输入
- **+ `/withReview`**：若启用了 `/withReview`，测试计划可参考审核报告中的风险点和边界遗漏建议，增强测试覆盖
- **被 `/withMock` 依赖**：`/withMock` 的 subAgent 以此测试计划为主要输入
- **+ `/withMock`**：测试计划 → 测试数据生成（推荐组合）
- **+ `/withQuery`**：测试场景中的 `query_params_json` 可通过 `/withQuery` 指令生成；若叠加 `/withQuery`，subAgent 在生成测试计划时同步为每个页面验证场景附带 JSON 查询条件
