# /withGrill — 目标澄清（grill 门禁）

## 触发

- `/withGrill` — 显式激活，对当前 Goal 中标记 `grill` 的分点生成澄清问题
- 隐式触发：TL 读取目标总览时，检测到分点含 `grill` 关键字 → 口头建议启用 `/withGrill`

## 适用范围

**仅 TL 模式可用**。若当前为 Teacher 模式，提示用户先执行 `/asTL`。

## 目的

在目标尚未完全明确时，**人定规则维度，AI 按维度生成简洁追问**，帮人快速理清目标边界。处于流程最上游——目标澄清 → 计划 (`/withPlan`) → 审核 (`/withReview`) → 执行。

## 核心原则

- **人定规则，AI 提问**：规则维度硬编码于此文件中，AI 遍历维度生成问题
- **独立文件，不污染目标总览**：问题写入独立 grill 明细文件，不直接修改 `目标总览.md`
- **人答疑，AI 归集**：人在 grill 文件中答疑后，Agent 按结构化格式归集回目标总览
- **门禁最高**：在所有 grill 问题变为陈述句之前，TL 有权拒绝推进到 `/withPlan`

## 执行流程

### Phase 1: 解析 grill 分点

1. 读取 `A.目标体系/目标总览.md`
2. 定位用户指定的 Goal（或当前活跃 Goal）
3. 扫描该 Goal 的 `当前分点` 和 `挂起分点`，找出所有含 `grill` 关键字的顶层分点

### Phase 2: 生成澄清问题

对每个 grill 分点，从以下两个视角各生成问题：

#### 视角一：业务用户视角

关注功能对使用者而言"有没有用、好不好用"：

| 维度 | 关注点 | 问题示例 |
|------|--------|---------|
| **业务价值** | 解决什么业务痛点？不做会怎样？ | "这个功能解决谁的什么问题？如果没有这个功能，目前是怎么处理的？" |
| **操作清晰度** | 用户操作路径是否直观？学习成本？ | "用户从哪进来、点哪、看到什么、做完走哪？最常用的操作路径是什么？" |
| **功能组合** | 可以和什么已有功能联动产生更大价值？ | "这个功能完成后，和现有的哪个功能搭配能发挥 1+1>2 的效果？" |

#### 视角二：系统设计视角

关注技术实现和架构影响：

| 维度 | 关注点 | 问题示例 |
|------|--------|---------|
| **页面/组件** | 涉及哪些页面？新增还是修改？组件树结构？ | "需要几个页面？是新增还是修改已有页面？" |
| **数据流** | 数据从哪来？需要哪些接口/表？关键字段？ | "数据来源是什么？需要新接口还是复用已有接口？" |
| **用户与权限** | 谁用？什么角色？权限边界？核心操作路径？ | "哪些角色可以使用？是否有权限控制？" |
| **边界与异常** | 空状态？错误处理？数据上限？极端值？ | "数据为空时如何展示？单次操作有上限吗？" |
| **影响范围** | 改动会影响哪些已有功能？联动模块？ | "这个改动会影响哪些已有页面或接口？" |

**生成规则**：
- 每个问题以 `- [ ] {简洁问题}？` 格式写入
- 每个视角至少覆盖 2 个维度（维度明显不适用的除外）
- 问题必须针对目标具体领域，不能是泛泛的空话
- 对关键问题可附加建议方向：`→ 建议：{方向}`（写在问题行内）

### Phase 3: 创建 grill 明细文件

将生成的问题写入独立的 grill 明细文件，**不修改目标总览**。

**文件路径**：`A.目标体系/GOAL-XXX/产物/grill/{分点序号}-grill明细.md`

**文件格式**：

```markdown
---
goal: GOAL-XXX
point: "{分点序号}. {分点描述}"
status: pending_answers
created: YYYY-MM-DD
---

# Grill 明细 — GOAL-XXX 分点 {序号}：{描述}

> 请逐一回答以下问题：将 `[ ]` 改为 `[x]`，问句改为陈述句。
> 暂时无法确定的，标记为 `[待定]` 并说明原因。
> 全部回答完成后，Agent 将按结构化格式归集回目标总览。

## 业务用户视角

- [ ] {问题1}？
- [ ] {问题2}？

## 系统设计视角

- [ ] {问题3}？
- [ ] {问题4}？
→ 建议：{方向}

## 答疑备注

<!-- 人在此区域自由记录答疑过程中的补充说明 -->
```

### Phase 4: 口头提示

```
🔍 grill 已就绪 — GOAL-XXX 分点 {序号} "{描述}"

grill 明细文件已创建：A.目标体系/GOAL-XXX/产物/grill/{序号}-grill明细.md

已从业务用户视角和系统设计视角生成 {N} 个澄清问题，请逐一回答（将 `[ ]` 改为 `[x]`，问题改为陈述）。

全部回答完成后，Agent 将按结构化格式归集回目标总览，门禁自动通过。
```

### Phase 5: 归集回目标总览

当用户表示答疑完成（或 grill 明细文件中所有问题均已转为陈述/待定），Agent 执行归集：

1. 读取 grill 明细文件中的答疑内容
2. 将答疑内容综合为结构化描述，写入 `目标总览.md` 对应分点下

**归集格式**（参考 GOAL-002 风格，非硬模板，Agent 根据领域灵活选择适用维度）：

```markdown
- [ ] {序号}. {一句话效果}
    - 目标：{核心要达成什么}
    - 形式：{具体呈现方式、操作路径}
    - 参考：{可参考的已有实现或模式}
    - 调研结论：{需要调研确认的事项及结论}
    - 材料：{依赖的外部文档或数据}
    - 待定：{标记为待定的遗留问题}
```

**归集规则**：
- 维度按需选取，不强制全部出现
- 不包含工时估算
- 归集完成后，将分点中的 `grill` 关键字移除（门禁解除）
- grill 明细文件保留作为澄清记录，不删除

## 门禁检查协议

### 触发时机

TL 执行 `/withPlan` 之前，或 TL 准备对 grill 分点进行方案设计时。

### 检查逻辑

```
对每个含 "grill" 关键字的顶层分点：
  ├── 对应 grill 明细文件不存在 → ❌ 门禁未过：「分点 X 已标记 grill 但尚未生成澄清问题，请先执行 /withGrill」
  ├── grill 明细文件中仍存在以 ？ 结尾的未回答问句 → ❌ 门禁未过：「以下问题尚未回答：{列出}」
  └── grill 明细文件中所有问句已转为陈述/待定，且已归集回目标总览 → ✅ 门禁通过
```

### 不通过时的输出

```
🚫 grill 门禁未通过 — GOAL-XXX 分点 {序号} "{描述}"

以下问题尚未回答（位于 A.目标体系/GOAL-XXX/产物/grill/{序号}-grill明细.md）：
  - [ ] {未回答的问题}？
  - [ ] {未回答的问题}？

请先回答所有 grill 问题，或明确表示「不再需要 grill」以跳过门禁。
```

### 用户跳过

用户明确说"不需要 grill 了"/"跳过 grill"/"移除 grill"时，TL 将分点中的 `grill` 关键字移除，门禁解除。grill 明细文件如已创建则保留为半成品记录。

## 行为约束

### 必须做

- 问题简洁明了，一行一问，以 `？` 结尾
- 每个 grill 分点从两个视角各至少覆盖 2 个维度（维度明显不适用的除外）
- 问题写入独立 grill 明细文件，不直接修改 `目标总览.md`
- 针对目标业务领域发问，拒绝泛泛空话
- 门禁检查在 `/withPlan` 前强制执行
- 不通过时明确指出未回答的问题及其所在文件
- 答疑完成后按结构化格式归集回目标总览
- 在建议方向中提供 AI 的经验判断，帮人做更全面决策

### 禁止做

- 不替人回答问题（不自动将问句改为陈述）
- 不跳过门禁（除非用户明确要求）
- 不在 Teacher 模式下响应此指令
- 不修改 grill 分点以外的内容
- 不在答疑未完成时将 grill 问题写入目标总览

### 边界处理

| 场景 | 处理 |
|------|------|
| Goal 无 grill 分点 | 提示用户：当前 Goal 没有标记 grill 的分点，无需澄清 |
| 用户已回答部分问题 | 门禁检查时只列出尚未回答的问句 |
| 用户追加新问题 | 允许，人可以在 grill 明细文件中自行添加更多问题 |
| 分点 grill 拼写变体 | `grill`、`grill-me`、`grillMe` 均识别为 grill 标记 |
| 用户对同一分点重复执行 `/withGrill` | 检测已有 grill 明细文件 → 询问是覆盖还是追加新问题 |
| grill 明细文件目录不存在 | 自动创建 `A.目标体系/GOAL-XXX/产物/grill/` 目录 |

## 与其他 with 指令的交互

- **+ `/withPlan`**：grill 门禁在 `/withPlan` 之前检查，门禁未通过时拒绝执行 `/withPlan`
- **+ `/withReview`、`/withTest`、`/withMock`**：这些指令在 `/withPlan` 之后执行，门禁不直接阻断
- **+ `/withFinish`**：不受 grill 门禁影响

## 门禁等级

grill 的优先级在 with 系列中最高。流程顺序为：

```
/withGrill（澄清） → /withPlan（方案） → /withReview（审核） → 执行 → /withFinish（归一化）
    ↑ 门禁检查点：grill 明细文件中无未回答问句 + 已归集回目标总览
```
