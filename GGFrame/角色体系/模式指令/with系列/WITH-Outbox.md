# /withOutbox — 需求导出（框架→外部）

## 触发

- `/withOutbox`、`导出需求`、`需求导出`、`打包需求`、`导出给外部` — TL 模式下将框架内需求文档导出为外部可读的文档包

## 目的

将框架内某个 Goal 分点的需求文档（实施计划、原型、审核报告、grill 明细等非代码产物）整理为**去标识化的独立文档包**，放入 `A.目标体系/_需求收件箱/`，供人类线下分发给外部人员（非本框架使用者）。

> **与 `/withInbox` 的关系**：`/withInbox` 是入站（外部→框架），`/withOutbox` 是出站（框架→外部）。共用一个收件箱目录，方向相反。

---
## 执行模型

```
用户: /withOutbox GOAL-XXX P{N}
      ↓
Agent 确认目标 Goal 和分点号（未明确时询问）
      ↓
扫描 A.目标体系/GOAL-XXX-.../产物/{P{N}}/ 和 grill/ 目录
      ↓
筛选：保留非代码产物（.md / .html / .png 等），排除代码文件（.sql / .java / .vue / .ts 等）
      ↓
去标识化处理（详见 UTIL-需求导出协议.md）：
  ├── 目录名 → 纯业务主题（去 GOAL 编号/分点号）
  ├── 文件名 → 去 [GOALNNN]-[NN]-ART-角色- 前缀
  ├── 文件内容 → 去 YAML frontmatter + 替换内部引用
  └── README.md → 纯业务语言，不出现框架编码
      ↓
在 _需求收件箱/ 下创建 {业务主题名}/ 目录
      ↓
复制去标识化后的文件 + 生成 README.md 索引
      ↓
口头报告：导出位置、文件清单、排除了哪些文件及原因
```

---
## 行为约束

### 必须做

- 用户未明确指定 Goal/分点号时，**主动询问**（不允许模糊导出）
- 导出前完整读取分点相关的**全部产物文件**，理解上下文
- **严格去标识化**：文件名 + 目录名 + frontmatter + 正文内部引用，不留任何本地编码
- 生成 README.md 索引，使用纯业务语言描述背景、文档清单、关键决策、状态
- 导出后口头报告完整结果
- 原始文件**原样保留**，导出的是去标识化副本

### 禁止做

- 不修改原始 Goal 目录下的任何文件
- 不在导出包中保留 YAML frontmatter
- 不在 README.md 或文件名中引用 GOAL/分点/任务编号
- 不导出代码文件（SQL/Java/Vue/TS 等）
- 不导出框架内部管理文件（工作记录/历史分点/任务文件）
- 不在 Teacher 模式下响应此指令

---
## 去标识化规则

详见 `通用能力层/工具手册/UTIL-需求导出协议.md`。核心规则：

| 对象 | 规则 | 示例 |
|------|------|------|
| 目录名 | 纯业务主题 | ~~`GOAL-002-P5-收支流水`~~ → `收支流水统一表需求` |
| 文件名 | 去 ART 前缀 | ~~`[GOAL002]-[05-00-02]-ART-TL-实施计划.md`~~ → `实施计划.md` |
| 文件内容 | 去 frontmatter | 删除 `---...---` 块 |
| 正文引用 | 替换内部编码 | `GOAL-002 P5` → 业务名称 |
| README | 纯业务语言 | 不出现 GOAL/P{N}/ART 等 |
