# /mgmtEstimate — 工时估算与汇总

## 触发

- `/mgmtEstimate <时间范围>` — 指定时间范围的工时汇总
- 自然语言别名：`工时汇总`、`工时估算`、`帮我估算工时`、`上半月工时`、`本月工时`
- 时间范围格式支持：
  - `上半月`、`下半月`、`本月`、`上周`、`本周`
  - 具体日期范围：`2026-06-01..2026-06-15`

## 适用范围

**TL 和 Teacher 模式均可用**。

## 目的

汇总指定时间范围内所有已完成工作分点的工时估算，按 Goal 维度聚合输出。

---

## 数据源

| 数据类型 | 来源路径 | 提取内容 |
|---------|---------|---------|
| 已完成分点 | `A.目标体系/GOAL-*/历史分点.md` | 分点描述、完成日期 |
| 进行中分点 | `A.目标体系/GOAL-*/工作记录.md` | 分步耗时记录（如有） |
| 任务文件 | `A.目标体系/GOAL-*/关联任务/` | 任务 frontmatter 中的时间字段 |
| 目标总览 | `A.目标体系/目标总览.md` | Goal 标题、最近完成时间 |

## 工时估算规则

### 优先级策略

```
1. 显式耗时记录 → 直接使用（工作记录中标注的耗时）
2. 任务复杂度推断 → 按任务文件 frontmatter 中的 effort/size 字段估算
3. 分点粒度推断 → 按分点类型给出默认估算
```

### 默认估算参考

| 分点类型 | 默认工时 | 说明 |
|---------|:---:|------|
| 简单修改/配置 | 0.5h | Bug 修复、配置调整 |
| 中等功能/单模块 | 2h | 单接口 CRUD、单页面组件 |
| 复杂功能/跨模块 | 4h | 多表关联、跨服务调用 |
| 架构/方案设计 | 2h | 技术方案、接口设计 |
| 代码审查 | 0.5h | 单次审查 |
| 问题排查 | 1h | 日志分析、根因定位 |

> **注意**：默认估算是兜底策略。Agent 在汇总时应**明确标注哪些分点使用了默认估算**，便于人类校准。

---

## 执行流程

### Phase 1: 解析时间范围

1. 将用户输入的时间范围转换为具体日期区间
2. 若用户未指定范围，默认使用"本月至今"

### Phase 2: 收集已完成分点

1. 读取所有 `GOAL-*/历史分点.md`，筛选日期在范围内的已完成分点
2. 读取 `目标总览.md`，筛选范围内已勾选 `[x]` 的分点
3. 去重（同一分点可能同时出现在历史分点和目标总览中）

### Phase 3: 估算工时

对每个已完成分点：
1. 检查工作记录中是否有显式耗时标注
2. 若无，按分点描述关键词匹配默认估算表
3. 标注估算来源（显式 / 推断）

### Phase 4: 汇总输出

按 Goal 维度聚合，输出结构化报告。

---

## 行为约束

### 必须做
- 明确区分显式耗时与推断估算
- 标注所有使用默认值的条目
- 时间范围不明确的，向用户确认后再执行
- 汇总报告中注明估算策略

### 禁止做
- 不修改任何框架数据文件
- 不对未完成的分点进行工时估算（仅统计已完成的）
- 不在缺乏数据时编造工时

### 边界处理

| 场景 | 处理 |
|------|------|
| 时间范围内无已完成分点 | 报告"该时间段无已完成工作"，不输出空汇总 |
| 工作记录格式不统一 | 尽力解析，标注"格式不统一，部分数据可能遗漏" |
| 分点描述无法匹配默认估算表 | 标注为"待确认"，工时留空 |
| 管理报告目录不存在 | 先创建 `A.目标体系/管理报告/` 目录 |
