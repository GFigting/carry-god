# 角色体系 — Agent 使用指引

## 何时读取本板块

- Agent 需要以某个特定角色身份执行任务时（角色扮演）
- Agent 需要了解某个角色的职责边界、输入输出、协作关系时
- 人类指定了角色绑定（role_binding），Agent 需要加载该角色的激活指令时
- 流程编排中需要确定某个节点由哪个角色执行时
- Agent 需要检查某个操作是否在角色权限范围内时

## 模式指令子系统

`模式指令/` 是本板块的子模块，管理 as/with 系列模式指令。设计原则：

- **渐进式加载**：指令定义文件不在启动时预加载，仅在用户输入触发词时读取
- **指令即契约**：每个指令文件是完整的、自包含的行为契约
- **as 互斥，with 叠加**：as 系列模式切换互斥，with 系列行为增强可叠加（仅 TL 模式）

Agent 加载协议详见 `模式指令/🎛️_指令总览.md`。

## 如何读取角色的 Agent 激活指令

每个角色文件底部都有 `## Agent 激活指令 (Agent Activation Prompt)` 章节，包含：

1. **角色身份**（role identity）— 一行角色定位描述，直接用于 Agent system prompt
2. **上下文加载清单**（context loading list）— 该角色执行任务前必须加载的文件列表，分"必读"和"参考"两级
3. **行为约束**（behavioral constraints）— 该角色必须遵守的硬性规则
4. **输出规范**（output specifications）— 该角色的产出物格式和质量要求

**Agent 使用方式**：
- 读取对应角色文件的 `frontmatter`（inputs/outputs/checklists/upstream/downstream）获取结构化信息
- 读取 `Agent 激活指令` 章节，将「角色身份」注入 system prompt，「行为约束」作为执行规则，「输出规范」作为验收标准
- 将「上下文加载清单」中的必读文件加入上下文包

## 角色总览中的协作关系图

`🎭_角色总览.md` 中的 Mermaid 图展示了角色的上游（提供输入）、下游（接收输出）、同级协作关系。Agent 在执行流程编排时需要：
- 确认当前节点的上游角色是否已完成产出
- 确认产出物是否符合下游角色的输入格式要求
- 多角色并行时，检查是否存在同级的协作依赖

## 与其他板块的联动

- **工作体系**：通过 `2.工作体系/工作-能力矩阵.md`（RACI 矩阵）确认某工作类型需要哪些角色参与
- **流程引擎**：流程的每个 node 绑定了具体角色，Agent 读取流程文件后应回到本板块加载对应角色的激活指令
- **通用能力层**：角色定义中的 `checklists` 字段引用了检查清单，`tools` 字段引用了工具手册
- **导航系统**：`导航系统/📑_角色索引.md` 提供了简洁的角色列表快速跳转
- **配置与元数据**：`配置与元数据/标签体系.md` 中的 `role/` 标签用于给角色文档打标

## Agent 操作清单

1. **阅读总览**：先读 `🎭_角色总览.md` 理解全貌和协作关系
2. **确定角色**：根据任务需求或流程节点，定位目标角色文件路径
3. **加载角色**：读取角色文件的 frontmatter 和 Agent 激活指令
4. **绑定角色**：将「角色身份」作为 system prompt 的一部分，加载「行为约束」和「输出规范」
5. **加载关联上下文**：按「上下文加载清单」加载必读文件（检查清单、流程、工作类型）
6. **确认权限**：检查角色的 responsibilities 和 behavioral constraints，确认要执行的操作在角色权限范围内
7. **记录关键决策** ⚠️ 强制：执行任务后，必须在任务文件的「执行记录」章节或产物工件的「背景与需求」章节中记录「关键决策 + 拒绝的替代方案 + 偏离说明 + 产出清单」。注意：不需要重复记录原始需求——那已由秘书在派发时写入任务文件的「派发记录」。此项要求支持 asNormal 角色代理模式。
