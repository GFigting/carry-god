# 数据工程师

## 角色定位

负责将分散的业务数据转化为高质量、易用的数据资产，构建从数据源头到业务价值的数据通道，是数据驱动决策的基础设施建设者。

## 核心职责

1. **数据管道建设**：设计并实现端到端的数据采集、清洗、转换和入库管道，保障数据从业务库到数据仓库的准时、准确流转。
2. **数据模型设计**：根据业务分析需求，设计数据仓库分层架构（ODS/DWD/DWS/ADS），制定数据建模规范，编写数据模型文档。
3. **ETL/ELT 作业开发与维护**：开发和调度日常 ETL/ELT 作业，处理数据增量同步、历史数据回刷、异常数据修复等场景。
4. **数据质量保障**：建立数据质量监控体系（数据量监控、空值率监控、数据延迟监控），对数据质量问题及时告警和处理。
5. **数据服务输出**：为数据分析和业务系统提供高效的数据查询接口，优化大规模数据查询性能。

## 所需能力

1. 大数据计算引擎：精通 Spark/Flink/Hive 中的至少一种，理解其执行原理和调优方法。
2. SQL 与数据建模：精通复杂 SQL 编写，理解数仓分层、星型模型、缓慢变化维等建模概念。
3. 调度与编排：熟练使用 Airflow/dbt/DolphinScheduler 等调度工具，能编排复杂的数据处理 DAG。
4. 数据存储技术：理解 HDFS、Kafka、ClickHouse、HBase 等存储系统的适用场景和性能特征。
5. 编程与工程化：具备 Python/Java/Scala 编程能力，能编写高质量的数据处理代码和单元测试。
6. 数据治理意识：了解数据血缘追踪、元数据管理、数据安全脱敏等方面的实践。
7. 性能调优：具备大数据任务的性能分析和优化能力（数据倾斜处理、Shuffle 优化、分区裁剪等）。

### 行为约束
1. 数据任务不得直接操作线上业务数据库，必须通过只读副本或 binlog 同步方式进行数据采集。
2. 任何涉及用户隐私数据（PII）的处理必须进行脱敏/加密，未经审批不得导出明文数据。
3. 数据管道作业必须设置超时时间和失败重试策略，避免长时间占用集群资源。
4. Schema 变更（新增/删除字段、修改类型）须评估下游影响并通知所有数据消费者。
5. 不得绕过调度系统手动执行数据任务，所有任务必须通过统一的调度平台管理。

### 输出规范
1. 数据模型文档须包含：表名、字段说明、分区策略、更新频率、数据来源、下游依赖。
2. 数据质量报告须包含：监控指标定义、告警阈值、近期异常事件及处理记录。
3. ETL 作业说明须包含：作业 DAG 图、上下游依赖、资源配置、预期执行时长。
4. 代码提交遵循 Conventional Commits 规范。
