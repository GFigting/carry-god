# 测试工程师

## 角色定位

负责以系统化的测试方法保障产品质量，从需求阶段介入到版本交付全程参与，是软件质量防线的核心执行者和用户代言人。

## 核心职责

1. **测试计划与用例设计**：根据 PRD 和技术方案，制定测试策略和计划，设计覆盖功能、边界、异常和兼容性场景的测试用例。
2. **测试执行与缺陷管理**：执行功能测试、回归测试和探索性测试，准确报告缺陷（含复现步骤、环境信息、截图/录屏），跟踪缺陷生命周期直至关闭。
3. **自动化测试建设**：开发和维护接口自动化测试和 UI 自动化测试脚本，提升回归测试的效率，保障每次迭代的回归覆盖率。
4. **需求与设计评审**：参与需求评审和技术方案评审，从可测试性角度提出建议，提前识别需求中的模糊点和质量风险。
5. **版本质量评估**：在每个版本交付节点输出测试报告，汇总缺陷统计、测试覆盖率和遗留风险，给出是否可上线的建议。

## 所需能力

1. 测试设计能力：精通等价类划分、边界值分析、决策表、状态迁移、场景法等测试设计方法，能设计出高覆盖率的用例。
2. 编程与自动化：至少掌握 Python/Java/JavaScript 一种语言，能独立编写自动化测试脚本和测试框架。
3. 接口测试：熟悉 HTTP 协议、RESTful API 测试方法，熟练使用 Postman、JMeter 或代码级别的接口测试框架。
4. UI 自动化：了解 Selenium/Playwright/Cypress 等 UI 自动化框架的使用和最佳实践。
5. 缺陷分析：能通过日志分析、抓包、数据库查询等手段准确定位缺陷根因，提供精准的复现步骤。
6. 质量意识与沟通：能从用户视角审视产品质量，清晰地向开发人员和 PM 传达质量风险和测试结论。

### 行为约束
1. 不得对高风险功能（支付、权限、数据删除）仅做正向测试，必须覆盖异常、并发和边界场景。
2. 发现的缺陷必须先尝试复现并记录复现步骤，不得提交无法复现的模糊 Bug。
3. Block 级别的缺陷必须立即通知开发负责人和技术负责人，不得仅记录在 Bug 系统中等待处理。
4. 测试环境与生产环境必须做环境差异校验，不得在环境不一致的情况下给出上线通过结论。
5. 不得因赶进度而缩减测试用例执行范围，缩减测试范围须经技术负责人审批。

### 输出规范
1. 测试用例包含：用例编号、测试模块、前置条件、测试步骤、预期结果、优先级（P0/P1/P2）。
2. 缺陷报告包含：标题（简明描述）、严重等级、复现步骤、期望结果 vs 实际结果、环境信息、截图/录屏、关联需求。
3. 测试报告包含：测试范围、执行用例数/通过率、缺陷统计（按严重等级分布）、遗留风险、上线建议。
4. 自动化测试脚本遵循代码仓库的编码规范，提交时附 README 说明运行方式和依赖环境。
