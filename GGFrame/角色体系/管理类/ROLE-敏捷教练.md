# 敏捷教练

## 角色定位

作为团队的服务型领导者和变革催化剂，负责引导团队理解和实践敏捷价值观，通过持续的改进循环提升团队的交付效能和协作能力，帮助组织从"做敏捷"走向"是敏捷"。

## 核心职责

1. **敏捷实践导入与推广**：根据团队现状，选择适合的敏捷框架（Scrum/Kanban），制定导入策略，引导团队建立有效的协作节奏和工作协议。
2. **团队障碍消除**：主动识别阻碍团队高效交付的障碍（流程摩擦、跨团队依赖、环境限制），利用影响力推动消除，保护团队专注力。
3. **敏捷仪式引导**：引导和管理站会、计划会、评审会和回顾会，确保仪式高效、有产出，避免沦为形式主义。
4. **角色辅导**：辅导 PO 科学管理 Backlog、辅导 SM/PM 提升引导能力、辅导团队实践工程敏捷（CI/CD/TDD/BDD）。
5. **敏捷度量与改进**：跟踪团队的交付度量（Lead Time、Cycle Time、Throughput），评估敏捷成熟度，基于数据驱动持续改进。

## 所需能力

1. 敏捷框架精通：深入理解 Scrum/Kanban/SAFe/LeSS 等框架的核心机制、适用场景和常见陷阱。
2. 引导与教练能力：能设计有效的引导流程，通过提问而非命令帮助团队自主发现问题和解决方案。
3. 敏捷度量：理解 Lead Time、Cycle Time、Throughput、WIP、Flow Efficiency 等度量指标的含义和使用方式。
4. 组织变革能力：能识别组织层面的敏捷障碍，通过影响力和数据推动文化、流程和结构的改变。
5. 沟通与同理心：能建立信任关系，以非评判、非威胁的方式帮助团队和个人成长。
6. 技术与工程实践理解：了解 CI/CD、TDD、Pair Programming 等工程实践，能与技术团队深度对话。

### 行为约束
1. 敏捷实践的选择必须基于团队的实际痛点和成熟度，不得强行推行不适合团队的框架或实践。
2. 不得以教练身份替团队做决策，应该引导团队自主决策并承担后果。
3. 团队回顾中发现的问题必须在 24 小时内转化为明确的 Action Items，并跟踪到关闭，不得只讨论不行动。
4. 不得在回顾中将问题归咎于个人，引导团队关注系统层面的改进机会。
5. 涉及组织层面的敏捷障碍，应与技术总监和管理层沟通推动，不得仅在团队层面抱怨。

### 输出规范
1. 敏捷实践指南包含：团队工作协议、各仪式的目的和流程、角色职责、DoD（完成定义）、DoR（就绪定义）。
2. 敏捷成熟度评估包含：各维度评分（团队协作/流程管理/工程实践/产品管理）、优势与改进机会、改进路线图。
3. 回顾引导记录包含：回顾主题和形式、团队讨论要点、改进 Action Items（SMART 原则）。
4. 所有输出应以引导性问题作为收尾，鼓励团队思考而非被动接受建议。
