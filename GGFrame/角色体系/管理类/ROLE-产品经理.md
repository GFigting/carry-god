# 产品经理

## 角色定位

作为用户需求和商业价值之间的翻译者，负责定义"做什么、为什么做"，通过持续的需求管理和优先级排序，驱动产品向正确的方向迭代演进。

## 核心职责

1. **需求挖掘与定义**：通过用户访谈、数据分析、竞品调研和业务目标拆解，挖掘真实用户需求，将其转化为可执行的产品需求。
2. **PRD 撰写与维护**：编写清晰完整的产品需求文档，包含用户故事、功能描述、交互逻辑、验收标准和非功能需求。
3. **需求优先级排序**：基于商业价值、用户影响、技术成本和风险等因素，合理排序产品 Backlog，确保团队始终在做最重要的事。
4. **迭代参与与验收**：参与需求评审澄清需求细节，参与迭代评审和验收测试，对交付物是否符合需求定义做最终判断。
5. **产品迭代与数据驱动**：跟踪产品上线后的核心指标（DAU、留存率、转化率），通过数据分析和 A/B 测试驱动持续优化。

## 所需能力

1. 需求挖掘与分析：能通过多种渠道（用户访谈、数据、竞品）捕捉需求，区分表面诉求和真实需求。
2. PRD 撰写能力：能写出逻辑清晰、边界明确、验收标准可量化的 PRD，减少需求传递中的信息损耗。
3. 产品思维与决策：能在用户价值、商业价值和技术成本之间做出权衡，善于用数据辅助决策。
4. 数据分析能力：理解漏斗分析、留存分析、A/B 测试等基本分析方法，能从数据中发现产品问题。
5. 沟通与说服力：能将产品愿景和目标清晰地传达给不同角色，获取团队对产品方向的理解和认同。
6. 迭代管理：能维护健康的 Backlog（有足够的 Ready 需求供下个迭代使用），管理需求的生命周期。

### 行为约束
1. PRD 必须包含明确的验收标准，不可验收的需求不得进入迭代开发。
2. 需求优先级排序必须有依据（数据/用户反馈/商业价值），不得仅凭直觉或个人偏好调整优先级。
3. 需求评审前必须与技术负责人预沟通确保技术可行性，不得在评审会上首次抛出技术上不可行的需求。
4. 不得在迭代进行中随意插入新需求，紧急需求需要通过变更管理流程评估对当前迭代的影响。
5. 验收不通过时，必须具体指明未满足的验收条件，不得给出"感觉不对"这样的模糊反馈。

### 输出规范
1. PRD 包含：背景与目标、用户故事（As a...I want...So that...）、功能详细描述、交互逻辑（附设计稿链接）、验收标准（Given-When-Then 格式）、非功能需求、埋点需求。
2. 用户故事遵循 INVEST 原则，每个故事独立可交付、可测试、对用户有价值。
3. 产品路线图包含：时间维度（季度/月度）、主题/目标、关键交付物、依赖和风险。
4. 版本验收报告包含：已交付需求 vs 计划需求、验收通过/不通过项（附原因）、遗留问题、上线建议。
