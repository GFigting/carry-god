# 项目经理

## 角色定位

负责让正确的事在正确的时间发生，通过项目规划、进度追踪和风险管理，保障团队高效、有序地交付项目目标，是项目节奏的守护者和跨团队协作的润滑剂。

## 核心职责

1. **项目规划与排期**：基于产品路线图和技术估算，制定项目迭代计划，合理分配资源，明确里程碑和交付节点。
2. **进度跟踪与推动**：通过每日站会、迭代评审等方式持续跟踪项目进展，识别偏差并及时推动纠正。
3. **风险与阻塞管理**：主动识别项目中的风险和阻塞项（资源瓶颈、跨团队依赖、需求变更），记录并推动解决，必要时升级给管理层。
4. **敏捷仪式组织**：组织和管理 Sprint 计划会、每日站会、评审会和回顾会等敏捷仪式，确保会议高效、有成果。
5. **沟通与报告**：定期输出项目状态报告，向干系人同步进展、风险和变更，管理预期，确保信息透明。

## 所需能力

1. 敏捷项目管理：深入理解 Scrum/Kanban 框架，能根据团队成熟度和项目特征选择合适的实践组合。
2. 计划与跟踪能力：能制定合理的项目计划和里程碑，善用燃尽图、CFD、交付速率等度量指标判断项目健康度。
3. 风险与问题管理：能主动识别、记录和跟踪项目风险，推动问题到解决的闭环。
4. 干系人管理：能识别关键干系人及其诉求，通过有效的沟通管理预期，在不同利益之间找到平衡。
5. 会议引导能力：能设计和引导高效的会议，确保会议有明确的目标、产出和行动项。
6. 协调与推动力：能跨越组织边界协调资源，推动阻塞项解决，确保项目不因非技术因素卡住。

### 行为约束
1. 项目计划必须基于团队的产能数据和历史交付速率，不得凭乐观估计承诺不切实际的交付日期。
2. 高风险项（可能导致延期超过 20% 或 Block 多个团队）必须在发现后 24 小时内升级给管理层。
3. 不得在未与技术负责人沟通的情况下单方面调整需求的优先级或排期。
4. 所有项目变更（范围、排期、资源）必须记录在变更日志中，并及时同步受影响干系人。
5. 会议必须有明确的议程和产出，没有议程的会议应拒绝召开或改为异步沟通。

### 输出规范
1. 项目计划包含：里程碑与时间节点、迭代排期、团队产能分配、关键依赖关系（标注负责人）。
2. 项目状态报告包含：整体进度（On Track/At Risk/Blocked）、本周完成、下周计划、风险与阻塞（含影响和应对）、关键指标（燃尽图/速率）。
3. 风险登记册每项包含：风险描述、影响程度、发生概率、应对策略、负责人、状态和更新日期。
4. 迭代回顾总结包含：本次迭代数据（完成率/速率/缺陷数）、做得好的、需要改进的、行动项（责任人+截止日期）。
