# 改造方案：Goal 为中心目录结构

- [x] 本篇已完成

## 改造目标

将框架从"任务系统 + 产物工件双中心"演进为"Goal 单中心"，实现：

1. **人类只需维护一个文件** — `目标总览.md`，所有活跃目标+分点一目了然
2. **每个 Goal = 一个自包含文件夹** — 历史分点、工作记录、关联任务、产物全部在 goal 目录下
3. **任务与分点显式关联** — 分点→任务 1对多，任务文件直接放在所属 goal 的 `关联任务/` 下
4. **产物按任务分组** — `产物/TASK-YYYY-NNN/`，不再平铺混放
5. **AI 辅助维护** — 人类发起指令，AI 原样迁移已完成分点、维护工作记录、维护关联任务索引

## 新目录结构详细规范

### 1. `A.目标体系/目标总览.md`

**维护者**：人类（AI 只读，不可修改）

**格式**：

```markdown
# 目标总览

> 此文件由人类维护。AI 只可读取，不可修改。
> 分点完成后，向 AI 发起指令「将 GOAL-XXX 的已完成分点迁移到历史分点」。

---

## GOAL-003: 中台-结算明细-对接CBS

- **目标效果**：按给定的文档完全完成目标
- **当前分点**：
    - [ ] 1. 初版代码微调
        - [ ] 1.1 getCbsAccountInfoList 不存在；FC_CBS_EXECUTION_STATUS字典不存在 → [[TASK-2026-017]]
        - [ ] 1.2 ...
    - [ ] 2. 后续优化
- **最近完成**：2026-06-11 — 基于可执行开发计划进行开发

---
```

**规则**：
- Goal 标题格式：`## GOAL-NNN: 系统-模块(可选-子模块)` — 系统/模块名帮助人类快速定位领域
- 每个分点如果创建了任务，在分点行末标注 `→ [[TASK-YYYY-NNN]]`
- 分点全部完成后，人类删除该分点行，并通知 AI 迁移
- 保留"最近完成"行作为上下文锚点（可选，帮助人类回忆起上次做到哪了）

### 2. `GOAL-NNN-系统-模块/历史分点.md`

**维护者**：AI（人类发起指令后执行）

**格式**：

```markdown
# GOAL-003 历史分点

> AI 维护。人类发起「迁移已完成分点」指令后，AI 原样追加到此处。
> 倒序排列（最新完成在最上面）。

---

## 2026-06-11

- [x] 3. 整理所需配置项，SQL，字典权限 → 关联 [[TASK-2026-017]]
  - 输出：字典SQL、权限配置、CBS接口对接配置

## 2026-06-10

- [x] 2. 基于可执行开发计划进行开发
  - 涉及：fms-rear 结算明细模块 + fms-ui 结算明细页面

## 2026-06-09

- [x] 1. withPlan 查阅分析相关文档
  - 输出：实施计划 [[ART-TL-2026-017-01-实施计划]]
```

**规则**：
- 按日期分组，倒序（最新在最上面）
- 每个分点原样保留勾选状态 `[x]` + 描述 + 关联任务链接
- AI 执行迁移时：从 `目标总览.md` 复制已完成分点文本 → 追加到历史分点文件顶部 → 人类自行从总览中删除

### 3. `GOAL-NNN-系统-模块/工作记录.md`

**维护者**：AI（TL 模式下分步执行时自动追加）

**格式**：

```markdown
# GOAL-003 工作记录

> AI 维护。分步执行时自动追加。倒序排列。

---

## 2026-06-12 Step 5: 初版代码微调

- 要求：修复 getCbsAccountInfoList 和 FC_CBS_EXECUTION_STATUS 字典
- 状态：[x] 已完成
- → 已转为任务 [[TASK-2026-017]]

## 2026-06-11 Step 3-4: 配置项整理 → 代码开发

- 要求：整理SQL、字典、权限配置，然后开发
- 状态：[x] 已完成
- 实现：...
```

**规则**：
- 倒序，按日期+Step分组
- 每个Step记录：要求 + 状态 + 实现简述（或转任务链接）
- 简单分步直接记录完成，复杂分步转任务后在此引用

### 4. `GOAL-NNN-系统-模块/关联任务/`

**维护者**：AI（TL 创建任务时自动放入）

**内容**：标准任务 `.md` 文件，使用 `tpl-agent-task` 或 `tpl-task` 模板，frontmatter 完全不变。

**规则**：
- 任务文件直接放此目录（不建子目录）
- 命名保持 `TASK-YYYY-NNN.md`（全局编号不变）
- 子任务命名：`TASK-YYYY-NNN-SUB{N}.md`
- Agent 任务命名：`TASK-YYYY-NNN-AT{N}.md`
- 任务 frontmatter 中 `linked_goals` 字段必填，指向所属 goal

**跨 goal 任务处理**：
- 任务文件放在主要关联的 goal 下
- 另一个 goal 的 `关联任务/` 中创建一个引用文件（内容为 `→ 见 [[GOAL-XXX/关联任务/TASK-YYYY-NNN]]`）
- 文件名：`TASK-YYYY-NNN.引用.md`

### 5. `GOAL-NNN-系统-模块/产物/`

**维护者**：AI（Agent 完成任务时写入）

**内容**：任务产出的非代码文档（实施计划、技术方案、DDL、评审报告等）

**规则**：
- 按任务分目录：`产物/TASK-YYYY-NNN/`
- 产物命名保持 `ART-{角色缩写}-{YYYY}-{NNN}-{序号}-{中文名}.{扩展名}`
- 代码文件不受此管理，直接写入项目源码目录
- DDL 脚本放此处，不同步到项目

### 6. `A.目标体系/历史目标/`

**维护者**：人类（将已完成 goal 的整个目录移入）

**规则**：
- Goal 所有分点完成后，人类将整个 `GOAL-NNN-xxx/` 目录移入此处
- 移入后在 `目标总览.md` 中删除该 goal 条目

## Goal 命名规范

```
GOAL-NNN-{系统}-{模块}
```

| 组成部分 | 说明 | 示例 |
|---------|------|------|
| `GOAL-NNN` | 全局编号（NNN 为三位数字，递增） | GOAL-003 |
| `{系统}` | 系统简称（fms/lasen/中台等） | 中台 |
| `{模块}` | 功能模块（结算明细/账单对账单等） | 结算明细 |

**示例**：
- `GOAL-003-中台-结算明细`
- `GOAL-004-FMS-账单对账单`
- `GOAL-999-日常问题排查`（跨系统的维护类 goal 可省略系统名）

**历史 goal 命名**：移入 `历史目标/` 时，可补全系统和模块信息：
- `GOAL-001` → `GOAL-001-FMS-账单对账单-基础框架`

## 关键设计决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| Goal 命名包含系统和模块 | `GOAL-NNN-系统-模块` | 从目录名就能看到领域归属，不依赖打开文件 |
| 不要独立的目标定义文件 | 人类只看 `目标总览.md` | KISS：一个文件 > 多个文件跳转 |
| 任务文件放 goal 下 | `关联任务/` 目录 | 分点→任务 1对多，物理上的接近性帮助定位 |
| 产物按任务分目录 | `产物/TASK-YYYY-NNN/` | 避免多任务产物混放 |

## 风险与注意事项

1. **Dataview 查询**：如果用户不使用 Obsidian，Dataview 查询无效，但不影响框架功能
2. **外部引用**：如果外部系统（如 CI/CD）引用了 `任务系统/进行中/` 路径，需要更新
3. **人类习惯**：从"任务系统找任务"变为"从 goal 找任务"，需要适应期
4. **迁移数据量**：当前 GOAL-001/002 历史分点超过 100 行，迁移后各 goal 的历史文件会很大，但不影响使用
