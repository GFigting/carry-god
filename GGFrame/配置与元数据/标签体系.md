# 标签体系

## 说明

本标签体系采用层级化前缀设计，确保标签含义明确、避免冲突。标签使用英文，便于 Dataview 查询和跨工具兼容。

---

## 一级分类

### `type/` — 文档类型

标识文档的核心类型，每个文档必有至少一个 type 标签。

| 标签 | 说明 | 对应模板 |
|------|------|----------|
| `type/moc` | 导航索引页（Map of Content） | tpl-moc |
| `type/role` | 角色定义 | tpl-role |
| `type/work-type` | 工作类型定义 | tpl-work-type |
| `type/task` | 任务记录 | tpl-task |
| `type/process` | 流程定义 | tpl-process |
| `type/knowledge` | 知识文章 | tpl-knowledge |
| `type/daily-log` | 日报 | tpl-daily-log |
| `type/weekly-report` | 周报 | — |
| `type/meeting` | 会议记录 | tpl-meeting |
| `type/checklist` | 检查清单 | — |
| `type/artifact` | 产物工件 | tpl-artifact |
| `type/config` | 配置/元数据文档 | — |
| `type/template` | 模板文档 | — |

## 使用规范

1. **每个文档必须有 `type/` 标签**
2. **`status/` 标签与文档生命周期同步更新**
3. **角色定义文档额外带 `role/` 标签**
4. **工作类型文档额外带 `work/` 标签**
5. **知识文档额外带 `domain/` 标签**
6. **任务文档额外带 `status/`、`work/`、`priority/`、`project/`、`module/` 标签**
7. **产物工件文档额外带 `status/`、`role/`、`project/`、`module/`、`task/` 标签**

## Dataview 查询示例

```dataview
-- 查询所有活跃任务
FROM "3.任务系统"
WHERE type = "task" AND status != "archived"
SORT priority ASC, due_date ASC
```

```dataview
-- 查询后端领域知识
FROM "5.知识沉淀"
WHERE contains(tags, "domain/backend")
SORT updated DESC
```
