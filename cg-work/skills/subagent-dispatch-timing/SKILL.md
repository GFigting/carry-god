# 子智能体派发时机

本技能是框架内子智能体派发判据的唯一来源：回答"何时派发、何时不派发、各阶段如何派发"。工作流与 core 只保留指向本技能的指针，不复制正文。本技能不改变任务状态机、证据门禁与交付路径规则。

## 总则：比例原则

默认最小交付。仅当派发子智能体带来以下三类明确增益之一时才派发：

1. **上下文隔离**：任务只需局部上下文，或任务会产生大体量输出（长探索、大量命令结果），需要保护主会话上下文。
2. **并行**：工作可拆分为边界互不重叠（按文件所有权切分）的独立部分。
3. **独立视角**：需要不受实施者立场污染的审查或验收结论。

无以上增益时不派发：单模块小刀改动、可直接验证的行为调整、主 Agent 亲自完成更快的场景，一律由主 Agent 直接执行。轻量执行档（`delivery_path: lightweight`）默认不派发任何子智能体。

## 分阶段判据

### 计划阶段

- 跨模块、高风险或用户明确要求审查的任务：可并行派发两个子智能体做两线计划审核——**需求审核线**只判断需求覆盖、验收标准、范围遗漏或越界；**规范审核线**只判断计划结构、依赖、步骤、风险、验证可执行性和项目规范；均按"问题—依据—建议"输出。
- 同一子智能体不应同时代表需求方和规范方作最终结论。
- 轻量档与单模块小刀不做计划审核派发。

### 实现阶段

- 执行含多个独立任务的实现计划时，按镜像技能 `subagent-driven-development`（同会话）或 `executing-plans`（并行会话）的流程派发实现子代理；需要并行派发时按 `dispatching-parallel-agents` 执行，任务边界按文件所有权切分。本技能只引用这些镜像正文，不复制其流程。
- 实现类子代理不并行派发（文件冲突）；审查类可并行。
- 同形状小改动（同一类一行修改、常量替换、字段添加重复出现在多个文件）合并为一次派发交给同一个子代理，作为一个整体审查；只有需要独立判断、独立测试或独立审查面的工作才逐任务派发。
- 实现子代理不得再派发子代理（既不派助手也不派审查者）；审查由派发它的控制方安排。
- 单任务、单文件、主 Agent 可直接完成时不派发。

### 验证阶段

- Web 项目的页面与用户路径验收统一派发 browser-use 子代理：按项目上下文 `verification.profiles` 中配置的步骤执行，结果（截图、控制台日志、网络请求证据）回写任务 `verification.md`。
- 项目无对应验证 profile 或无浏览器界面时，不派发 browser-use；不得以静态检查或口头声明冒充页面验收结论。
- 验证记录必须区分已通过、环境受限未执行和不适用，不能以替代检查冒充完整检查。
- 纯浏览器验收存在边界：不覆盖数据库字段校验与日志警告类问题，此类校验必须结合接口/数据层检查才能兜住功能正确性。

### 审查收尾阶段

- 审查类子智能体可并行派发（如规范与需求两个视角分线审查）。
- 子智能体意见由主 Agent 汇总、去重并决定是否采纳，最终结论写回任务记录（该责任是 core 不变量，见 [工作模型](../../core/operating-model.md#计划、审查与验证的边界)）。
- 主 Agent 不代替子代理修复问题后跳过审查；涉及业务取舍的结论交由用户确认。
- 轻量档自审即可，不强制派发审查子智能体。

## 派发契约

- 派发词只包含该任务自身所需内容：任务定位一句话、需求或简报文件路径、上游任务留下的接口与决定、歧义的处理结论、报告文件路径与回传契约。不粘贴会话历史与累积摘要。
- 大体量交付物以文件路径交接，不把内容驻留进主上下文。
- 派发时明确模型选择：按任务复杂度选择够用的最低档位，省略模型会静默继承会话默认模型。
- 等待已派发的子代理时不轮询短超时、不做无限静默等待；有本地工作（更新记录、准备下一步交接）就继续做，真正空闲时分段有界等待并核对在派子代理状态。

## 反模式

以下偏差一经发现即纠正：

- **该派不派**：Web 验收跳过 browser-use 派发，用静态检查、代码阅读或口头声明冒充页面验收结论。
- **过度派发**：轻量任务派发子智能体；逐条审查发现各派一个修复代理（应合并为一次修复派发）；为同一差异重复派发多个审查席位；实现子代理自派审查者造成重复席位。
- **错误并行**：并行派发多个实现子代理造成文件冲突；并行派发时未按文件所有权切分边界。

## 边界

- 本技能不复制镜像技能正文；多任务计划执行、并行派发、跨会话执行的流程细节分别以 `subagent-driven-development`、`dispatching-parallel-agents`、`executing-plans` 镜像为准。
- 本技能不新增任务状态、产物文件或校验门禁；派发结论作为对应阶段证据写入既有任务记录。
- 外部、破坏性、生产、认证、部署或跨会话操作的授权边界仍以 [特殊操作](../../core/special-operations.md) 为准，派发判据不替代授权要求。
