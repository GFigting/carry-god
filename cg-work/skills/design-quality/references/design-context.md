# 设计上下文

## 为什么是硬前置

代码只记录"做了什么"，不记录"为谁做、要在什么情境里起什么作用、该有什么感觉"。跳过这一步，模型会退回到训练分布的平均值：居中标题、三行副文案、一排图标卡、一点渐变——什么都不错，但没有一处是决定。

四项必须由人给出，**禁止从代码库推断，禁止用"现代简洁"这类空词代替**。

## 四项必填

| 项 | 要什么 | 不合格 | 合格 |
|---|---|---|---|
| 受众 | 谁用、在什么情境用、用多久 | "用户""年轻人" | "凌晨加班从手机上核对库存的门店店长，一只手操作" |
| 用途 | 这一屏要让人完成什么动作或判断 | "展示产品" | "在 20 秒内确认本周哪两个 SKU 会断货" |
| 调性 | 一个明确的形容词方向 | "现代、简洁、高级" | "克制的编辑感：大字号标题、窄栏正文、没有图标" |
| 差异化 | 让人记住的一个点 | "好用" | "首屏就是一张真实门店的俯拍照片，标题直接压在货架上" |

另加两项现实约束：

- 品牌资产：已有的色、字、logo 能否使用；不能使用时要明确说明替代方案。
- 素材现实：自有照片 / 可截取的真实界面 / 可调用图像工具 / 只有纯图形。**这决定门禁 A16 是否触发降级**。

## 追问方式

- 一次问完，不要边做边问；用户答不上来时给两个具体候选让他选，不要继续泛问。
- 用户已给过上下文（历史对话、设计文档）就复用，不重复问。
- 只补一次：回答仍含糊时，按最接近的一个具体候选开工，并在报告写明"按 X 调性执行，若不符请指出"。

## 模板

写入设计目录的 `design-context.md`；没有设计目录时写入任务目录。

```markdown
# 设计上下文 · <页面或模块名>

- 受众：
- 用途（一屏内要完成的动作/判断）：
- 调性（一个形容词方向 + 一句解释）：
- 差异化（一个记忆点）：
- 品牌资产：可用 / 不可用（原因）
- 素材现实：自有照片 N 张 / 可截真实界面 / 可用图像工具 / 仅纯图形
- 明确不做：<用户说过不要的方向>
- 更新于：<日期>，变更人：<谁>
```

上下文变更不覆盖历史，追加"变更"小节并注明影响范围，避免同一页面两版方向混用。
