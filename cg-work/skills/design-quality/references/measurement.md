# 测量与降级

本框架没有上游那套自动化脚本（需要 Node + 浏览器），门禁靠人工测量。测量的目的是**把"我觉得"变成"多少"**，让判定不依赖审美自信。

## 三档能力

按手上条件选最低够用的一档，并在报告声明用了哪档。

| 档 | 条件 | 能判定的门禁 | 不能判定 |
|---|---|---|---|
| 完整 | 可启动页面 + 可截图 | 全部 A / B | —— |
| 半程 | 可启动但截图靠人工提供 | A1–A15、A18、B1–B12；A16/A17 由人工提供截图后判定 | 动效时序、错峰节奏 |
| 降级 | 只有源码 | 静态可查项：字体家族数、字号层级、渐变/阴影/毛玻璃、等宽与编号、图片数量、`prefers-reduced-motion` 是否存在、语义标签 | 视觉层级、空间节奏、留白、遮挡 |

降级时报告必须写明：`未做浏览器测量：<原因>`，并列出哪些门禁只做了静态判定。

## 完整档操作

1. 三档宽度截图：1440 / 768 / 390，各一张全页（可分段拼接）。
2. 量测：用开发者工具取值并填入对比表，不靠目测估像素。
   - 左右外边距：`getBoundingClientRect()` 与视口宽度相减。
   - 区块间距：相邻区块外接矩形间距。
   - 字号与色值：计算样式（computed style），不读源码。
   - 标题行数：截图数视觉行数；必要时用 `getClientRects()` 数行盒。
3. 动效：在加载与滚动中各截两帧，数位移/透明度变化的独立元素；开启系统"减少动态效果"再截一次，确认动效归零。
4. 对比度：取正文与底色色值算对比度，正文目标 ≥4.5:1。

## 半程档操作要点

- 明确告诉用户：需要哪几档宽度、哪几个状态（空/加载/错误/无权限）的截图。
- 一次要齐，避免多轮往返；给出截图清单而不是"来几张看看"。
- 收到的截图不足时只判可判项，其余写"待测"，不要猜。

## 常见测量错误

- 用设计稿尺寸代替实际渲染（设计稿是 1440@2x，不等于浏览器 1440）。
- 用源码里的 `max-width` 推断实际行宽，忽略父级 padding 与容器查询。
- 把浏览器的自动换行当成"标题两行"，而实际是视觉三行。
- 只看桌面档就断言响应式通过。

## 记录格式

```markdown
测量档位：完整 / 半程 / 降级
宽度：1440 / 768 / 390
| 门禁 | 实测 | 判定 |
```

数值保留整数像素；颜色保留原值（`#1a1a1a` 或 `oklch(...)`），不做主观近似。
