# 改已有页面的顺序

## 为什么有固定顺序

改版最常见的失败不是审美差，而是**同时动了太多东西**：颜色变了、结构也变了、还加了动效，结果用户说不清哪里不对，只能整页回退。

固定顺序按"效果大、风险小、可回滚"排序，且每一层都为下一层提供稳定基础。

## 第 0 步：基线（不可跳过）

改之前先记录，否则无法证明改好了。

| 记录项 | 方式 |
|---|---|
| 三档截图 | 1440 / 768 / 390 全页截图，存 `before/` |
| 排版 | `h1` 行数、正文 `font-size`、正文字族、字号层级数 |
| 空间 | 内容区左右外边距、区块垂直间距、是否存在半屏空白 |
| 颜色 | 底色、主墨色、强调色色值；强调出现的次数 |
| 状态 | 空 / 加载 / 错误 / 无权限 是否存在设计 |
| AI 味清单 | 眉标、图标卡、渐变、等宽编号、细线各出现几处 |

## 第 1–5 步

| 序 | 层 | 动什么 | 为什么在这个位置 |
|---|---|---|---|
| 1 | 字体 | 字族收敛到 ≤2、字号层级收敛到 ≤5、标题行数、测度 | 改动最便宜、影响最大；先定字，后面的间距才有依据 |
| 2 | 颜色 | 一底一墨一强调、明度台阶、对比度 | 依赖字重与字号，必须在字之后；改完整体气质已变 |
| 3 | 框架 | 外边距、区块间距、首屏标题与区块标题、区块顺序 | 依赖颜色分区；此时才看得出"哪块该合并/删除" |
| 4 | 状态 | hover / focus / active / disabled / 加载 / 空 / 错误 | 结构与颜色稳定后才不会返工 |
| 5 | 存量组件 | 替换套路卡片、图标卡、渐变按钮、眉标 | 最后做，因为前面几步常让它们自然消失 |

明确不动：技术栈、路由、数据契约、既有品牌资产、其它页面。需要迁移依赖或改数据结构时单独开任务确认。

## 每步的收口

每步完成后立刻截一组 `after-step<n>/`，与基线同比同宽度对比，写下差异；不通过就停在这一层修，不带病进入下一层。

## 对比表模板

```markdown
| 指标 | 改前 | 改后 | 判定 |
|---|---|---|---|
| h1 行数（390） | 3 | 2 | 通过（A1） |
| 正文字号 | 13px #888 | 16px #1a1a1a | 通过（A7） |
| 左右外边距（1440） | 差 24px | 相等 | 通过（A4） |
| 强调色出现次数 | 11 | 2 | 通过（A8） |
| 半屏空白 | 2 处 | 0 | 通过（A5） |
| 图片数 | 0（灰块 3 个） | 6（实拍） | 通过（A16） |
```

## 迁移与兼容

- 只换视觉、不改 DOM 结构时，尽量用同一批 class 或 token，降低回归面。
- 必须改结构时，先加新结构、后删旧结构，保证任一时刻页面可用。
- 涉及品牌 token 修改时，先查所有引用点，列出受影响的其它页面，再决定是本页覆盖还是全局改。

## 回滚

任一轮出现以下情况立即回滚到上一次 `after-step`：正文可读性下降、主要动作不可见、布局在某一档断掉、控制台报错。回滚后记录原因，不直接继续叠加修改。
