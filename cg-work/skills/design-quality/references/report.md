# 交付报告

报告的作用是让用户与后续接手者知道：**做了什么、凭什么说达标、有什么还没解决、什么东西是临时的**。不写报告等于无法验收，也无法回滚。

## 必填六节

1. 方向与调性：一句话，来自设计上下文；与上下文不一致时必须说明原因。
2. 让位记录：来自 `instruction-contract.md`，一条一段；没有就写"无"。
3. 门禁结果：A/B 逐条通过或不过，每条附证据。
4. 评分卡：最后一轮的七维分数与最低三项的处理结果。
5. 未解决项：仍未达标的门禁、原因、建议，不隐藏。
6. 素材与占位：图片、字体、样例内容来源；上线前必须替换的清单。

## 声明纪律

**不声明未执行过的检查。** 没跑浏览器测量就写"未做浏览器测量"；没测移动端就写"未测 390"；没做无障碍扫描就不写"已符合 WCAG"。

允许的措辞是事实陈述，不是结论承诺：

- 可以写："A1–A15 按降级档静态判定通过，A16/A17 待测。"
- 不可以写："设计已全面达标。"

## 模板

```markdown
# 交付报告 · <页面/模块> · <日期>

## 1. 方向与调性
<一句话>（上下文来源：`local/projects/<project-id>/design/design-context.md`，更新于 <日期>）

## 2. 让位记录
- 让位 A10 无渐变｜原因：<用户要求>｜范围：<选择器>｜后果：<代价>｜回滚条件：<条件>

## 3. 门禁结果（档位：完整/半程/降级）
| 条目 | 判定 | 证据 |
|---|---|---|
| A1 标题行数 | 通过 | 390 宽 2 行 |

## 4. 评分卡（第 <n> 轮）
| 维度 | 分 | 说明 |
|---|---|---|
| 视觉层级 | 3 |  |

交付线判定：通过 / 未通过（哪一维未达标）

## 5. 未解决项
- <门禁编号>：<现象>｜原因｜建议

## 6. 素材与占位
- 图片：<来源>，共 <n> 张；其中 <n> 张为占位
- 字体：<家族与来源>
- 样例内容：<哪些是编造的示例名>
- 上线前必须替换：<清单>
```

## 与任务记录的关系

- 报告本体写入任务目录 `verification.md` 或对应交付物旁；不另建平行文档。
- 报告中的"未解决项"要同步进任务的 `next_action`，避免验收后遗忘。
