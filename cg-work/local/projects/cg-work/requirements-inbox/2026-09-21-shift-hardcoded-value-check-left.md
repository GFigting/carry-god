# 硬编码与常量化检查前移

框架不应等到代码审查阶段才发现“请使用常量，不要硬编码”。对重复出现且有业务含义的字面量、状态值、类型值、路由片段、接口路径和阈值，应在计划和编码阶段完成常量化判断，并在提交前留下可验证的检查证据。

范围：

- 核心代码规范补充前置检查和例外边界。
- 工作流明确计划、编码、提交前和审查四个阶段的职责。
- 标准任务计划与验证记录使用统一的 `standards_preflight` 证据段落。
- 优先使用项目已有 ESLint、Checkstyle、静态扫描或格式化工具；没有合适工具时，记录针对变更差异的人工自查，不伪称自动检查通过。

非目标：不把所有字面量都强制抽成常量；一次性文案、测试数据、协议固定值、模板内容和局部明确值仍可保留，但应能说明理由。

验收标准：

- 编码前能在计划中看到常量化判断，而不是首次出现在审查意见中。
- 提交前验证能区分自动检查、人工差异自查和不适用项。
- 审查规则明确为复核前置证据，不再承担首次发现职责。
- 历史任务无需迁移，新增流程保持兼容。
