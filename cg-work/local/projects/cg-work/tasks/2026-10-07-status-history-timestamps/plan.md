# status_history 结构化记录实施计划

## 目标

将新产生的 `status_history` 记录统一为带 `status`、`at` 和 `reason` 的结构，同时兼容历史字符串数组，并保留不可恢复信息的明确标记。

## 范围

### 包含

- 校验结构化项的状态、时间和原因字段，继续接受历史字符串项。
- 验收队列写入带时间和原因的 `done` 记录。
- 新增可预览、显式 `--apply` 的历史迁移；`archived: true` 任务始终跳过。
- 同步规则文档、脚本文档、版本和测试。

### 不包含

- 不新增状态或改变状态转移矩阵。
- 不根据文件时间猜测历史时间，不伪造原因。
- 不改变任务验收和完成证据门禁。

## 需求与验收

- 需求来源：`../../requirements-inbox/2026-10-07-status-history-timestamps.md`
- 验收标准：
  - [ ] 新结构化项通过校验，历史字符串数组继续通过。
  - [ ] 验收队列写入结构化 `done` 历史项。
  - [ ] dry-run 不写入，`--apply` 只迁移指定项目的未归档任务。
  - [ ] 已归档任务不被迁移或再次校验。

## 影响范围

- 任务校验器、验收队列、迁移脚本、框架规则文档、脚本文档、版本和测试。

## 实施步骤

1. 定义结构化字段和历史兼容边界。
2. 更新校验、写入入口和迁移脚本，并补充测试。
3. 更新文档和版本，执行全量验证与 dry-run。

## 计划审核

- 需求覆盖：完整，结构化写入、兼容读取、迁移和归档排除均有验收项。
- 范围边界：不改变状态机，不猜测历史时间，不处理业务项目任务。
- 依赖与顺序：先更新校验与写入入口，再执行迁移和全量验证。
- 风险与回滚：默认 dry-run；未知时间和原因以 `null` 与明确说明保存。
- 审核结论：通过。
- 审核意见来源：主 Agent 自审与用户确认的方案。
