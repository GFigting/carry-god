# documentation 元数据规范化实施计划

## 目标

以 `documentation.impact`、`documentation.files` 和 `documentation.reason` 作为新任务规范字段，同时兼容历史别名并提供安全迁移。

## 范围

### 包含

- 校验规范字段和历史别名，拒绝同一语义同时出现两套字段。
- 新增迁移脚本，默认 dry-run，`--apply` 才修改指定项目范围。
- 迁移框架受管 `cg-work` 任务，业务项目不自动迁移；`archived: true` 的任务始终跳过。

### 不包含

- 不改变文档影响取值和任务状态。
- 不删除 `summary` 历史内容；作为兼容字段保留，后续另行评估。

## 需求与验收

- 需求来源：`../../requirements-inbox/2026-10-07-documentation-metadata-canonicalization.md`
- 验收标准：
  - [ ] 新规范字段通过校验，历史别名继续通过。
  - [ ] 同一语义同时填写规范字段和历史别名时被拒绝。
  - [ ] dry-run 不写入，`--apply` 只迁移指定项目。
  - [ ] 业务项目任务不被默认迁移。
  - [ ] 已归档任务不被迁移或再次校验。

## 影响范围

- 任务 YAML、任务校验器、迁移脚本、框架规则文档和测试。

## 实施步骤

1. 定义规范字段与兼容别名边界。
2. 实现校验和迁移脚本，先测试再迁移框架记录。
3. 更新文档、版本和任务证据。

## 计划审核

- 需求覆盖：完整。
- 范围边界：仅任务 documentation 元数据，不改变状态机。
- 依赖与顺序：校验器和迁移脚本先于数据迁移。
- 验收与验证：脚本测试、任务校验和全量检查。
- 风险与回滚：迁移默认预览，保留历史别名可回滚。
- 审核结论：通过。
- 审核意见来源：主 Agent 自审与用户决定。

## 验证

- standards_preflight：读取框架维护规则、工作模型和现有任务字段样例；不涉及业务代码。
- 自动化测试：`npm test`
- 静态检查：`npm run check`、`node scripts/check-skills.mjs`
