# 任务归档路径实施计划

## 目标

为历史任务提供不改变 `done` 语义的独立归档标记，归档后退出验收队列和常规生命周期校验。

## 范围

### 包含

- 新增 `scripts/archive-tasks.mjs`，按任务 ID 日期筛选，默认预览，`--apply` 才写入。
- 归档任务写入 `archived: true`、`archived_at` 和 `archive_reason`，不移动或删除文件。
- `acceptance-queue.mjs` 跳过已归档任务。
- `check-all.mjs` 对已归档任务只检查 YAML 可解析性；直接任务校验同样不执行生命周期门禁。
- 同步唯一规则来源、脚本文档、入口文档、版本和测试。

### 不包含

- 不把归档任务置为 `done`。
- 不自动处理当前日期或未来日期任务。
- 不迁移既有任务目录或清理历史证据。

## 需求与验收

- 需求来源：`../../requirements-inbox/2026-10-07-task-archive-bypass.md`
- 验收标准：
  - [ ] dry-run 不修改任务文件，`--apply` 只归档截止日期之前的目标任务。
  - [ ] 已归档任务不进入 `npm run queue`。
  - [ ] 已归档任务不因缺少 handoff、verification 等生命周期证据而被 `npm run check` 拒绝。
  - [ ] 非归档任务的现有校验和验收行为不变。

## 影响范围

- 文件、模块或接口：任务 YAML、归档脚本、验收队列、全量检查、核心规则和测试。
- 调用方和依赖方：`npm run queue`、`npm run check`、任务记录维护者。

## 实施步骤

1. 在校验器中定义归档记录的最小识别和跳过路径。
2. 新增归档脚本及测试，覆盖 dry-run、截止日期和显式 apply。
3. 更新队列过滤、规则文档、脚本说明、入口和版本。
4. 运行测试、结构检查和技能镜像检查，记录结果。

## 计划审核

- 需求覆盖：完整；归档标记、脚本、队列过滤和检查豁免均有对应验收。
- 范围边界：不改 `done` 语义，不移动证据，不处理当天任务。
- 依赖与顺序：先确定归档识别，再实现脚本和调用方过滤。
- 验收与验证：以脚本测试、队列输出和全量检查为准。
- 风险与回滚：归档字段可删除恢复；脚本不覆盖非目标任务。
- 审核结论：通过。
- 审核意见来源：主 Agent 自审与用户确认的方案。

## 验证

- standards_preflight：已读取 `AGENTS.md`、`README.md`、`core/framework-maintenance.md` 和 `core/operating-model.md`；当前差异仅涉及框架脚本、任务规则、文档与测试；不适用项目业务代码规范和外部环境检查。
- 自动化测试：`npm test`
- 静态检查或构建：`npm run check`、`node scripts/check-skills.mjs`
- 页面、接口或用户验收：执行归档脚本 dry-run，核对目标数量和排除当天任务。

## 风险与交付

- 风险和环境限制：归档记录不再接受常规生命周期校验，必须依赖归档元数据和操作日志追踪。
- 集成方式：用户验收后保留、合并并创建本地框架提交，不推送。
