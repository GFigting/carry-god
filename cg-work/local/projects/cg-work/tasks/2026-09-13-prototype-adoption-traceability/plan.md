# 原型采纳可追溯变更地图

## 证据与范围

- 事实：汇率原型已被任务引用，但生产页面只部分转写，缺少“原型到实现”的交付记录，难以判断哪些交互被采纳。
- 目标：当任务声明 `prototype_reference` 时，形成同目录的 `prototype-disposition.md`，记录原型、采纳结论、实现映射、验证映射和未采纳项。
- 非目标：不要求所有任务创建原型；不扫描原型文件内容；不改变未声明 `prototype_reference` 的历史任务。

## 唯一来源与兼容性

| 规则 | 唯一来源 | 可观察实现 |
| --- | --- | --- |
| 原型为正式 Artifact、审查处置 | `core/operating-model.md` | 任务记录与处置文件 |
| 功能工作流的原型步骤 | `workflows/feature-development.md` | 功能任务计划与评审 |
| 处置文件要求与状态门禁 | `scripts/check-task.mjs` | `node scripts/check-task.mjs` |

- 兼容性：新增可选字段；仅在任务声明 `prototype_reference` 且状态为 `review` 或 `done` 时要求 `prototype_disposition_reference`。历史任务保持通过。
- 版本：兼容性新增，`2.1.0` 升级到 `2.2.0`。

## 实施顺序

1. 先增加校验器正反向测试，覆盖引用原型后缺失处置记录被拒绝、记录存在被接受、无原型任务不受影响。
2. 在校验器中实现条件门禁，并补充处置文件模板要求。
3. 将规则同步到核心模型、功能工作流、框架维护、入口与脚本说明。
4. 为本框架任务写入处置记录，运行单测、框架全量校验和任务校验。
