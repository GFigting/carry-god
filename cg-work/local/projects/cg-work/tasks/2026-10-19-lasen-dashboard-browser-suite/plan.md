# 实施计划：LASEN 海外税务看板浏览器自动化套件

## 需求与范围

用户要求新增 `overseas-tax-dashboard` 套件，并允许按前端功能模块扩展相应套件。本任务继续为海外税务前端主要顶级模块补充独立套件。

套件复用 LASEN 已登记的 `login` flow 和 `lasen-ui` / `lasen-fc` 目标，覆盖看板、注册管理、资产管理、VAT、EPR/PPWR、授权代表、基础配置和月度汇率页面。列表套件覆盖加载、重置和控制台错误；看板额外覆盖已到期指标与处置队列。套件步骤按当前动态数据设计，不把实时资产数量固定为测试常量。

## 验收标准

- `test-suites.json` 包含 8 个海外税务模块 suite，均引用 login flow 和前后端预检目标。
- 看板套件覆盖已到期卡片及处置队列；管理类套件覆盖页面加载和重置；基础配置覆盖刷新；所有套件检查控制台错误。
- 配置校验器接受该配置，prepare 能渲染对应步骤（凭据可用时），框架 `npm run check` 通过。
- browser-use 执行说明要求等待数据加载结束，并以当前页面显示的指标与队列结果核对，不写死业务数据数量。

## standards_preflight

- 复用已有 `lasen-ui`、`lasen-fc`、`login` 标识及看板路由；suite ID 使用小写 kebab-case。
- 不新增业务状态、权限、接口或自动化工具行为；断言使用当前 schema 支持的 `visible`、`text_includes`、`url_includes`、`console_errors`。
- 测试不得执行写操作或修改业务数据；检查仅在本地 LASEN 测试环境进行。

## 计划审核

- 需求覆盖：包含用户点名的套件及基于当前模块增加套件的可扩展方式，首个交付严格限定海外税务看板。
- 验收可执行性：用现有浏览器步骤动作与验证器支持的 expect key 表达；动态到期数据采用运行时对照而非硬编码数量。
- 风险：认证信息仅通过已有本地 `*.local.json` 注入并在 brief 中脱敏；无测试账号时不得伪造通过结果。

## 实施步骤

1. 在 LASEN `test-suites.json` 增加看板 suite 的页面、指标、队列和重置步骤。
2. 更新 browser-test README 的 LASEN suite 清单与看板测试说明。
3. 运行配置校验及框架结构检查；测试账号缺失时仅报告该执行环境受限。
