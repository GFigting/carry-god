# 原型实现一致性优化计划

## 目标与方案

在现有 `prototype_disposition_reference` 采纳记录之上增加 `prototype_contract_reference`。契约是原型进入实现前的可执行设计摘要，统一记录状态/场景、视觉/响应式、资源/依赖、交互/业务规则和验收映射。校验器只在任务声明原型且进入 `review` 或 `done` 时强制该引用，保持历史兼容。

## 计划审核

- 需求覆盖：覆盖原型落地偏差的主要来源，并把设计意图转成可校验记录。
- 范围：只修改框架原型技能、文档、任务校验器和回归测试，不修改业务项目。
- 依赖：沿用现有任务状态机、原型采纳模板和 Node.js 测试工具。
- 风险：新增门禁可能影响声明原型的历史任务；通过仅对新增字段和进入审查/完成的任务启用，并为框架现有相关任务补齐记录。
- 验收：缺少契约或缺少契约章节时失败；完整契约通过；无原型任务不受影响；全量校验通过。

## standards_preflight

- 需要常量化的契约章节名称集中在 `scripts/check-task.mjs` 的校验函数中。
- 允许例外：历史任务未声明 `prototype_reference` 时不要求契约；原型仍处于 `pending`/`in_progress` 时允许先创建契约引用或暂不引用。

## 实施步骤

1. 增加原型实现契约模板并同步核心模型、工作流说明。
2. 更新 prototype 技能，要求真实数据、异常状态、多视口和验收矩阵。
3. 扩展任务校验器，增加契约引用和章节门禁。
4. 增加校验器正反向回归测试。
5. 为本任务补齐审查、验证和交接记录，运行新鲜验证。
