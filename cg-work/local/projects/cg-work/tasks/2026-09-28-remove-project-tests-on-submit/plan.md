# 原项目提交测试清理规则实施计划

## 目标

明确原项目提交前删除全部测试文件的规则，同时保留 cg-work 框架自身测试。

## 变更地图

- 唯一提交规则：`core/naming-and-submission.md`。
- 直接引用：`README.md`、`core/framework-maintenance.md`、`workflows/README.md`、`workflows/feature-development.md`、`workflows/bugfix.md`。
- 回归保护：`test/submission-rules.test.mjs` 检查原项目范围、框架测试排除和验证顺序。

## 非目标与兼容性

- 不删除本仓库或任何现有项目文件。
- 不修改 Git 自动化，不自动执行删除、提交、推送或部署。
- 这是新增提交门禁，兼容现有任务状态机；版本按兼容新增能力提升次版本。

## 验收标准

- 提交规则明确原项目测试文件必须在提交前删除。
- 规则明确 `cg-work/test/` 不受影响。
- 规则要求先完成验证并记录删除清单，再创建本地提交。
- 文档引用和回归测试通过。

## standards_preflight

- 流程字面量“原项目”“cg-work 框架自身测试”“提交前验证”“删除清单”是协议术语，保留在规则文档和测试中。
- 不新增运行时代码或业务常量。

## 计划审核

- 需求覆盖：已覆盖用户澄清的原项目范围、全部测试删除和框架测试排除。
- 风险：删除行为不可逆，规则仅要求在用户明确提交原项目时执行，且必须先验证并记录清单。
- 结论：范围可独立验收，无需路线图或额外迁移。
