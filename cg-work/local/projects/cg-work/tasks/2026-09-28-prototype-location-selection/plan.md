# 原型存储位置选择实施计划

## 目标与范围

为多页面原型定义 `project` 与 `framework` 两种存储位置；单页面原型继续使用框架设计目录。兼容已有原项目仓库内原型，不执行文件迁移。

## 变更地图

| 约束 | 唯一来源 | 直接引用与验证 |
| --- | --- | --- |
| 原型位置与兼容策略 | `core/framework-maintenance.md` | README、原型技能 |
| 上下文加载与项目原型登记 | `core/context-loading.md`、`core/project-context.template.yaml` | `scripts/check-project.mjs`、项目上下文 |
| 原型制作选择方法 | `skills/prototype/SKILL.md` | 原型任务引用 |

## 实施步骤

1. 扩展项目上下文模板，增加可选的 `prototypes` 登记结构。
2. 扩展项目上下文校验器，校验原型登记的 id、location、path 和 entrypoint。
3. 同步核心维护规则、上下文加载规则、README 和原型技能，说明两种多页面位置及单页面默认位置。
4. 为项目校验器补充原型登记的通过与拒绝测试。
5. 更新当前 `cg-work` 上下文，登记已知的原项目原型目录（若目录存在）；运行任务、项目、框架全量校验和测试。

## 兼容性与风险

- 新字段全部可选，历史上下文无需迁移。
- 仅校验登记项，不扫描或移动原型文件。
- `prototype_reference` 的现有相对路径校验保持不变；原项目外部路径可使用绝对路径。

## 计划审核

- 需求覆盖：两种多页面存储位置、单页面默认位置、原项目原型登记、历史兼容和验证均有步骤覆盖。
- 范围控制：不改变任务状态机、不自动迁移原型、不改变原型采纳门禁。
- 风险检查：上下文字段采用可选结构；校验器只增加登记项的结构和路径检查。
