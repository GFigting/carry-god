# 大任务拆分与关闭变更地图

## 证据与范围

- 现状：`wayfinder` 与 `to-tickets` 已存在于 `skills/`，但没有受 `cg-work` 约束的路线图目录、父子任务编排、需求覆盖或关闭归档流程。
- 缺口：任务只能单向引用父任务，父任务无法汇总子任务、依赖、需求覆盖和关闭结论。
- 目标：让复杂需求通过决策地图进入本地路线图，再转为可验收任务，并在关闭时保留完整索引。
- 非目标：不修改原始镜像技能；不迁移历史任务；不把项目业务资料写入框架规则。

## 唯一来源与兼容性

| 约束 | 唯一来源 | 可观察实现 |
| --- | --- | --- |
| 大任务的对象与生命周期 | `core/operating-model.md` | Roadmap 规则与目录约定 |
| 上下文加载与特殊操作路由 | `core/context-loading.md`、`core/special-operations.md` | 大任务触发路径 |
| 流程阶段与技能引用 | `workflows/large-task-decomposition.md` | `framework:<skill>` 引用可解析 |
| 本地落盘规则 | `skills/large-task-decomposition/SKILL.md` | 路线图、覆盖、关闭文件约定 |
| 引用与关闭门禁 | `scripts/check-task.mjs` | 回归测试和任务校验 |

兼容性：新增的任务字段全部可选；只有任务实际声明 `roadmap_reference` 并进入 `done` 时才要求 `closure_reference`。版本从 `2.2.0` 升级到 `2.3.0`。

## 实施与验证

1. 为缺失关闭记录与自身依赖添加失败测试，先确认现有校验器未覆盖它们。
2. 实现可选路线图、父任务、依赖、覆盖、后续任务与关闭引用的校验。
3. 新增路线图模板、工作流和框架自有技能，更新所有入口和索引。
4. 运行任务单测、全量测试、结构校验、镜像校验、任务校验与差异检查；再完成审查记录。
