# 原项目提交测试门禁优化计划

## 目标

让所有原项目提交自动适用测试删除规则，并明确测试文件识别范围，同时排除 cg-work 框架自身测试。

## 变更地图

- 唯一规则来源：`core/naming-and-submission.md`。
- 直接引用：`README.md`、`core/framework-maintenance.md`、`workflows/README.md`、`workflows/feature-development.md`、`workflows/bugfix.md`。
- 回归保护：`test/submission-rules.test.mjs` 验证触发条件、范围边界和提交顺序。

## 非目标

- 不自动扫描、删除或提交任何原项目文件。
- 不删除 `cg-work/test/` 或其他框架测试。
- 不改变推送、合并、部署授权边界。

## 验收标准

- 核心规则使用“原项目提交”作为强制触发条件，不再依赖“提交全部内容”。
- 测试文件范围包含测试目录内容、`.test.`/`.spec.` 文件、夹具、快照、模拟数据和测试配置。
- 规则要求先验证、再删除、记录删除清单、复核无测试残留后提交。
- 所有入口和工作流引用一致，现有测试通过。

## standards_preflight

- “原项目提交”“测试文件”“删除清单”“无测试残留”是协议术语，保留在规则文档和测试中。
- 不新增运行时代码或业务常量。

## 计划审核

- 需求覆盖：覆盖触发条件优化、识别边界和框架排除。
- 风险：删除仍是不可逆操作，规则保留用户明确提交行为、验证前置和记录清单门禁。
- 结论：范围独立、可由文档契约测试验收。
