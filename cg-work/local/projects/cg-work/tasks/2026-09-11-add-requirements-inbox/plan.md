# 原始需求箱实施计划

## 范围与验收标准

- 每个已初始化项目在 `local/projects/<project-id>/requirements-inbox/` 中有可提交的目录说明和占位文件。
- 原始需求、附件与任务过程产物保持分离；真实内容不进入 Git。
- `project-context.yaml` 显式登记需求箱绝对路径。
- 全量框架校验拒绝缺少需求箱或需求箱说明文件的已初始化项目。
- FMS、LASEN 与 cg-work 具备空需求箱。

## 实施步骤

1. 先为缺少需求箱的项目增加失败的全量校验回归测试，并运行确认失败。
2. 增加目录说明与 Git 忽略边界，更新项目上下文模板、初始化技能和加载协议。
3. 扩展项目上下文和框架全量校验；补齐三个已初始化项目的上下文和空需求箱。
4. 运行单元测试、全量框架校验、三个项目上下文校验，并记录审查与验证证据。

## 风险与边界

- 校验只强制已存在 `project-context.yaml` 的项目，不把未初始化目录当成缺陷。
- 需求箱中的真实文件保持忽略；只有 `README.md` 和 `.gitkeep` 可提交。
