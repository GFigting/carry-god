# 命名与提交

- 目录和普通文件使用 `kebab-case`。
- 技能目录、技能 ID 和流程引用名称保持一致。
- 项目 ID 使用小写 `kebab-case`；任务 ID 使用 `<YYYY-MM-DD>-<task-slug>` 格式，例如 `2026-09-10-project-initialization`，并在对应项目目录内唯一。
- `README.md`、`AGENTS.md`、`CLAUDE.md`、`SKILL.md` 和 `VERSION` 是约定的固定名称。`CLAUDE.md` 只是 Claude 系 Agent 的路由入口，指向 `AGENTS.md`，不复制规则。
- `cg-work/` 下框架内容默认提交。
- `local/projects/` 下真实项目内容不提交。
- 不提交凭据、临时调试文件、项目业务数据或未经确认的生成产物。

## “提交全部内容”口径

当用户要求“提交全部内容”时：

- 暂存并提交当前任务范围内的全部有效代码、测试、文档和 SQL；
- 删除已确认无效、临时或重复的测试，并在任务验证记录中说明删除理由；
- 将最新 SQL 合并到正式脚本，清理同一变更的冗余脚本，保留历史任务仍引用且仍有独立价值的脚本；
- 清理与本次变更直接相关的冗余代码、字段、注释和配置，但不得借机删除无法确认归属的用户改动；
- 提交前完成新鲜验证、差异检查和任务记录校验；
- “提交”仅表示创建本地 Git commit，不自动推送、合并、部署或删除分支。
