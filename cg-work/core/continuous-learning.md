# 持续学习与经验沉淀

本文件是任务学习闭环的唯一规则来源。它将执行中的发现变成可验证、可定位的经验，避免把未经证实的猜测或一次性细节直接写成长期规则。

## 协议与兼容性

标准新任务在 `task.yaml` 中声明 `learning_protocol: v1`。`framework:bugfix` 的 `execution_profile: lightweight` 不声明该协议：这类任务的范围已限定为无可复用经验的既有行为恢复；一旦出现值得沉淀的经验，必须转为标准任务。该协议对历史任务兼容：未声明该字段的既有记录无需迁移，也不会因本规则失效。

使用 `v1` 的任务在进入 `review` 或 `done` 前必须填写 `learning_reference`，并指向任务目录内的 `learning.md`。校验器负责检查该引用和文件存在性。

## 工作循环

1. **执行中记录候选项**：只记录会改变当前方案、验证方式、风险判断或未来同类任务效率的观察；每项都注明事实证据和适用范围。
2. **先反馈当前任务**：发现影响正确性、范围或风险时，立即调整计划、实现或验证，不得等到收尾才处理。
3. **审查时判定**：对每项候选经验判断为“提升”“任务内保留”或“无可复用经验”，并写明依据；缺少新鲜证据时不得提升。
4. **收尾时交接**：`learning.md` 记录最终去向。只有稳定、跨任务可复用且已验证的经验，才可以提升到项目文档、`core/`、工作流或框架自有技能。

沉淀不是自动改写规则。提升到长期文档或框架仍须遵守相应的项目维护、审查、验证和用户确认门禁。

## `learning.md` 格式

```markdown
# 学习记录

  对当前任务的行动：

## 审查结论

- 结论：提升 / 任务内保留 / 无可复用经验
  理由：
  沉淀位置或不沉淀原因：

## 后续验证

- 下一步：
```

没有候选经验时，保留该文件并在“审查结论”中写明“无可复用经验”及判断依据。

## 边界

- 不记录密钥、个人信息、生产数据、完整日志或未确认的业务结论。
- 任务经验不替代需求、设计、审查或验证证据。
- 项目专属经验留在项目文档；只有跨项目稳定共识才提升到框架。
